## 随框架启停

编辑器（`editor/`）必须和锅巴一样是"框架的一部分"。生成器（启动脚本 / vbs / 计划任务）**已全部退役**，插件不再产出
这类产物，正式部署下只有 bot 一个进程。独立跑（`node editor/editor.mjs --port …`）只给本机调试与 `editor/test/` 用，
**不是部署形态**。"编辑器在服务而机器人没跑"、"机器人重启了、编辑器还是上一轮的旧进程"，都是要避免的状态——那正是
口令对不上与两个写者同时改一张表的来源。整套判据与理由写在 `modules/editor-host.js` 的文件头。

- **挂在 bot 自己的 HTTP server 上**：`modules/editor-host.js` 在**插件加载期**把编辑器挂到 `Bot.server`，前缀 `/queue`
  （唯一定义在 `components/constants.js` 的 `EDITOR_MOUNT`；nginx 把 `/queue` 转给 bot 端口即可，与锅巴同一形态）。
  `index.js` 的职责之一是调 `startEditorHost()`，且**失败不抛**：缺表 / 没口令 / 已有独立编辑器在跑，都只记日志
  （配置不合法是 **error**，其余半死路径是 **warn**——失败不抛就更要一眼看得见），bot 照常起服务。
- **必须在 `http.Server` 这一层接管，不能用 `Bot.express.use()`**：框架的 express 构造时就按顺序装了四个 body parser，
  **没有路径过滤**；编辑器是**自己读原始请求体**的（`req.on("data")` / `("end")`），挂在 parser 之后时流已被读完，
  监听**一个事件都收不到**——不是"读到空 body"，而是**保存 / 上传永久挂起**。做法：摘下 `server` 上原来的 `request`
  监听器，换成"是 `/queue` 本身或它下面的路径就交给编辑器、其余原样转发"；`/queueX` 这种"像但不是"的一律不吞，
  框架自己的路径（`/ping`、`/File`、`/exit` 等）行为不变。
- **挂载之后不得再直接 `server.on("request")`**（框架代码与其它插件都不行）：Node 会把同一条请求发给**所有**监听器，
  后来的那个会与编辑器**同时**处理 `/queue`——写接口双重处理、双写竞态、`ERR_HTTP_HEADERS_SENT`，而且它是在 `emit` 里
  同步抛的，能直接打死进程。分发器只做到"响应写完就不再往后转"（保证自己不做第二个写响应的人），**挡不住后来者**，
  这条只能靠纪律；要加请求级钩子就挂 express 中间件（编辑器不走 express，别把两者混在 `request` 事件上）。
- **配置只有一份来源**：状态文档固定 `<插件根>/data/queue.json`（`queue.xlsx` 是导出镜像），口令 / 签名密钥 / 管理口令
  只有 `config.editor` 那三个键，挂载前缀也是常量。宿主**先注入、再动态 `import()`**（注入缝 `editor/injected.js`，
  键名就是参数名，**空串也照样注入**，免得 bot 环境里恰好同名的环境变量被编辑器捡走）。静态 `import` 会让
  `createConfig()` 在注入之前跑掉，两边各拿各的口令——同一件事有两个来源，就是这类事故的温床。
- **在别人家里不管别人的生死**（宿主模式的两条分叉，判据是 `editor/injected.js` 的 `isHostMode()`）：① 配置不合法时
  **抛 `EditorConfigError`**（宿主接住 → 记日志 → **不挂载**，`detail` 进日志），不得 `process.exit(1)`；② **不装**任何
  进程钩子（`exit` / `SIGINT` / `SIGTERM` / `SIGHUP` / `uncaughtException` / `unhandledRejection`）、不接管 stdout——
  那些是 bot 的。编辑器请求处理里抛出的异常也不许冒到框架的 `request` 监听器上（宿主包一层，回 500 并记日志）。
- **同一张表不许两个写者**：`127.0.0.1:7788` 上已有独立编辑器在服务时**不挂载**——判据是"那儿有 HTTP 回应"
  （`200` / `403` 都算有，连不上才算没有），只记一行日志。探针**不带口令**：判活不需要它，而 7788 可能被**别的**服务
  占用，把口令发给它是没必要的暴露。判据**有意的宽**：任何在这条路径上回 200 / 403 的服务都会被当成「有编辑器在那儿」
  ——宁可少挂一次（人工看一眼日志）也不要放过一个残留写者。挂载成功后还要**低频复探**（默认 5 分钟，
  `startInterlockWatch()`）：命中只记一条 **error** 提示人工处置，**不自动卸载**——撤掉主人正在用的编辑器是人的决定。
  复探定时器必须 `unref()`，否则会吊住进程与离线套件。
- **数据落点固定**：表与它派生的一切（`.bak` / 绑定 / 白名单 / 锁 / 群名单 / 版本 / 归档）都在 `<插件根>/data` 里；
  `--file` 解析到插件外就**拒绝启动**（唯一例外是回归套件的 `ABYSS_EDITOR_TEST_PATHS=1`，生产不许设）。
- **启动补齐不负责拉起编辑器**：它只做两件事（口令与签名密钥缺失时生成 → 编辑器白名单首次写入），编辑器由机器人带着
  起来；宿主挂不上时只记日志，插件照常跑。
- **读表只有一条路**：一律走 `model/xlsx.js` 的 `openWorkbook()`——解压预算就装在那儿（整份表所有被读到的部件合计解出
  ≤ **256 MB**、条目 ≤ **2048**，**边解边数**，不信 zip 头里声明的 `uncompressedSize`，超了立刻中断而**不是**先解完再
  检查）。机器人的 `model/local.js`（每次现读同一个 `data/queue.json`，投影成 models）、xlsx 导入 / 上传 / 回退都从这儿进；
  **不要**在别处 `JSZip.loadAsync(...)` 之后直接 `async("string")` 读内容——那等于绕开唯一的闸门，而 xlsx 是能
  "1 MB 解出几十 GB"的，编辑器与机器人**同进程**，撑爆一次就是全群掉线。
- **独立入口只留给调试与套件**：`editor/editor.mjs` 仍可直接 `node` 跑（本机调试、`editor/test/` 那一批套件，套件清单
  见 [`../test/README.md`](../test/README.md)），为此它导出 `handler` / `startEditor` / `cfg`，并在文件末尾用
  `import.meta.url` 比对 `process.argv[1]` 判断"是不是自己在跑"（win32 下按小写比较）。**只有**独立跑时才谈得上
  `--port` / `--bind` / `--allow-no-token` 这类部署参数。

## 安全（汇总，细则见 [`编辑器-写入与安全.md`](编辑器-写入与安全.md)）

- **每个响应都带三个安全头 + 一份 CSP**：`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、
  `X-Content-Type-Options: nosniff`——由 `handler` 开头统一设（`editor/http/respond.js` 的 `applySecurityHeaders`），
  所以 301 / 403 / 410 / 500 这些提前返回的路径也带；接口响应（`json()`）另外统一 `cache-control: no-store`。
  **CSP 分两份**：首页那份**只认每次响应现生成的 nonce**（`cspForPage(nonce)`，模板里两段内联 `<script>` 写着
  `nonce="__NONCE__"`、由首页路由替换），其余页面给 `CSP_PLAIN`（`default-src 'none'`）。推论两条硬口径：
  ① **页面里不许出现内联 `on*=` 属性**（CSP 会挡掉；现有代码全部用 JS 赋处理器）；② 新增内联脚本必须带
  `nonce="__NONCE__"`（`editor/test/editor.test.mjs` 有源码断言盯着）。`style-src` 保留 `'unsafe-inline'`。
- **新增"口令校验之前就能到达"的路由时，必须一并想清楚这几个头与 CSP**。现在有三条：尾斜杠 301、favicon、
  头像代理 `GET /api/avatar?qq=`（它只会被 `<img src>` 请求、带不了 `x-abyss-*` 请求头，只能放在口令校验之前；
  QQ 号只认 5~12 位数字，上游地址按主机白名单 `q.qlogo.cn` / `p.qlogo.cn` / `api.dicebear.com` 固定拼，不接任意 URL）。
- **凭证走请求头、不进 URL**：页面自己发的 `/api/*` 用 `x-abyss-token` / `x-abyss-identity` / `x-abyss-sign` /
  `x-abyss-admin` 带头，服务端取法是 `paramOf`：**请求头优先、query 兜底**（`x-abyss-window` 同理），于是老地址、
  老页面照旧能用。只有**导航类**（首页那一跳、`font/cn.woff`、下载链接）还带 query 凭证——它们改不了头；要彻底干净
  得在 nginx 那层脱敏 `/queue/` 的 query（部署方的事）。
- **凭证一律恒时比较**：访问口令（`?k=`）与管理口令（`?a=`）的判定收在 `editor/http/auth.js`，比较走 `sameSecret()`
  ——先比长度，等长再 `timingSafeEqual`。签名身份那边（`model/identity.js`）本来就是恒时比较，同一个口径。
  例外：`editor/config.js` 里"两个密钥是否相同"的**配置自检**是本地两个值比对，用 `===` 即可。
- **用户可控文本进 `innerHTML` 之前一律 `esc()`**（连单引号一起转）、**页脚自由 HTML 先过 `sanitizeFooter()`**、
  **进日志前先 `oneLine()` 压成一行**——三条都有套件盯着，实现位置与理由见 [`编辑器-写入与安全.md`](编辑器-写入与安全.md)。
- **写操作必须留痕**：所有非 GET 请求在响应结束时记一行审计（`editor/audit.js`：`qq` / `action` / `status` + 路由用
  `auditLog.note()` 补的 `sheet` / `rows` / `version` 等细节）。出口**由宿主注入**（宿主模式 = 框架 logger；独立模式 =
  `console` → `data/editor.log`）；**只写显式字段、绝不带 `?k=`**，失败（403 / 400）也记。新增写接口要一并补
  `auditLog.note()`。
- **`/queue` 不经过框架的 `server.auth`**：它不走 express，框架那层 header / query 鉴权对它无效，也不该指望。编辑器的门是
  自己的口令（`?k=`）与发送者身份签名；"外网只有该看到的人能访问"由 nginx 与 `editor.token` 负责。挂载**不碰**
  `Bot.express` 的 `quiet` / `skip_auth`（那是给走 express 中间件的插件用的）。

## 与插件的关系

- **链接鉴权：身份只来自链接，权限只问群名单**——权威版是 [`编辑器-链接与认领.md`](编辑器-链接与认领.md)。一句话：
  `u/s` 签名（QQ + 群昵称 + 签发时刻，30 天）+ `w/ws` 5 分钟窗口（管理员另有一枚 24 小时 `abyss_admin_ok`），
  权限只问 `editor/roster.js` 的 `isMember(qq)` 三档；**没有设备认领**这一层（2026-11-25 整段删除）。
- **插件不再给编辑器发 HTTP 请求**：写操作全部走 `editor/service.js` 的进程内注册表（`registerEditorService` /
  `getEditorService` / `resetEditorService`），名单同步 / 每日整理 / 插队都是同进程直调，**没有代签、没有时间窗、
  也没有出站链接**。编辑器没挂载时 `getEditorService()` 返回 `null`，调用方直接报错，**不兜底、不回退 HTTP**
  （否则又会出现第二条写路径）。出站只剩**给群友的填报链接**（`components/fill-entry.js` 的 `windowedEditorUrl`，
  内部用 `model/identity.js` 的 `editorUrl` + `signWindow` 拼 `k=&u=&s=&w=&ws=`），那是给人点的，不是机器人请求。
- **主播区（表头之上）与排队区（表头之下）是同一张表里的两个区，但共用一根行号轴**：任何"在主播区插 / 删行"的动作
  必须同时下移 / 上移表头与整个排队区，并同步搬走绑定与完成情况锁里的行号（`insertRowsAndShift` + `shiftRowsOf`）；
  两个区的**序号各自独立**（排队区序号插行后仍是 1..N，主播区编号也从 1 起），不得互相串号。否则会出现"版本戳对得上、
  人却被认到别人的行上"。插入点必须严格落在表头**上方**（`insertedAt < headerRow`）：算不出来就明确拒绝（表 / 绑定 /
  锁 / 版本一个字都不动），绝不让新主播行落进排队区。

## 回归

- `test/editor-host.test.mjs`（15 项）钉住"挂载与前缀、带 body 的请求不挂死、口令只有一份来源、框架路径不被吞、重复调用
  不重复挂载、互锁探针语义（不带口令 / 200 与 403 都算有）、半死路径记 warn、宿主路径也带三个安全头、运行期互锁记一次
  error、**响应写完就不再往后转发**"——它只发**注定失败的**请求（409 版本冲突 / 400 不是 xlsx），收尾核对表文件哈希未变。
