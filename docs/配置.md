# 配置

> 三层结构、锅巴读写链路的八条硬约束、热重载。目录与模块职责见 [`开发说明.md`](开发说明.md)；
> 凭证怎么进编辑器见 [`编辑器.md`](编辑器.md)。

## 三层结构

```
Plugin/
├── defSet/config.yaml          ← 模板：完整注释 + ${变量} 占位符（锅巴保存时用）
├── config/config.yaml.example  ← 参考默认值（入 git，可手动编辑）
└── config/config.yaml          ← 运行时（不纳入 git）
```

- 用**模板变量替换法**写配置，禁止 `YAML.stringify` 整写（会抹掉注释）。
- 锅巴 field 用点分隔路径（`section.key`），模板变量用下划线（`section_key`）。
- `getPluginConfig` 兜底：`config.yaml` 不存在时从 `.example` 复制；**禁止**解析 `defSet/config.yaml` 过滤 `${变量}` 当兜底
  ——替换成空会生成非法 YAML。
- 每个 `${变量}` 必须在锅巴 `defaultValues` 里能找到对应项；锅巴 schema 每个大 label 一个文件，`guoba/index.js` 只做拼装。
- 配置写入必须保留注释（按模板渲染后写回，或走锅巴同一路径）。

## 八条硬约束（改配置键 / 锅巴面板前逐条对）

前三条是**结构不变量**、其余是**读写链路不变量**。违反任一条的后果都是"面板显示与真实配置不一致"或"配置被写坏"，
而且**往往不报错**——所以必须由 `test/guoba.test.mjs`（锅巴那条读写路）与 `test/bootstrap.test.mjs`（启动补齐那条写入路）
钉住，不接受"看起来没问题"。

1. **三份文件同构，且是同一份模板的产物**：`defSet/config.yaml`（值写成 `${变量}`）、`config/config.yaml.example`、
   `config/config.yaml` **行数与"注释 + 键"骨架逐行相同**。参考文件不是手抄的：它是「模板 + `DEFAULT_CONFIG` 走一遍
   `renderDefSet()`」的输出，所以模板里每个占位符都必须有默认值来源（含跨层键 `footer.html`，其默认值与
   `editor/config.js` 的 `DEFAULTS.footerHtml` 逐字相同）；改配置键必须**同一轮改模板**并重新生成参考文件。
   行内注释的对齐空格、示例值带不带引号不算差异（骨架闸只看注释与键）。
2. **占位符与字段双向一一对应**：模板里每个 `${变量}` ↔ `CONFIG_FIELDS` 每项；变量名一律由 `fieldToVar()` 从配置路径
   推导，**禁止手写映射表**（必然漂移）。面板专用名（如别名子表 `anchor_aliases_list`）必须在 `guoba/index.js` 登记，
   且**不得与真实配置路径撞名**。值的写法统一走 `yamlValue()`：字符串 `JSON.stringify`，数组与对象写成**单行 YAML**
   （`{名: ["别名"]}`）——多行块写法会被锅巴保存归一成一行，三份的行数与骨架就对不上了。
3. **一个键只有一个来源**：默认值在 `DEFAULT_CONFIG`（每个 `CONFIG_FIELDS` 键都要有）；可配的键必须有 schema 字段、
   有 `PANEL_FIELDS` 条目、有模板占位符。**禁止假配置**：能填的值只有一个、或填了不生效的键，一律删掉而不是留着。
   **凭证类的"生成"来源也只有一个**：`editor.token` / `editor.sign_key` 由启动补齐（`index.js` →
   `components/bootstrap.js`）在**首次缺失时**生成，`editor.admin_token` 由主人按需手填（留空 = 不开管理口令入口）；
   锅巴面板只显示与手改，**不许替主人生成**——面板不知道编辑器正拿着哪个口令，换一个就把编辑器踢出局。这些键的
   **唯一来源就是这份 `config.yaml`**：宿主（`modules/editor-host.js`）读它、注入给编辑器。
4. **锅巴的"读"必须读文件，不许读内存快照**：`getConfigData()` 与 `renderDefSet()` 的兜底值走 `readCurrentConfig()`。
   模块加载时求值一次的 `config` 看不到别人后来写进文件的东西（启动补齐写密钥、手工编辑、面板上一次保存）——读它会
   **把"看不见的空值"在下次保存时写回文件**。
5. **读写必须同源**：面板读与写都走 `resolveConfigPath()`。一处硬编码 `configPath`、另一处做解析，就会出现"面板把值
   写进仓库配置、插件从临时配置读"这种静默错位。
6. **写完必须同步内存，并说清生效时机**：`setConfigData()` 落盘后调 `reloadConfig()`（`config` 是各模块共用的同一个
   对象，就地改写即全局生效）；插件侧由 `index.js` 启动的 `watchConfig()` 负责外部改动热重载。**运行期改不了的键一律
   登记在 `RESTART_ONLY_FIELDS`**，保存回执、热重载日志、配置注释三处口径必须一致，且提醒**只提这次真的改了的键**
   （面板提交的是整张表单，按"在不在表单里"判会变成每次保存都喊重启）：`notify.cron`（它决定唯一那条定时任务的周期，
   由插件实例化时交给框架），以及 `editor.token` / `editor.sign_key` / `editor.admin_token` / `footer.html`——**编辑器在
   插件加载时把它们取走**，插件侧热重载了、编辑器侧没有，不重启就是"插件用新口令、编辑器还认旧口令"。
7. **读不出来不许静默，写下去必须先验**：`readCurrentConfigWithStatus()` 的 `error` 非空 = 那份 `config.yaml` 读不出来
   （语法坏掉 / 读不动）。四条都要做到：
   - `getConfigData()` **不许抛错**：抛错会让锅巴前端只剩一个"确认"弹窗、**面板彻底打不开**——而面板正是主人唯一能把
     坏配置改回来的地方。正确做法是照常返回值（参考文件 + 默认值），并额外给一个 `_panel_warning` 告警横幅，写明
     "读不了哪份文件、现在显示的是参考默认值、不是你原来的配置"。这个横幅受两条锅巴约束（都由 `test/guoba.test.mjs`
     钉住）：`component` 只能是锅巴**注册过**的名字（现在是只读的 `InputTextArea`，写错会静默渲染成"未知的组件"）；
     且这一项**必须排在某个 `SOFT_GROUP_BEGIN` 之后**，否则锅巴会为它单独多开一个"默认"页签。**"未配置"（`editor` 段
     三个凭证键都是空串）不算异常**：那是全新安装的正常样子——面板照常打开、照常保存，只有"解析不了 / 读不动"才挂横幅。
   - **错误文案里不许出现配置文件的内容**：`yaml` 库会把出错那行的原文塞进异常消息，而那行常常就是 `token:` /
     `sign_key:`——原文进了日志或面板弹窗，等于**把口令打出来**。`explainParseError()` 只留"哪份文件 + 解析器给的原因
     （到第一个换行为止）"。
   - `setConfigData()` **写盘前必须验证**：渲染出的文本先 `YAML.parse` 一遍，再逐个比对"提交的值"与"解析回来的值"；
     解析不了、或对不上，就返回 `Result.error`，**一个字节都不写**。
   - **每一个写入者都要过同一道闸**：`config.yaml` 有**两个**写入者——锅巴（按模板渲染整份写回）与启动补齐（只在缺失时
     改 `editor.token` / `editor.sign_key` 两行，`components/bootstrap.js`）。后者同样要：**读不出来就停下**（不在坏文件上
     做行级改写）、**值一律走 YAML 解析器取**（手写正则剥不掉行尾注释，会把「值 + 注释」整段当成口令）、写已有行**只替换
     那个标量占的字符区间**（缩进、行尾注释、行尾符与其余字节原样留下）、**落盘前把结果解析回来并核对读到的就是准备写的
     值**。**只堵一个写入者等于没堵**。
   **为什么**：`renderDefSet()` 对"表单没提交的键"是按文件当前值兜底的，文件读不出来时那份兜底就是"全默认"——照写等于
   拿一份全空的模板把主人的配置**整份覆盖掉**（事故现场：44 字节的坏配置被写成 5 KB 的全空配置，面板还报"保存成功"）；
   而少了写前验证，一个坏值就能把文件写成**下次读不出来的样子**（事故现场：`token: """`）。**读不出来的文件仍然允许被
   保存覆盖**——面板是主人唯一能救回它的路，但要按参考默认值重写其余键，所以**回执里必须点明"其余键已按参考默认值重写"**。
   `ensureConfig()` 同理：只在"文件根本不存在"时复制参考文件，**不拿参考文件盖掉空白 / 坏掉的 `config.yaml`**。
8. **热重载不许用 OS watcher**：`watchConfig()` 用 `fs.watchFile` 轮询（`persistent: false` + 关闭时 `unwatchFile`），
   **不是** chokidar / `fs.watch`。这台机器上两条 OS-watcher 的路都会崩在原生层（接不住）：`chokidar.watch(文件)` 在文件
   被删时由底层 `FSWatcher` 发 `error`，chokidar 5 不把它转成自己的事件 → 未捕获异常；`chokidar.watch(目录)` 退出时
   libuv 断言 `!_wcsnicmp(filename, dir, dirlen)` 直接 abort。轮询最多晚一个间隔生效（配置不是热路径），换来"文件被删 /
   被原子替换 / 被外部覆盖都不崩、也不吊住离线套件"。
