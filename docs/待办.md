## 已知问题（待另一位开发者处理）

> 这一节是**交接清单**，不是规范。条目在解决后从本节删除，并把结论记进 `docs/历史沿革.md`。

- **身份认领复查 ①：已有会话时，群内短码不兑换**。已经进过编辑器（带访问口令或管理员 24 小时
  cookie）的浏览器点群里的 `#code=123456` 短链，会直接按上一次身份进主页面，不处理本次短码。
  入口页只在未授权时给（`editor/editor.mjs:3709` 起），而 `#code` 只存在于 hash，服务端看不到，
  主页面脚本也不处理。方案：主页面 boot 先兑换 `#code` 再展示；旧代码同样如此，不是重写引入。

- **身份认领复查 ② 的剩余（身份已按标签页存，这一半已修）**：`editor/editor.html` 现在把
  `u/s/a/v` 放 sessionStorage、口令与设备令牌留 localStorage（`BOX`），多标签页不再互相顶掉；
  但没有带 `u/s` 的请求仍会按设备认领（`editor.mjs` 的 `claims.holderOf` / `claims.resolve`）
  认回上一次身份——共用浏览器里不带链接直接打开 `/queue`，仍可能是上一个人的视角。要不要收紧
  （例如无身份时一律先给入口页）另议。

- **身份认领复查 ④：入口页内联 `onsubmit` 被 CSP 拦，手输口令点「进入」没反应**。
  `editor/http/pages.js` 的 `denialPage`（`onsubmit="go(event)"`，:53）与 `entryPage`
  （`onsubmit="goCode(event)"` :92、`onsubmit="goToken(event)"` :95）都用了内联事件，而 CSP 只有
  `script-src 'self' 'nonce-…'`（`editor/http/respond.js` 的 `cspForPage`），Chromium 实测提交请求为 0；
  随短链自动兑换不受影响。旧代码同样如此。方案：改成 `addEventListener('submit', …)`，保留 CSP。

- **手机端细节（P4 剩余）**：手机表格 textarea 14.5px、抽屉 input 15px（iOS 聚焦会放大页面）；
  「编辑」按钮 44×23（高 23px）；页脚对比度 2.21:1。导航下拉、默认落填写页、隐藏「当前选中」已做。

  编辑器已是五档（夯 / 顶级 / 人上人 / NPC / 拉完了）。
