# 编辑器 · 页面与版式

> 填写页的结构、缩放、表格、已完成栏、主播区、页脚，以及窄屏口径。
> 2026-11 从 `editor/README.md` 按主题拆出，正文逐字未改；入口与部署见 [`../editor/README.md`](../editor/README.md)。

## 页面结构（填写页的版式口径）

页面是**单文件**（`editor.html`，无构建、无外部 CSS），骨架从上到下：

```
顶栏（排队表 · 填写 / 上次保存 / 口令状态）
榜名大标题（当前榜，.sheet-h）
页签（四个榜，带人数）
只读提示条（无身份时）｜ 主人/管理员的操作条
主播列表（只读卡片 .acards）
主区两栏 .wrap：排队中（表格 #grid）｜ 已完成（#doneCol）
页脚（版权 / 备案，来自配置 footer.html）
```

### 缩放：只有一个单位 `--u`

所有尺寸都从同一个变量派生，**没有按分辨率写的字号断点**（只有 `max-width: 900px` 一条结构性断点，用来把两栏收成单栏）：

```css
:root { --u: clamp(0.78px, 0.05208vw, 2.2px) }   /* 0.05208vw = 1px @1920 */
```

| 视口宽 | `--u` | 相对 1920 |
|---|---|---|
| 1366 | 0.78px | 0.78× |
| 1920 | 1px | 1×（基准） |
| 2560 | 1.33px | 1.33× |
| 3840 | 2px | 2× |

字阶只有 6 级，全部在 `editor.html` 末尾的「字号与自适应的唯一出口」段里定义（用 `calc(N * var(--u))`）：

| token | 1920 下 | 用在哪 |
|---|---|---|
| `--fs-p3` | 52px | 榜名大标题 |
| `--fs-p2` | 20px | 「排队中 · N 人」标题、已完成面板标题、主播区标题 |
| `--fs-p1` | 17px | **表格正文全部列**（含序号）、表头、胶囊、已完成昵称 |
| `--fs-0` | 15px | 已完成条目的目标、主播卡正文 |
| `--fs-1` | 13px | 页头元信息、页签、按钮、完成人胶囊、主播卡元信息 |
| `--fs-2` | 12px | 预留（目前只有测试钉死的公共队列胶囊用字面量 12px） |

改字号**只改这一处**：历史上有同一个选择器被写 3~4 次 `font-size` 的叠加（改一处不生效），已清掉。

### 表格（排队中）

- `table-layout: fixed`，列宽由表头 `th` 决定：序号 58px、群昵称 21%、原神游戏名 14%、选择主播 12%、难度及目标 19%、备注 15%、操作 116px（像素部分同样 `calc(N * var(--u))`）。
- **列不裁、内容也不裁**：只读态把昵称 / 游戏名 / 备注渲染成**纯文本**（`input` 只能被裁剪、永远显示不全），单元格允许换行；每格另带 `title` 存全文（序号列除外——它的 `title` 是「表格第 N 行」，测试按它找行）。
- 只读访客的操作列**不渲染删除按钮**，只显示 `—`；有权限时才出现删除。
- 表顶标题是表格前的 `div.panel-h`，**不是** `<caption>`：caption 的内容区受固定布局与 sticky 首列影响，用 padding 推不到序号列（实测 padding 4→20 只移动 8px）。

### 已完成栏（右栏）

- 与主表同一份数据；主表里那些行仍然在（`display:none`），按行号找行的断言不受影响。
- 条目一行式：`✓ 昵称 目标 完成人胶囊`；昵称过长截断（`text-overflow: ellipsis`），胶囊 `flex: none` 不换行。
- 胶囊三档色：本人完成 `.dc-by-self`（绿）、主播代打 `.dc-by-anchor`（暗红）、其他 `.dc-by-plain`（灰）。
- 面板高度由 `fitDoneCol()` 按 `window.innerHeight - 面板顶部 - 24` 写入，内部 `overflow-y: auto`；窗口 resize 时重算（只绑一次）。

### 主播列表

只读态是卡片（`.acards`，`minmax(calc(252 * var(--u)), 1fr)` 自适应列数），**整体左对齐**、与主表共用左边距；推荐度用星级（`强烈推荐 ★★★★★` / `推荐 ★★★★` / `可选 ★★★`），说明小字随 `--u` 缩放。可编辑态仍是表格（`#anchorGrid`），它的列宽也是 `calc(N * var(--u))`。

## 页脚（版权 / 备案）

页脚内容**不写死在页面里**，由插件配置 `config/config.yaml` 的 `footer.html` 提供。
前端从 `GET /api/meta` 取它（**与其它请求共用同一个 `withToken()`**：主脚本开局就把 `?k=` 收进
localStorage 并把地址栏清干净了，再自己读 `location.search` 会拿到空口令 → 403 → 页脚静默消失）。
模板（`config.yaml.example`）里**已经写好署名首行**，备案号自己往后接：

```yaml
footer:
  # 首行署名（`&` 用实体 `&amp;` 更稳；要改署名直接编辑这一行）
  html: |
    <div>© 2026 <a href="https://github.com/Hyposelenia-Moon">缄月</a> &amp; <a href="https://github.com/AxiuCN">阿修Axiu</a> · 由 <a href="https://github.com/Hyposelenia-Moon/abyss-queue">abyss-queue</a> 提供</div>
    <div><a href="https://beian.miit.gov.cn/" target="_blank" rel="noreferrer">京ICP备2026xxxxxx号-1</a></div>
```

- **规范署名行由编辑器追加**：这份自由 HTML 之后，编辑器会**自动追加**一行
  `Created By {框架名} {yunzaiVersion} & {PluginName} {pluginVersion}`（口径见 [`协作.md`](协作.md) 的「日志、版本号与注释」）。
  框架名按宿主 `package.json` 的 `name` 判：含 `trss` 就是 `TRSS-Yunzai`，其余是 `Yunzai-Bot`（与 `components/pluginVersion.js` 同一条判据）。
  所以维护者改署名时**不用管版本号**，也别把版本号抄进 `footer.html`——
  版本取编辑器自己定位到的插件根下的 `package.json`，插件名取插件 `components/constants.js` 的
  `PLUGIN_NAME`（与回复页脚 `versionFooter` 同源）；两者都推导不到时显示「未知」，不会因此起不来。
  编辑器是第二个入口（可能按并排布局部署），这一路上**没有静态 import 插件的 `components/`**。
- **署名口径**：首行是两位维护者并列（缄月 / 阿修Axiu），与仓库 `AGENTS.md` 的权属一致。
  `&` 建议写成 `&amp;`（HTML 实体）——裸 `&` 浏览器一般也容错，但严格校验器会报错，显示效果一样。
- **备案号留给你**：不预填，避免把示例号当成真号带上线（备案号必须与本站实际备案一致）。

- **自由 HTML，不拆字段、不校验**：版权几行、备案号放哪、要不要公安备案（`https://beian.mps.gov.cn/#/query/webSearch?code=<号>`）、
  甚至放图片，都由维护者自己排。编辑器只负责"有就画、没有就不画"（空串 = 整块不渲染）。
- **覆盖四处**：填写界面 + 三个提示页（需要口令 / 仅主人可用 / 链接已失效）。提示页在鉴权之前就返回，
  所以它们由服务端直接拼进 HTML；填写界面走 `GET /api/meta` 下发、前端用 `innerHTML` 插入。
- **只由维护者维护**：它被当作可信内容原样插入页面，**不要**把群友可控的字符串接到这里（那等于给公网页面留 XSS）。
- 改完要**重启机器人**才生效（配置只在插件加载时读一次：凭证由宿主注入、页脚与开关进 `cfg`）；
  编辑器跑在机器人进程里，所以没有"单独重启编辑器"这回事。两种跑法见上面「怎么起」。

### 手机端（窄屏 ≤ 820px）的显示口径

窄屏下表格变成"一行一张卡片"（`thead` 隐藏、每个 `td` 前面用 `data-k` 当代字段名），并且**只留三列**：

- **别人的行**：序号 / 群昵称 / 帮帮完成情况（其余字段折起来，手机上一屏能多看几个人）；
- **自己那一行整行展开**（`tr.own`）：`perm.roam === false`（名单不可信 / 链接里没有群名片）时服务端**只发自己那几行**
  ⇒ 发来的都算自己的；本群成员（`roam`）拿到整张表 ⇒ 按**群昵称**认自己那一行（打开页面时服务端已按 QQ
  把这一行同步成群名片，所以对得上）；
- **主人与管理员整表展开**（`body.see-all`）：他们要看全所有人的信息。这两个视图是**分开的**：
  `own` 是**逐行**打的（`renderGrid`），`see-all` 是**整表**的（`renderPerm`）——从前 `own` 也是 body 级，
  结果普通人一进页面**所有行**都展开，"只看自己那一行"这条等于没有。
- **「序号」那一格**在窄屏必须 `padding: 0`：PC 那条 `td.rowno { padding: 0 8px }` 不覆盖的话，
  这一格的字段名会被顶进 8px，与其它行的字段名对不齐（维护者报的"序号行错位"）。
- **锁定格的完成情况一颗值一颗胶囊**（与可编辑的多选格同一套拆分 `/[,，]/` 与同一套底色口径）：
  整串塞进一颗时 `pillColor` 认不出"阿修Axiu,听雨"是哪一类，会画成一颗黄底大胶囊。
  这个只读分支**只有非 admin 走得到**（服务端 `statusLocked = caller.role !== "admin" && …`），
  所以表现是"手机上普通人看到的完成情况和主人/管理员不一样"。

回归见 `editor/test/client-state.test.mjs` 的「手机端①/①续/②/③」四条。

### 手机端（≤1100px）的页面切换与「当前选中」（2026-11-24）

- **页面切换**：侧栏 `.side` 在 ≤1100px 收起，`#mobPage` 复用 `show(id)`——选项由
  `renderMobNav()` 按权限生成（排队表打头，其余取 `#nav .ni` 里当前可见的页面，顺序与 `TITLES`
  一致），切换时同步 `#crumb`、`.ni.on` 与地址栏 hash。`#mobPage` 在更宽的视口不显示（`.mobpage{display:none}`）。
  2026-11-25 起它从左下角浮动胶囊改成**通栏贴底**的胶囊条（`position:fixed;left:0;right:0;bottom:0`，
  `body` 底部留 76px 内边距）——原来那颗固定在下左，正好压住排队表第 3、4 行的群昵称。
- **两种身份两套页面**（2026-11-26）：主人 / 管理员只有管理那七页，**没有填写页**，报名走排队表
  底部那一行「＋ 新增一行」；普通成员（`perm.role === 'self'`）与只读访客（`guest`）**只有「排队表 · 填写」**
  这一页，PC 侧栏与手机下拉都只出它，进来直接落这页（`load()` 里 `show('fill')`）。填写页底部同样有
  「＋ 新增一行」（只读时置灰），没报名的人点主按钮「我要报名」就**就地建一行**，不用回排队表。
  依据：用户口径「普通成员的 PC 端和手机端只有填写页，没有别的页；管理的手机端不设填写页」。
  三类按钮的显隐都在 `applyPerm()`（`fillOnly` 变量）与 `renderMobNav()` 里，回归见
  `editor/test/client-state.test.mjs` 的「成员只有填写页，管理员没有填写页」。
- **「管理台 /」前缀**：`.adminonly` 只给 `owner / admin / manage` 身份，其他身份在手机与桌面都不显示。
- **「当前选中」卡**：管理页 `#selBody` 与填写页 `#fillSelBody` 同为 `.card.selcard`，在 ≤1100px 隐藏；
  桌面保留（高度由内容决定，实测约 150px）。「已完成」列表不隐藏。
- **「我的报名」**：以服务端下发的 `mineRows`（按 QQ 绑定 / 唯一同名认出来的行号，每榜最多一行）为准，
  页面不再自己按昵称 `find`；服务端也认不出、表里又有多个同名行时写「待核对」、主按钮写「我的报名待核对」
  并提示联系管理员核对归属，不猜也不建行。回归 `editor/test/client-state.test.mjs` 的「成员只有填写页，
  管理员没有填写页」「成员在填写页点「＋ 新增一行」就能就地报名」「只读访客在填写页点「我要报名」不建行」
  与「同名多行且服务端认不出」。服务端的 `mineRows` 断言在 `editor/test/member-row-area.test.mjs` 的
  「本人（self）的合法追加仍然可用」里。

### 手机端排队区（≤1100px，2026-11-25）

- **一行读完**：每行是 `grid-template-areas:"seq nick stat call"` 的四区网格——序号在左、群昵称居中偏左、
  完成情况胶囊靠右、呼叫在最右；「编辑」是昵称右端的 34×34 方形小键（`[data-medit]` 保留，点它开抽屉）。
- **攻炼榜另排**：它的完成情况是多段复合值（`7.2排队中 7.3等待开启`），硬塞进四区会把昵称压成竖排，
  所以 `body.attack-sheet .tr` 改成「序号 / 昵称 / 呼叫」一行、状态落到第二行右侧。
- **输入框 16px**：手机档 `.cellinput` 与抽屉 `.msrow input` 都是 16px，低于这个字号 iOS 会在聚焦时
  放大整个页面。
- **页脚与副标题对比度**：`.site-footer` / `.fillfoot` / `.anchors-head .sub` 统一到 `#5f6b7d`
  （浅玻璃底上约 5:1）；填写页里 `.fillfoot` 与 `#siteFooter` 同时出现会重复署名，所以
  `body.fillmode #siteFooter{display:none}`。
- **填写页页头竖排**（2026-11-26）：`.fillhead` 在窄屏改成 `flex-direction:column`，标题字号 34px → 26px、
  `#fillSaved` 左对齐。原因是并排时右侧那串「上次保存 2026/11/26 01:57:02」要占 ~150px，390px 宽的屏上
  34px × 6 字的「幻想真境剧诗」只剩不到 200px，会断成「幻想真境剧 / 诗」两行。桌面档仍是并排原样。
- 回归：`test/layout.test.mjs` 钉着「手机端紧凑列表必须有 `.medit{` 规则与 `data-medit=`」这条源码契约，
  另有「手机档填写页头竖排（榜名不被「上次保存」挤断）」一条；
  `editor/test/client-state.test.mjs` 的「手机抽屉」「手机端页面切换」两段覆盖抽屉与切页。
  390×844 实测整页 1722→1368px（7 行排队的人一屏能看完更多）。

### 呼叫按钮的点击回执（2026-11-25）

- **按下**：`.callbtn`（表格行）/ `.acall`（主播卡）都带 `transition:transform .12s ease,box-shadow .12s ease,background .16s ease,color .16s ease`，
  `:active` 时 `transform:translateY(1px) scale(.96)`——按下去能看到陷下去，松开弹回来。
- **发出之后**：`callMember()` / `callAnchor()` 成功后给按钮加 `.called`（蓝底白字，`900ms` 后由 `flashCalled()` 自己摘掉）。
  失败**不加**这个类——别把失败的呼叫画成成功的样子。
- 回归：`editor/test/anchor-add.test.mjs` 两条（成功后短暂带 `called`、失败不留 `called`）+ `test/layout.test.mjs`
  的一条源码契约（`:active` 位移、`transition`、`.called` 样式、页面里真的 `classList.add('called')`）。

### 群昵称候选浮层（2026-11-26）

- **点开才出、空输入摆前 8**：排队表的群昵称格与填写页的昵称输入框聚焦即弹 `#nickpick`
  （独立的一个 `.pk.nickpick`，**不复用** `#picker`——两个浮层各管各的生命周期，弹一个不会把另一个顶掉）；
  输入为空时列名单前 `NICK_BROWSE_LIMIT = 8` 个名片，标题「群成员名单 · 点一下填入」；
  有字就实时筛（`nickSuggest()`：前缀 0 分、包含 1 分、不小于两字且最长公共片段 ≥2 且编辑距离 ≤2
  给 `2 + 距离` 分，排序 `分数 → 公共片段 → 长度 → zh-CN`；一字不差的不提示），标题换成
  「相近的群昵称 · 点一下填入」，没有命中就给一行灰字「没有相近的群昵称」。
- **怎么填**：点候选直接写回输入框并触发 `oninput`（进草稿、1.2 秒防抖后自动保存）；
  `↑`/`↓` 移高亮（`.kbd` 蓝框），`Enter` 填入并收起，`Esc` 收起；输入清空立即收起，
  点页面别处也收起（走 `bindClose` 那套「点别处才收」）。只读身份不弹（`showNickPicker()` 先看 `st.readonly`）。
- **样式**：玻璃卡片、`min-width:220px`、`max-width:min(340px, calc(100vw - 24px))`，
  候选是胶囊 `.opt`，底部一行「共 N 人」；`z-index:95`，比手机抽屉（85）高。
- **数据来源**：`/api/data` 的 `roster.candidates`（机器人推来的群名单去重按 `zh-CN` 排序）。
  只给**本群的人**：名单判定为「不在本群」（`member === false`，拿着别群链接进来）时下发空数组；
  只凭口令进来、没有链接身份的只读访客照旧能拿（他们本来就看得到整张表的名片）。
- 回归：`editor/test/client-state.test.mjs` 的 ⑤b 段 4 条（聚焦摆名单 + 打字实时筛 + 点一下填入、
  `↑↓`/`Enter`/`Esc` 与清空自动收、只读身份不弹、纯符号名片被跳过）；
  `editor/test/link-identity.test.mjs` 的「本群成员拿得到整群名片」与「不在本群名单里的人拿不到」。

### 左下角成员头像（2026-11-26）

- **从协议端取**：`model/roster.js` 的 `collectMembers()` 取成员时顺带取头像——
  `getAvatarUrl()` 拿得到就用它（onebotv11 的成员对象带这个方法），拿不到按 QQ 拼
  `https://q.qlogo.cn/g?b=qq&s=100&nk=<qq>`；头像要**在 `{ ...v }` 归一之前**取，
  因为真机给的是带方法的实例、展开之后方法就没了。`editor/roster.js` 的 `saveRoster()`
  把 `avatar` 一起存进 `data/abyss-editor-roster.json`（空值不写这个键）。
- **页面走同源代理**：CSP 是 `img-src 'self' data:`，外链头像进不来，所以新增公开路由
  `GET /api/avatar?qq=`——只认 5~12 位数字 QQ，先看名单里那份头像、没有就按 QQ 拼，
  上游只允许 `q.qlogo.cn` / `p.qlogo.cn` / `api.dicebear.com`（主机白名单，不接任意 URL），
  成功后内存缓存 30 分钟（最多 400 条）并回 `cache-control: private, max-age=3600`；
  取不到就是 404，页面回落成原来的金色圆章 + 昵称首字。
- **页面**：`perm.avatar` 有值就往 `#meAv` 里塞一个 `<img>`（`object-fit:cover` 的圆图），
  `onerror` 自己摘掉退回首字——头像挂了不影响名字与权限。
- 回归：`editor/test/client-state.test.mjs` 的「有 `perm.avatar` 就渲染同源代理图，取不到退回昵称首字」；
  `editor/test/link-identity.test.mjs` 三条（代理公开可达 / 非数字或过短的 QQ 直接 400 /
  `perm.avatar` 是 `api/avatar?qq=<自己>`）；`test/roster.test.mjs` 两条（适配器直链优先、名单落盘带头像）。
