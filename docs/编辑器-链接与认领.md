# 编辑器 · 链接与身份

> 身份只来自链接、权限只问群名单、5 分钟时间窗、退群检测与整理。
> 2026-11 从 `editor/README.md` 按主题拆出；2026-11-25 按「身份认领重写」整节改写。入口与部署见 [`../editor/README.md`](../editor/README.md)。

## 身份：只有链接这一个来源

编辑器**不认设备、不认浏览器**，只认链接里那份签名身份（`?u=&s=`，`model/identity.js` 的 `signIdentity` / `verifyIdentity`）：

- 谁点进来就是谁——页面打开链接时把 `k/u/s/a` 收进存储、把地址栏清干净（`editor/editor.html` 的 `incoming`），
  之后每次 `/api/*` 用请求头带上（`x-abyss-token` / `x-abyss-identity` / `x-abyss-sign` / `x-abyss-admin`）。
- 身份签名 30 天有效，签的是 **QQ + 群昵称 + 签发时刻**；改一个字就验不过。
- **没有设备认领这一层**：不种 `abyss_editor_device`、不存 `abyss-editor-claims.json`、页面里也没有
  `x-abyss-device` 头与 `abyss.d:*` 键。同一台电脑的两个标签页各带各的身份（身份存 `sessionStorage`）。

## 权限：只问「这个 QQ 在不在群成员名单里」

服务端拿链接里的 QQ 去问 `editor/roster.js` 的 `isMember(qq)`，结果三档（`editor/editor.mjs` 的 `memberStateOf`）：

| `isMember(qq)` | 能做什么 |
|---|---|
| `true`（在名单里，名单可信） | 整行排队区可写；自己的行不限，别人的行一次 ≤3 位、10 分钟 ≤10 位，且不碰两条红线（见 [`编辑器-权限与归属.md`](编辑器-权限与归属.md)） |
| `false`（名单可信、但没有他） | **只读**（`perm.outOfGroup`，转发到群外 / 退群了）。页面说明「这个链接的身份不在本群成员名单里」 |
| `null`（名单不可信：没推过 / 超 48 小时） | 老口径：只拿得到自己那一行，改别人的行一律拒绝 |

- 群昵称：身份里的 `n` 是**发链接那一刻**的群名片；编辑器**群名单优先、链接里那份兜底**（`nickOf`）。
  名单里没有这个人、链接里也没带昵称时 `perm.nick` 为空，页面会分两句话说清楚（本人点「＋ 新增一行」报名 / 不是本人则回群里重新取链接）。
- 只读的**唯一三种来源**：没有身份（`guest`）、不在本群（`member === false`）、名单不可信且改别人的行。
  **没有"链接被取代"这一档**——`staleLink` / `linkStateOf` 已随认领层一起删除。

## 链接的时间窗（5 分钟）

管理员 / 主人的链接**只在本人发 `#排队` 时私聊给一次**，带的是**那一刻的当期窗口**（`?w=&ws=`，`model/identity.js` 的 `signWindow` / `verifyWindow`）：

- 编辑器只认**当前窗口与上一窗口**（`WINDOW_MS` = 5 分钟，`windows = 2`），更旧的 `w/ws` 一律 410 + 链接失效提示页。
- 过期就再发一次 `#排队`（机器人 tick **不主动重发**）。
- **没带 `w/ws` 的身份链接照样放行**：群友的 `#code=` 短码兑换出来的就是这一档（身份签名自己管 30 天）；
  能写多少不在这里判，由上面那份群名单决定。
- **管理员只能从"窗口刚验过的那一刻"进门**（2026-10-18 审核 P1）：那一刻给这台设备种一枚 24 小时的
  `abyss_admin_ok`（`HttpOnly` + `SameSite=Lax`，https 才带 `Secure`；令牌是 HMAC 绑 **QQ + 过期时刻**）。
  之后**不带 `w/ws` 的管理员请求必须带着它**，否则按过期链接处理（410 + 提示页）——不然"把 `w/ws` 删掉"
  就能让一条老管理链接靠 30 天的身份签名一直当管理员。**只有管理员走这条**，群友一律只认链接。
  管理口令 `?a=` 不受影响（独立静态凭证，由页面存起来按请求头带）。
- **独立跑的本机编辑器 → `--cloud` 指向的另一份部署推表也带窗口**：`POST /api/push-cloud` 转发调用者身份时会连当期 `w/ws` 一起签
  （对端同样只认带窗口的身份链接）。
- 回归：`editor/test/link-identity.test.mjs`（时间窗段：当期与上一期 200、两窗之前 410、被改签名 410、
  别人的签名 410、未来窗口 410）。

## 群内的短码：`#code=123456`

普通成员在群里发 `#排队`，机器人发的是**固定入口页 + 6 位数字填表口令**，不是完整长链接：

1. `apps/queue.js` 的 `prepareEntry` 用 `issueLink(qq)` 生成口令（`model/editor-links.js`），
   记进登记簿 `<插件根>/data/abyss-editor-links.json`（`{ QQ: { v, at, code, link } }`，**机器人写、编辑器只读**），
   再把群消息里的链接换成 `<public_url>/#code=123456`；
2. 点开链接后，页面（`shortCodeOf()` / `redeemShortCode()`）或入口页拿口令去 `GET /api/link-code?code=…`
   反查回**完整签名链接**（`readLinkTarget`），然后 `location.replace` 整页跳过去；
3. 口令 **5 分钟作废**（`LINK_CODE_TTL_MS`），一次一换；重发一次 `#排队` 就换一个。

- **`#code` 在主页面也兑换**：`#code` 只在 hash 里、服务端看不见，而入口页那条路只在未授权时才给。
  所以主页面 boot 先读 `#code` / `#c`（六位数字）去兑换，兑换有结果之前不渲染、不读表；失败只提示
  「口令不对或已过期」并给回入口页的链接。
- **同一个标签页里点短链也兑换**：已经停在 `/queue/#queue` 的页面里点 `#code=123456`，浏览器只改 hash、
  不重载脚本，所以 `hashchange` 也要处理——`bootGate` 与 `hashchange` 共用上面那两个函数，
  hash 是六位短码就先兑换、**不当页名切换**；不是短码才按页名走。
- 回归：`editor/test/link-code.test.mjs`（登记簿口令兑换、5 分钟作废、入口页与主页面两条兑换路）、
  `editor/test/client-state.test.mjs` 第 ⑩⑪ 段。

## 私聊的长链接：管理员 / 主人专用

主人与白名单管理员（以及框架 master）发 `#排队` 时**群里一条都不发**，只走私聊（`apps/queue.js` 的 `dmTarget`）：

- 是带 `k/u/s/w/ws` 的完整长链接（`components/fill-entry.js` 的 `windowedEditorUrl`），
  **与普通人那一份走同一个函数**——口令（`#code=`）只在群消息那一档用；
- 身份是发起人、窗口是当期，过期或换窗口就重发 `#排队`；
- 管理员这份不受"本群守卫"约束（`role === "admin"` 走整表权限），也不进群内撤回那一套。

## 退群检测与整理

- **有绑定的退群**：`POST /api/roster` 的名单对账（`reconcileRoster`）按 **QQ** 判断——名单里没有这个 QQ
  ⇒ 删掉他那一行并压紧（删前自动存历史版本，并写一条 `kind: "remove"` 的改动记录）。触发时机：机器人
  启动后 20 秒、每天 `roster.at`、以及 `#排队` 前发现"名单里没有发送者"时补推（见 `apps/queue.js`）。
  **一趟推送里的"删行"与"改名"分两趟写**（先是删行压紧、再在搬完之后的表上改名）：压紧会把留下的每一行
  内容整体重写一遍（拿的是本临界区开头那一版表的值），同趟写改名会被同一格上的旧值盖掉，
  而表写前的自检发现"这一格期望新名、实际旧名"会**放弃整趟写入**——那样机器人推名单整个失败、
  当天名单同步上不去（编辑器退回老口径）。回归见 `editor/test/roster.test.mjs` 的
  「同一趟里改名 + 退群」那一组。
- **没绑定的孤儿行**：从没点过链接、没建过绑定的人退群时，那一行**不会**被自动删（对账只看绑定）。
  这类行由「归属状态」面板里的**退群候选行**列出来：**表里有这一行、但既没有有效绑定、群名单里也找不到
  这个人**（`GET /api/ownership` 的 `missing`）。**只列候选、绝不自动删**——群名单里的昵称与表里那一格
  是两份人工维护的文本（改名 / 带后缀 / 手填都会对不上），自动按昵称删会误删活人。
  主人按着名单点一下「删除这 N 行」才会删：`POST /api/ownership { action: "prune-missing", rows }`
  ——**只删他点名的那几行**（服务端不重新算一遍，免得删掉他没看见的东西），删行 / 绑定与锁迁移 /
  压紧走与退群对账同一份实现（`dropRowsAndMigrate`），删前存历史版本、删了什么进改动记录（`via: "主人确认"`）。
  名单不可信（没推过 / 超 48 小时）时**不列候选**，只回一句"先发一次 `#排队同步名单`"。
- **改了完成情况时的立刻检测**（`afterSaveFollowUp` → `nicknameCheckNow`，见 [`编辑器-页面.md`](编辑器-页面.md) 的「立刻生效」）：
  与每天那一趟**同一套判据、同一份实现**（`reconcileRoster(members, { drop: false, sheet })`），
  只有一处不同——**不删行**：改名照样按名单同步这一行（含完成情况里的旧名），名单里找不到人的
  两类（有绑定但那 QQ 不在了 / 没绑定且按昵称也对不上）只**提醒主人**（`alertOwner`，kind `missing`，
  同一份候选集合不重复打扰），删行仍旧只由"每天那一趟"或主人手动确认来做。
