# 编辑器 · 链接与认领

> 个人链接「最新一条有效」、认领记录、5 分钟时间窗、退群检测与整理。
> 2026-11 从 `editor/README.md` 按主题拆出，正文逐字未改；入口与部署见 [`../editor/README.md`](../editor/README.md)。

## 链接：**最新一条有效**（个人链接的作废机制）

机器人签的长链接里已经带 30 天身份与 5 分钟窗口；为了让"重发一次 `#排队`"能作废旧转发，每发一次再额外生成一个随机标记（`#v=`，8 个 base64url 字符），并把它记进登记簿
`<插件根>/data/abyss-editor-links.json`（`{ QQ: { v, at } }`，**机器人写、编辑器只读**，见 `model/editor-links.js`）。

编辑器拿它判"手里这条是不是该 QQ 最新那一条"（`editor.mjs` 的 `linkStateOf`）：

| 手里这条 | 结果 |
|---|---|
| **最新**那一条（`x-abyss-link` 与登记簿一致） | 可写（照旧受本群守卫、额度与红线约束） |
| **被新的取代了** | **只读浏览** + 页面说明"回群里重发一次 `#排队` 取最新链接" |
| **老链接**（没有 `v`） | 同上只读（它分不出新旧，等于没编号的钥匙） |
| 登记簿里**没有这个 QQ**（机器人还没更新 / 那一次没记上） | **不据此拒人**（宁放松一次，不能把人锁死） |
| 管理员 / 机器人身份 | **不受这条约束**（判据是白名单身份 + 5 分钟窗口） |

- 于是**本人重发一次 `#排队` 就等于把转发出去的那条作废**（旧链从"可写"变成"只读"），
  他自己则拿到新的那条、可写。**"认领"那一套已经不参与这件事**（见上一节）。
- 页面从地址里把 `v` 收进 sessionStorage（`abyss.v`），之后每次 `/api/*` 用 **`x-abyss-link`** 头带上——
  与时间窗同理：**走头才不进 nginx 日志**（`editor/http/respond.js` 的 `HEADER_OF` 有它）。
- 只读时页面上那句话是「**这条链接已经被更新的那条取代了**」，与"口令失效""不在本群""链接被转发"四者分开说，
  免得用户一直重发 `#排队` 试。
- **管理员那一份私聊长地址不带 `v`**：它的判据是白名单身份 + 5 分钟窗口，与"链接新旧"无关。

回归：`editor/test/link-latest.test.mjs`（共 24 项：模块层与真编辑器两段）。

## 链接认领**记录**（不再决定能不能写）

> **2026-10 口径反转**：认领**不再是权限判据**。维护者原话："**取消链接认领，通用链接就应该可以点进
> 别人的链接里面修改内容**"。从前"一条链接归第一台打开它的设备，别人只读"，现在**谁拿到链接都能用
> 链接自己的身份**——能改多少由「权限」那一节的三层（本群守卫 / 额度与红线 / 留痕）决定。

认领记录（`<插件根>/data/abyss-editor-claims.json`）现在只做两件事：

1. **记录**"这条链接**最早**被哪台设备、什么时候打开"（诊断 / 审计用，`editor/claims.js`）；
2. **设备回来时认出身份**：页面打开链接后把地址栏清干净（`editor.html` 的 `withToken()`），之后靠
   **设备 cookie（`abyss_editor_device`）或页面注入的令牌（请求头 `x-abyss-device`）**回到同一个身份；
   cookie 被内置浏览器挡掉时，那份令牌是唯一凭据。角色**每次都按白名单现算**，记录里不存角色。

因此：

- **别人 / 另一台设备点同一条链接** ⇒ 照旧是链接身份本人（不再降级成访客、不再 410）；
- **没有人"被顶掉"**：几台设备同时开着同一条链接都能用，写冲突交给行级冲突那一套（见「实时刷新与行级冲突」）；
- **认领记录不改指向**（永远是最早那台），`perm.forwarded` 这个字段与页面那句「此为其他人唤起的链接」
  一并删掉了；
- **老链（没带 `w/ws`）也照旧放行**：从前它只放行"认领过的那台设备"，现在放行——只是普通人这类链
  没有 `v` 标记 ⇒ **只读**（见「链接：最新一条有效」）。

## 链接的时间窗（5 分钟）


群里的链接一次只该由一个人用。编辑器侧在这一层上有几道判定（`editor/claims.js` +
`model/identity.js` 的 `w/ws`），**口令与身份签名照旧**：

| 层 | 管什么 | 存哪 |
|---|---|---|
| 访问口令 `?k=` | 能不能用这个服务 | 配置（`editor.token`） |
| 身份签名 `?u=&s=` | 这个链接是谁的（30 天有效） | 无状态（HMAC） |
| **时间窗 `?w=&ws=`** | 这条链接是哪 5 分钟签的（只认当期与上一期） | 无状态（HMAC） |
| **链接登记簿 `#v=`** | 这条链接是不是该 QQ **最新**那一条（决定能不能写） | `<插件根>/data/abyss-editor-links.json` |
| 认领记录（设备 cookie） | **只记**"最早是哪台设备打开的"+ 设备回来时认出身份 | `<插件根>/data/abyss-editor-claims.json` |
| **改动记录** | 谁改了哪一行的哪个字段（**只记事实，不参与鉴权**） | `<插件根>/data/abyss-editor-changes.json` |
| **越界额度窗口** | 群友改"别人的行"的 10 分钟累计（见「权限」） | `<插件根>/data/abyss-editor-quota.json` |

- **认领记录**：链接首次打开时写下那台设备，响应里种 `abyss_editor_device` cookie
  （随机 16 字节 + 签名，`HttpOnly` + `SameSite=Lax`；**请求是 https 才带 `Secure`**，
  判据是 `req.socket.encrypted` 与反代的 `x-forwarded-proto`，代码里不写死）。
  cookie 里**没有身份**——身份由服务器按设备号从记录里查；签名把"哪条链接"绑进去，
  所以拿别人的 cookie 配自己的链接验不过。
- **设备回来时认出身份**：认领的那台设备再来（页面把地址栏清干净、请求里没有 `u/s`）
  照样认出他是谁——**管理员及以上 24 小时内不必再带链接**（cookie `Max-Age=86400`，每次回来续期），
  **普通群友只种会话 cookie**（浏览器关掉就没了；群友的长期身份仍然是"群里重新取链接"）。
- **认领不再决定能不能写**（见上一节）：别人打开同一条链接照旧是链接身份本人，写权限由
  「权限」那一节的三层决定；几台设备同时开着同一条链接都行，写冲突交给行级冲突那一套。
- **5 分钟作废**：机器人发给主人 / 白名单管理员的那条私聊链接**只在本人发 `#排队` 时给一次**，
  带的是**那一刻的当期窗口**；过期就再发一次 `#排队`（机器人不主动重发）。编辑器只认**当前窗口与上一窗口**，
  更旧的 `w/ws` 一律 410 + 链接失效提示页。群友拿到的长链接同样带当期窗口，也适用这条规则。
- **管理员只能从"窗口刚验过的那一刻"进门**（2026-10-18 审核 P1）：那一刻给这台设备种一枚 24 小时的
  `abyss_admin_ok`（`HttpOnly` + `SameSite=Lax`，https 才带 `Secure`；令牌是 HMAC 绑 **QQ + 过期时刻**）。
  之后**不带 `w/ws` 的管理员请求必须带着它**，否则按过期链接处理（410 + 提示页）——不然"把 `w/ws` 删掉"
  就能让一条老管理链接靠 30 天的身份签名一直当管理员。普通群友不看这枚 cookie（凭据是长链接的 `v` 标记）；
  管理口令 `?a=` 也不受影响（独立静态凭证，由页面存起来按请求头带）。
- **链接里没带上群昵称**（`perm.nick` 为空）：页面**分不清**"我就是链接主人、只是认不出名字"与
  "这是别人转发、我恰好第一个点开"，所以两句话都说——「这个链接里没有你的群昵称：如果你不是这条链接的主人
  （这是别人转发、你点开了），请在群内发送 `#排队` 取你自己的个人专属链接填写」+「如果你是本人
  （表里还没有你的行）：点「＋ 新增一行」即可报名」，并**不再自动替他开一行**（否则会出现"没有人填的幻影行"，
  看着像表被清空）。**注意不再写"此为其他人唤起的链接"**：那个口径连同 `perm.forwarded` 一起删了
  （认领不再是判据，见上一节）——现在只读只有三种来源：没有身份、不在本群（`perm.outOfGroup`）、
  手里这条不是最新的（`perm.staleLink`）。
  **正常情况走不到这一支**：机器人发长链接时会把**发送者当时的群昵称**写进身份（`u` 里的 `n`），
  编辑器按 QQ 从群名单里取不到名字时才用它兜底（见下面「链接里的群昵称」）。
- **链接里的群昵称**（身份 `u` 里的 `n`）：群名片一向由编辑器按 QQ 从**每天推一次**的群名单里补
  （`roster.js` 的 `nickOf`）——名单里没有这个人（没配群号、那一天没推成功、刚进群）时，身份里的 `n`
  就是空串，页面认不出"自己那一行"。所以机器人**发链接那一刻**把发送者的群名片一起写进身份
  （`components/fill-entry.js`），编辑器**群名单优先、链接里那份兜底**（名单是"现在的名字"，
  链接里那份是"发链接那一刻的名字"）。改身份里的 `n` 就验不过 `s` ⇒ 整条链接作废。
  **代价**：链接里从此也看得出"这是谁的链接"（与个人长链接里的身份同一件事，本来就是发给本人的链接），而且链接会随群昵称长短变化。
- **链接里的链接标记 `#v=`**（`model/editor-links.js`，见「链接：最新一条有效」）：
  编辑器据此只认该 QQ **最新**那一条可写，其余只读——**本人重发一次 `#排队` 就等于把转发出去的那条作废**。
- **没带 `w/ws` 的身份链接（老链）照旧放行**：2026-10 起不再"只放行认领过的设备"（那条闸随认领一起取消）。
  普通人这类链没有 `v` 标记 ⇒ **只读**；要写就回群里重发一次 `#排队`。机器人身份（`ROSTER_QQ` = `"0"`）
  在 **HTTP 路由**上照旧通行：名单同步 / 每日整理 / 插队现在由插件**进程内直调**
  （`editor/service.js`），不再代签请求、也不带时间窗；这些路由还留给编辑器页面与独立调试。
  跨层对账见 `test/outbound-window.test.mjs`（假 service 记调用 + 填报链接验窗口），编辑器这一侧见
  `editor/test/roster.test.mjs`（它的 HTTP 请求构造器**默认不带窗口**，覆盖的正是机器人身份那条豁免）。
  **别人点开某条链接**（转发、或另一个人的设备）：照旧是链接身份本人、照旧能写——能改多少由
  「权限」那一节的三层决定；页面不会再说什么"这是别人的链接"。
- **"这台设备"的证明有两条路，页面优先用第二条**（现场：手机 / QQ 内置浏览器点主人链接，页面能打开、
  数据全读不到，报 `Unexpected token '<'`——那些内置浏览器常把 cookie 当第三方挡掉、或无痕不落盘）：
  ① **设备 cookie**（`abyss_editor_device`，`HttpOnly` + `SameSite=Lax`，https 才带 `Secure`）；
  ② **设备令牌 + 请求头 `x-abyss-device`**：认领那条 HTML 响应会把令牌（与 cookie 同构的
  `<设备号>.<HMAC>`，签名绑"哪条链接 + 哪个身份"）**注进页面**（模板里的 `__DEVICE__`），
  页面存进 localStorage、之后每次请求带上；任何响应回的新令牌也会被页面收下（续期 / 换设备跟得上）。
  服务端**优先读请求头、没有再读 cookie**。
  令牌在浏览器里**按 QQ 归属**地存（键 `abyss-editor-device:<这条链接的 QQ>`，QQ 由服务端注入页面，
  模板里的 `__WHO__`）：只存一条的话，"先开过 A 的链接、再开 B 的链接"就会把 A 的令牌发给 B。
  **令牌验不过的后果**（2026-10 起）：只是"不认这台设备"，身份照旧来自请求里那份签名——
  从前那种"验不过就 410 失效页"随认领一起取消了。
  请求的组合**按顺序各试一次**：有令牌 → ①带令牌 ②不带令牌、带窗口；没令牌 → ①带窗口 ②都不带
  （服务端 410 的语义就是"这个组合它不认"）。所以"浏览器里存着别的链接的令牌"不会把页面卡死，
  顶多是只读访客；两发都 410 才报错（那才是链接真的过期了）。
  令牌只证明"这台设备认领过这条链接"，不含身份；换个身份 / 换条链接都验不过（签名里绑着）。
- **独立跑的本机编辑器 → `--cloud` 指向的另一份部署推表也带窗口**：`POST /api/push-cloud` 转发调用者身份时会连当期 `w/ws` 一起签
  （对端同样只认带窗口的身份链接）。
- **认领记录坏掉 / 条目过期 ⇒ 当未认领**：不崩、也不因此放开写权限；认领记录 24 小时过期。
  键是「身份 + 用途（admin / member）+ 30 天签发窗口」，认领记录里**不存角色也不存昵称**
  （白名单与群名片随时能改，每次现算 / 现取）。
- **认领记录的性能口径**（2026-10-08 复审 §2-#3，当时实测 2000 条 ≈ **12 ms/请求**）：
  ① **读盘按文件的 `mtime:size` 认版本**：文件没变就用内存里那份解析结果（`statSync` 微秒级，
  `readJson` 2000 条 ≈0.76 ms）；**外部改了这个文件，指纹一定变 ⇒ 下一个请求立刻按新内容判**，
  可见性与"每次都读盘"一字不差（`editor/test/link-claim.test.mjs` 有一条直接改文件再发请求的断言）；
  ② **反查走"设备号 → 认领键"的索引**：令牌里的设备号必须与记录里的设备号一字不差才可能验过，
  所以从"扫全表逐条验签"缩到"只看同设备号的那几条"；
  ③ **续期有粒度**（`RENEW_GRANULARITY_MS` = 1 分钟）：同一个设备再回来时记录还够新就**不重写文件**
  （24 小时的窗口晚续一分钟没有实际差别，而每个请求一次同步写盘是实打实的开销）。
  修完实测：2000 条 + 匹配不上的 cookie 从 12.25 ms/请求降到 **0.42 ms**（= 无 cookie 的基线）。
- 回归见 `editor/test/link-claim.test.mjs`：认领后角色正确 / 别人只读（写接口 403）、
  **更新且够新的链接接管认领（先点者被顶成只读）、更新但超出 10 分钟宽限不接管**、
  管理员 `Max-Age=86400` 与群友会话 cookie、当前与上一窗口可用而旧窗 410、
  没带 `w/ws` 的老链换设备 410（认领过它的设备不带窗口照旧放行）、认领文件损坏与条目过期按未认领、
  **无 cookie 的设备靠页面里那份设备令牌（请求头）照样是链接主人**（且别的链接的令牌 / 改过签名的令牌一律 410）、
  首页注入的 `__WHO__`（页面据此把令牌按人存）、降级访客那份两个注入位都是空串；
  页面侧的"令牌按 QQ 存、没有令牌时带窗口、410 换一种组合重试"在 `editor/test/client-state.test.mjs`。

### 退群检测与整理

- **有绑定的退群**：`POST /api/roster` 的名单对账（`reconcileRoster`）按 **QQ** 判断——名单里没有这个 QQ
  ⇒ 删掉他那一行并压紧（删前自动存历史版本，并写一条 `kind: "remove"` 的改动记录）。触发时机：机器人
  启动后 20 秒、每天 `roster.at`、以及 `#排队` 前发现"名单里没有发送者"时补推（见 `apps/queue.js`）。
  **一趟推送里的"删行"与"改名"分两趟写**（先是删行压紧、再在搬完之后的表上改名）：压紧会把留下的每一行
  内容整体重写一遍（拿的是本临界区开头那一版表的值），同趟写改名会被同一格上的旧值盖掉，
  而表写前的自检发现"这一格期望新名、实际旧名"会**放弃整趟写入**——那样机器人推名单整个失败、
  当天名单同步上不去（编辑器退回老口径）。回归见 `editor/test/roster.test.mjs` 的
  「同一趟里改名 + 退群」那一组。
- **没绑定的孤儿行**：从没点过链接、没建过绑定的人退群时，那一行**不会**被自动删（对账只看绑定）。
  这类行由「归属状态」面板里的**退群候选行**列出来：**表里有这一行、但既没有有效绑定、群名单里也找不到
  这个人**（`GET /api/ownership` 的 `missing`）。**只列候选、绝不自动删**——群名单里的昵称与表里那一格
  是两份人工维护的文本（改名 / 带后缀 / 手填都会对不上），自动按昵称删会误删活人。
  主人按着名单点一下「删除这 N 行」才会删：`POST /api/ownership { action: "prune-missing", rows }`
  ——**只删他点名的那几行**（服务端不重新算一遍，免得删掉他没看见的东西），删行 / 绑定与锁迁移 /
  压紧走与退群对账同一份实现（`dropRowsAndMigrate`），删前存历史版本、删了什么进改动记录（`via: "主人确认"`）。
  名单不可信（没推过 / 超 48 小时）时**不列候选**，只回一句"先发一次 `#排队同步名单`"。
- **改了完成情况时的立刻检测**（`afterSaveFollowUp` → `nicknameCheckNow`，见下一节的「立刻生效」）：
