## 完成情况与锁定

**「帮帮完成情况」这一列存的是人**（主播名 / 「本人已完成」落成的该行群昵称，逗号分隔多值）：
任何改名（本人保存、管理员改行、群名单同步）都必须过 `editor/editor.mjs` 的 `statusRenamePlan`，
把**整段等于旧昵称**的 token 换成新昵称；逐段精确比对，不碰主播名与 `等待开启` / `排队中` / `本人已完成`；
榜里两行同名、或这一行查不到可依据的 QQ 绑定时**宁可不动**，并在回执 / 日志里说明。
群消息 @ 人时，QQ 先按这一行的绑定反查、其次按群名单昵称查，都拿不到就只发名字、不发 @。

**主播锁只在"写成某位完成人"时才建**（2026-10-14 维护者口径）：主播把这一格改成主播名（或落成群昵称的
「本人已完成」）⇒ 建锁、本人那一格只读；改成 `排队中` / `等待开启` / 清空 ⇒ **删掉旧锁**，本人可以继续改
（"改回排队中"本来就该还给本人填）。**普通人能填的只有两档**：自己那一行只能写成 `排队中` 或 `本人已完成`，
其余值（主播名 / 等待开启 / 任意文本）**只忽略该格并回报**（不整单拒，同一发的其它字段照写）；
本群成员改**别人的行**仍按旧口径（受额度与主播锁约束，那是"帮别人打勾"）。
**锁只在"这一格当前确实记着某位完成人、且不是本人自有标记"时才生效**（`lockIsLive` + `lockWorthy`）：
值已经是 `排队中` / `等待开启` / 空 ⇒ 那把锁算**过期**；值是**字面「本人已完成」或本行自己的群昵称** ⇒ 那是
**本人的自有标记**，也算不算（主播代点过一次「本人已完成」也允许本人自己撤回）。
两种都下发 `statusLocked=false`、保存时也不忽略那一格。这条兜的是：① 绕过 `/api/save` 的改表（手工改表 /
第三方工具）留下的陈旧锁——开榜自动翻（`catchUpOpenStatus`）只改状态、不碰锁，会把它原样留着（翻完也顺手删）；
② 2026-10-17 录屏里那个"主播代点过「本人已完成」⇒ 本人那一格没有 ×/＋、改不回「排队中」"。
回归：`editor/test/editor.test.mjs` 的完成情况那组（含"过期锁不再拦人""锁 + 值＝本人群昵称不算锁"）、
`editor/test/quota-guard.test.mjs` 的锁段。

## 页面交互：自动保存、候选与移动端

**编辑器页面上没有「保存」按钮**（维护者报告 #6）：改动写在草稿里，停手 **1.2 秒**后自动写表
（防抖合并连续改动；同一时刻只飞一个请求，飞的过程中又改了等它回来补一轮补发）；**必填四项**
（群昵称 / 原神游戏名 / 选择主播 / 难度及目标）没齐时**一个请求都不发**；状态文字四档：
`已保存` / `未保存（有改动）` / `保存中…` / `保存失败，点这里重试`（最后一档可点，点了立刻重发）；
写失败**不自动重试**；版本冲突（409）时草稿一字不动、**自动保存暂停**（再敲键也不自动发）、也不自动重读。
服务端只改了一处：**自动保存那条路的存底有 5 分钟节流**（`editor/versions.js` 的 `AUTOSAVE_SNAPSHOT_MS`；
不加的话一次编辑会话连存 20 次就把 `versionsKeep` 个版本位全吃光，见 §十 末尾那条注解）。
**主播列表那颗「保存主播列表」保持手动**——它是结构性写表
（在主播区插一行、下面的行整体下移），不跟着敲键触发。回归 `editor/test/autosave.test.mjs`、
`editor/test/versions.test.mjs`（含节流那一条）。

**改主播名要先改别名表**（2026-11-24）：`config.anchor_aliases` 的**键是正名**，别名都挂在它下面。
`applyAnchors` 在写表前逐行断言：旧名落在键上而又要改名时**直接拒绝**（400，
提示「先把这个键改成新名」）——编辑器**不替人改 YAML**（手写配置，改了会被覆盖）。
取键走 `aliasCanonicalNames()`（去空白，口径与 `compileAliases()` 一致；空别名的键也算）。
回归 `editor/test/editor.test.mjs` 的「改名撞上别名表的正名会被拒，别名表外的名字照常能改」。

**保存成功之后的清草稿口径**（2026-10-10 审核 B-02/B-07）：提交前快照**这一发的键与值**，
重读时 `keepDrafts = true`（一个草稿都不动），回来只清"**这一格现在的有效值仍等于提交值**"的键；
这期间的新编辑留作草稿、新增行转成"那一行的草稿"。`/api/save` 的回执带**写完之后那一版的 `version`**，
页面立刻记下 —— 于是"保存成功但重读失败"不会把用户引向一场假 409。
另外三条一起做掉：**请求 15 秒超时**（`AbortController`，半开连接不会让"保存中…"卡死）、
**连败 3 次后退避**（自动发送也停，只留手动重试）、**`beforeunload` 离页守卫 + 提示里报别的榜的草稿数**。
回归 `editor/test/client-state.test.mjs`。

**「帮帮完成情况」的下拉候选只有三种来源**：状态词（`等待开启` / `排队中` / `本人已完成`）、主播区、
手动「＋ 收录新名字」——**表里在用的名字不再当候选**（点「本人已完成」落进这一列的是群昵称，端出来
等于每个点过完成的人都变成全体候选；改名 / 退群 / 广告名片留下的名字还会永远残留在下拉里）。
当前值由页面并进候选（所以点得到、取消得掉），服务端放行"这一格里本来就有的值"（老数据照旧能改能存）。
回归 `editor/test/editor.test.mjs` 与 `editor/test/client-state.test.mjs`。

**完成情况菜单只点人、点完就收**（2026-11-24）：候选里不再出现「排队中 / 等待开启」——它们是机器算出来的
状态词（新行默认值、攻炼按版本开放、清榜自动翻），人手点只会和自动逻辑打架。对还在排队的行点一位主播，
页面把状态词**替换**成这位主播，而不是拼成 `排队中,主播名`（服务端以两者互斥拒收）；选一位就收起浮层，
要再加一位完成人再点开同一格。回归 `editor/test/client-state.test.mjs` 的
「排队中的行点完成人：把「排队中」换掉」与「多选的选择器（完成情况）」。

**群昵称候选是一条「下拉浮层」**（2026-10-18 维护者要求，替代原来铺在单元格下面的胶囊条）：点进来 /
打字时在格子下方浮一层（`.picker`，摆位与其他几格共用 `placePickerAt`），空着给名单最前
`NICK_BROWSE_LIMIT = 8` 个（「群成员名单（点一下填入，共 N 人）」），打了字给前缀 → 含这段 → 编辑距离 ≤ 2、
按"越紧越短"取前 6，点一下填入并自动收起（走与手改**同一条路**：写草稿 + 刷计数 + 排自动保存）。
原生 `<datalist>` 仍然不挂——它只在聚焦时自己弹一层，会和这层**同时出现两处**，又不能按"差一两个字"匹配。

**候选名单必须先清理再摆**（"候选过多、有无关占位符"）：名单是按 QQ 扫来的群名片，原样摆会有
**空名**（没设名片又取不到昵称的人 ⇒ 一整行空白按钮）、**重名**（两个 QQ 用同一个名片 ⇒ 同一名字连出好几行）、
以及**纯符号 / 纯 emoji 的名片**（`.` `。` `🔼` ⇒ 看着就是无关占位符）。`cellInput` 里先 `trim`、
丢掉"一个字母/数字/汉字都没有"的名字、再按 `pillNorm` 去重得到 `nickList`，然后才喂给 `nickSuggest`；
名单全是垃圾时整条候选不建。
另外 `nickSuggest` **只按"文字相近"判，不按字数**（2026-10-18 维护者："搜索候选是与输入文字相近的
群昵称，而不是群昵称字数"）：编辑距离只说明"差几个字"——「随伦」与「听雨」字数相同、距离 2，却一个字都不
重叠。所以模糊那一档先要**连续 2 个字以上的公共片段**（`commonRun`），再谈距离 ≤ 2；
排序也是"越紧在前、同档里公共片段越长越前"，不是"名字越短越前"。
**单字查询不比编辑距离**：一个字与任意一个字的距离都是 ≤1（「随」会把 `.` / `。` / `🔼` / 另一个单字
全当"相近"），所以查询只有 1 个字符时只认前缀 / 包含。
回归 `editor/test/client-state.test.mjs` 的「空名与重名先清掉」「单字查询…」「模糊匹配按文字相近挑」三条。

**浮层"只开不切换"，且输入框必须带 `.nickpick`**（两条都是"弹出来闪一下就消失"的坑）：
① 手机上一次点按会先 `focus` 再 `click`，两个处理器都写成开关切换时，focus 先开、click 判成"已经开着"又关；
`showNickPicker()` 只负责开（已开就什么都不做），收起只留给"点别处 / Esc / 选完"。
② `document` 上那层"点别处就收起"按类名放行：`.picker`（浮层自己）、`.chips`（胶囊那格）、
**`.nickpick`（群昵称输入框）**——**输入框必须真的带这个类**，否则点输入框这一下 `click` 冒泡到
`document` 就被当成"点了别处"，刚打开的下拉立刻关掉（第一次修只改了①，现场依旧复现，真因就是缺这个类）。
回归 `editor/test/client-state.test.mjs` 的「focus → click」那条（假 DOM 为此补了 `closest()` 与
`fireDocument()`；把 `.nickpick` 去掉它必红）。

**浮层要跟着视口走，不能"一滚就关"**（移动端）：`resize`（软键盘弹出）/ 页面滚动 / `visualViewport` 变化时
只**重摆**（`syncPickerPlace`，贴哪一格记在 `picker.__host`），收起只留给"点别处 / Esc / 选完"。
量视口用 `visualViewport.height` + `offsetTop`（软键盘只改它、不改 `window.innerHeight`），否则会出现
"算着放得下、实际被键盘盖住"。这条是手机键盘一弹就把候选下拉关掉（等于移动端用不了）的修法。
回归 `editor/test/client-state.test.mjs`（候选下拉那条 + 「移动端：键盘弹出…」那条）。

**「＋ 新增一行」在表格下面**（同一轮）：移动端不用滚回顶部才能报名，顶部那条只剩「共 N 人 · 待保存 N 项」。
回归 `editor/test/editor.test.mjs` 的「页面源码」那条（按钮必须在 `#grid` 之后、且落在 `.barfoot` 那一行里）。

成员只有填写页，报名不能让他们回排队表；没报名时点主按钮「我要报名」也会就地建一行

## 名单、认人与链接投递

**管理员的私聊链接只在本人发 `#排队` 时给一次**：链接是**带当期 `w/ws` 的长地址**，5 分钟窗口过期即失效，
要新的再发一次 `#排队`；tick **不主动重发**（既不撤回也不刷新），状态文件只记"发给了谁 / 哪个窗口 / 消息 id"。
**管理链接只能从"窗口刚验过的那一刻"进门**（2026-10-18 审核 P1）：那一刻给这台设备种一枚 24 小时的
`abyss_admin_ok` 会话 cookie（HttpOnly / SameSite=Lax / 只在 https 上带 Secure；令牌是 HMAC 绑 QQ + 过期时刻）；
之后**不带 `w/ws` 的管理员请求必须带着它**，否则按过期链接处理（410 + 提示页）——不这样的话，把 `w/ws` 删掉
就能靠 30 天的身份签名一直当管理员。普通群友不受影响（他们的凭据是长链接的 `v` 标记、按"链接新旧"管）；
管理口令（`?a=`）同样不受影响（独立静态凭证，由页面存起来按请求头带）。回归 `editor/test/editor.test.mjs`
的两条（删窗口 ⇒ 410 / 同一设备窗口进门后不带窗口照常）。
`@` 人的"群昵称 → QQ"取**两路**：实时向框架要群成员，外加最近一次**扫成功**的名单缓存（实时那份是空就拿缓存兜底）；
两边都拿不到只发名字、不发 @，并记一条 info 日志（榜名 + 行号）。这份缓存**落盘一份**在
`<插件根>/data/roster.json`（`{ group, at, members: [{qq, nick}] }`，与绑定 / 进度同档、没有配置项）：
机器人重启后到下一次扫描之间也能 @ 得动，而且"本地到底有没有名单"有文件可查（读盘懒加载，坏文件当没有）。
**认人只认 QQ 绑定，名字只用来"没有绑定的时候怎么认"**（2026-10-18 维护者口径：
"识别的是群昵称，不是 QQ 名片"、"最好直接用绑定的 QQ 兜底"）。线上那一串现场是：
本人群昵称「希珀塞莱妮娅」，机器人拿到的是 QQ 名牌「绒月.」，绑定指着 `深境螺旋#14`、
而那一格写着「铭诸心腑吖」（维护者："铭诸心腑吖不是我的名字，表里有我自己的行"）。
所以 `locateSelf` 的判据是：**绑定（QQ）就是身份**——那一行还在、也没被别的 QQ 有效绑着，就认它；
名字对不上只返回 `renamedFrom` 当**诊断用**的数据（`syncIdentity` 记一条日志），**不据此判绑定作废**
（判废了本人那一块会直接空掉），**也不在回执里催人改表**——机器人手里那个名字本来就可能是错的
（2026-10-18 现场：表里三行都写「希珀塞莱尼娅」，机器人认成「缄月.」并按它催"请把那一格改成缄月."，
等于让用户把**正确的那一格改错**）。只有"那一行没了 / 已有效归属给别人"才算过期。
名字这一路并不可靠（框架的 `card` 有些适配器给的是 QQ 名牌，表里那一格也可能写错），所以：
① `AppBase.nicknames()` 给出**候选名字**，顺序是 **框架 `card` → 群名单里该 QQ 的群昵称 → 框架 `nickname`**
（`nickname()` 取第一个，用于日志 / 私聊链接记录；`card` 是群里那一刻最准的，群名单可能旧一天）；
② `mineView` 拿这串名字逐个试（`locateSelf` 每次只吃一个名字），**命中行就停**——没有绑定时
因此能靠第二、第三个名字认回来。回归 `test/locate-self.test.mjs`（绑定兜底 + `renamedFrom` /
绑定过期后按候选名字逐个试 / 两个 `missed`）与 `test/workbook.test.mjs` 的「本人改了群名片时…」。
**认不回来要明说，不能静默**：绑定失效、按这些名字又都找不到自己那一行时，`mineView` 记一条 `missed`
（哪一榜、绑定原来指哪一行、试过哪些名字、为什么没认回来：`none` 没这名字 / `dup` 重名 /
`claimed` 已绑给别人），`menu()` 的**私聊档**在填写情况那行后面补一句
「⚠️ 没认出你那一行：… 机器人这边认到的名字是 …」——否则用户只看到「未填：三榜」，
分不清"我没报名"和"机器没认出我"。另：`fillEntry` 的 `?n=` 用**表里那一行**的群昵称（认出来时），
不用机器人手里那个可能错的名字。
**填写情况那行是三段、顺序固定**（2026-10-18 维护者：「回复消息新增排队中，三者顺序为
1 未填 2 排队中 3 已完成」）：`未填：…；排队中：…；已完成：…`，空的段不写。
「排队中」= 有自己那一行但还没完成（表里 `排队中`，或榜没开、写着 `等待开启`）；
「已完成」= 主播打完的（表里是主播名）与自己点过完成的（表里落成群昵称）。
回归 `test/workflow.test.mjs` 的「排队中：…三段顺序」那条。
名单的两条自动路径是**启动后 20 秒**与**每天 `roster.at`**；另有主人命令 **`#排队同步名单`**
（`apps/roster-sync.js`，`permission: "master"` + handler 里再判一次 `e.isMaster`）可**立刻**推一次，
回执照实说"同步了几人 / 改名几行 / 退群删了几行 / 为什么没做（没配群号、没配编辑器地址等）"——
`skipped` 与启动后那次 kick 的结果此前**都不记日志**，现场"名单到底推没推"查不出来。
**编辑器侧那一趟对账里的"删行"与"改名"必须分两趟写**（先删行 + 压紧，再在搬完之后的表上改名）：
压紧会把留下的每一行内容整体重写一遍（拿的是本临界区开头那一版表的值），同趟写改名会被同一格上的
旧值盖掉，而写前自检发现"期望新名、实际旧名"就**放弃整趟**——机器人推名单整个失败、当天名单同步
上不去。回归 `editor/test/roster.test.mjs` 的「同一趟里改名 + 退群」。
**压紧扫的是"夹在活人中间"的空行，不是"这一次清掉的那几行"**（2026-10-18 审核观察）：压紧是另一个临界区，
两次几乎同时的删除可能交错成"后一次先压紧、把前一次要删的那一行顶上了别人"，前一次再压紧就被守卫跳过，
空档留在表里（界面上是**序号跳号**，因为序号 = 位置）。反正只有删过行才进这个函数，扫一遍不增加开销，
还能把漏掉的那次一起合上。**只扫中间**：数据区末尾那片空行是"还能填的格子"（`pickRowNumber` 找第一个空行），
`dataEnd` 里有近百行，压紧它们等于把整张表重写一遍。回归 `editor/test/delete-compact.test.mjs` 的 ⑤。

## 播报与 @

**开榜播报末尾要 @ 这一榜的主播**（维护者要求）：@ 的是**这一榜主播区里那几位**（表头上方 A 列，与 `#主播`
同一份名单）——口径是"该榜的所有主播"，**不按 D 列「专职」再筛**（那一列是给人看的说明）。名字与群里不一样
的（表里叫 A、群里叫 B）登记在 `anchor-names.json`（`{ names: { 表内名: 群内名或QQ } }`，
`model/anchor-names.js`）：**手改的数据文件、不是配置项**，**插件内**（`<插件根>/data/`）与**插件外**
（`<Yunzai 根>/data/`，即 `<插件根>/../../data/`）两处任选，**插件内优先**（`anchorNamesPaths()` ——
维护者要求过"放插件外、可自行增删"，放外面还有个好处：`#更新` 的快进绝不会碰它）；值**逐字照抄群名片**
或直接写 QQ（最稳）。**默认没有这个文件**（任何具体名字都不预置）。开关是配置键
`notify.open_anchor`（锅巴里那个 Switch），关掉就一行都不加。两边都对不上的人**只写名字不发 @**并记一条 info
（与"下一位"同一条纪律：不瞎 @、更不 @ 全体）。回归 `test/workflow.test.mjs` 的【4.5】。

**完成播报是"一块三行"，第三行 @ 下一位选的主播**（2026-10-18 维护者：「播报文字会有堆叠感，
重点不突出；下一位添加艾特主播功能。参考模板：xxx已完成，下一位@xxx，主播@xxx。
若选择主播为都可以，则取消最后一句」——**该选项 2026-11-25 起改叫「公共队列」**，下同）：

**行位移不算"刚完成"**（2026-10-18 审核 P2）：`data/progress.json` 的进度快照按**行号**存，而下面这些动作会让

## 定时任务与清榜周期

**定时任务只有一条** `notify.cron`（默认每 3 分钟），依次做下面几件事（都发到 `notify.groups`）：

1. **分榜清榜提醒**：@ 当前仍在排队的人，并做一次完成核查。
2. **开榜提醒**：某榜 `未开启 → 已开启` 时，@ 该榜所有排队中的人；末尾可加 `本榜主播：@…`（`notify.open_anchor`）。
3. **完成播报**：三行结构见「播报与 @」。
4. **回退播报**：已完成 → 排队中，见「播报与 @」。
5. **群成员名单同步**：`roster.at`（默认 05:00），另在机器人启动后 20 秒跑一次。
6. **每日整理**：同一时刻，规则见「播报与 @」。
7. **绝境攻炼版更 @全体**：版更当天 10:00 之后一次，同一期只发一次。
8. **开播提醒**：订阅制，见「主播直播状态与开播提醒」。

- 首次运行（没有 `data/progress.json`）只记基线，一件事都不做；"到点之后"当天都算数（半夜关、早上 9 点起仍补做）。
- 名单同步与每日整理**不发群**，所以关掉 `notify.enable` 不停它们；去重标记都在 `data/progress.json`，一次算好一次落盘再发，发送失败不重发。
- 「月末催办」已废弃（`monthly_enable` 保留但不再产生通知）。

## 主播区（推荐度、专职与别名）

主播区在每张表**表头行之上**：A 列主播名（可带 `【推荐度】`）、C 列核心强项、D 列专职、G/H 列直播入口、I 列总强项（`#主播` 合并多榜时优先用它，为空才退到各榜 C 列）。

**推荐度是五档胶囊**：`夯 / 顶级 / 人上人 / NPC / 拉完了`（颜色依次对应 N6 180s 紫 / N6 红 / N5 橙 / N4 绿 / 黑）。旧值（强烈推荐 / 推荐 / 提分推荐 / 可选 / 不可选）照原样灰显，改一次就换成五档。
机器人出图的排序仍是旧口径（`components/render.js` 的 `recRank` 只认旧档），表里已是五档时 `#主播` 会退化成按名字排；编辑器页面已按五档排序。这是已知问题（README 的「已知限制」里也记着）。

**专职** = 这位主播打哪个榜，放在 D 列（C 与 G/H 之间那块合并区的空位，不与其他列抢格）：

1. 表里手填：D 列写他专职的榜；
2. 自动推断：D 列留空时，按他出现在哪些榜的主播区显示。

编辑器的主播编辑框里，专职默认填当前榜名。

**别名** `config.anchor_aliases`：键是**正名**，值是别名数组（正则整串匹配、忽略大小写；写错的正则跳过，不影响出图）。例：

```yaml
anchor_aliases:
  阿修Axiu: ["阿修"]
  摸头妹: ["璃月第一深情"]
```

影响 `#主播 <名字>` 查找、`#排队` 里本人那一行的直播入口、编辑器「选择主播」下拉归一；**表里原文不改写**。改名时旧名若落在键上会被拒（先改 YAML 再改表，见「页面交互」）。主播编辑框（管理员，`POST /api/anchors`，带 `version`）六个字段：主播名、推荐度、专职、简介、直播入口平台与链接。

## 主播直播状态与开播提醒（2026-10-25）

- **只认 B 站**：主播区 G/H 里的 `live.bilibili.com/<房间号>` 与 `space.bilibili.com/<UID>`；抖音/虎牙/会议**不展示、不查状态**，由维护者写在声明里。
  编辑器主播列表只有**一个**「B站直播入口（平台+链接）」输入框；保存时页面自动拆成 G=`B站`、H=`链接`。
  `#主播` 图与 `#排队` 菜单里这一栏叫「开播状态」；有状态时只显示 `直播中/未开播`（**不带主播名、不带长链接**），查不到才显示链接；状态字号比正文大一号。
  `#排队` 一行选了**多位主播**时状态徽章要带主播名（否则分不清是谁）；单选不带。
  接口全公开、**不需要 Cookie**，不引 `node-fetch` / Redis / 新依赖（`model/live-status.js`）。
  缓存用 `roomAlias` 把短房号归一成接口 `room_id`；UID-only 直接进批量查询补房间；开播事件写 `pending`，由 tick 统一取走，自检刷新不会吞提醒。
- **开关** `anchor_live.enable`（默认 `true`，`config.yaml.example` 也是 true）：关掉时**完全不发请求**；打开后由唯一的 tick 每轮刷新，
  缓存 3 分钟、超过 10 分钟没刷新成功就不展示。`#主播` / `#排队` **只读缓存**，不在命令里等外网。
- **只显示「直播中 / 未开播」**；查不到或过期**不显示**（不把"不知道"写成"未开播"）。
- `#主播` 列表的 B 站入口后带 `直播中/未开播`（主播名已在第一列，不再重复）；`#主播 <名字>` 多一行 `直播状态：直播中` + 直播间地址；
  `#排队` 里本人选的主播正在直播时，图后文本直接给 `你的主播「…」正在直播：<地址>`。
- **开播提醒** `anchor_live.push`：只 @ **用 `#排队开播提醒` 订阅过**、当前还在排队、且选的就是这位主播的人；
  一个订阅的人都没有时**整条不发**；不 @ 全体；首次刷新只记基线（不把在播的全部报一遍）。
- 数据落点：`data/anchor-live.json`（状态缓存）、`data/live-alerts.json`（订阅名单），**常量、没有配置项**；
  套件用 `ABYSS_QUEUE_ANCHOR_LIVE_FILE` / `ABYSS_QUEUE_LIVE_ALERTS_FILE` 重定向。
- 帮助页：`#排队帮助`（`#排队菜单` / `#深渊帮助`），内容在 `resources/queue/help-cfg.js`，
  失败回落同源文本；回归 `test/anchor-live.test.mjs` 与 `test/help.test.mjs`。
