# 业务口径（认人、播报与名单）

> 完成情况与锁定、认人与绑定、播报与 @、名单同步与整理、直播状态、绝境攻炼。
> 规范面见 `AGENTS.md`，实现细节见 [`编辑器-写入与安全.md`](编辑器-写入与安全.md) 与 [`编辑器-权限与归属.md`](编辑器-权限与归属.md)；
> 本册只讲**口径**（谁该被认出来、为什么这么判、播报长什么样）。历史沿革见 [`历史沿革-出图与播报.md`](历史沿革-出图与播报.md)。

## 一、完成情况与锁定

**「帮帮完成情况」这一列存的是人**（主播名，或「本人已完成」时落成的该行群昵称，逗号分隔多值）。因此任何改名
（本人保存 / 管理员改行 / 群名单同步）都要过 `editor/status.js` 的 `statusRenamePlan`：把**整段等于旧昵称**的 token
换成新昵称，逐段精确比对，不碰主播名与 `等待开启` / `排队中` / `本人已完成`；榜里两行同名、或这一行查不到可依据的
QQ 绑定时**宁可不动**，并在回执 / 日志里说明。

**主播锁只在"写成某位完成人"时才建**：主播把这格改成主播名（或落成群昵称的「本人已完成」）⇒ 建锁、本人那格只读；
改成 `排队中` / `等待开启` / 清空 ⇒ **删旧锁**（"改回排队中"本来就该还给本人填）。

**普通人只能填两档**：自己那一行只能写成 `排队中` 或 `本人已完成`，其余值（主播名 / 等待开启 / 任意文本）
**只忽略该格并回报**，不整单拒——同一发的其它字段照写。本群成员改**别人的行**按额度与主播锁约束（那是"帮别人打勾"）。

**锁只在"这格确实记着某位完成人、且不是本人自有标记"时才生效**（`lockIsLive` + `lockWorthy`）：值已是
`排队中` / `等待开启` / 空 ⇒ 锁算**过期**；值是字面「本人已完成」或本行自己的群昵称 ⇒ 那是**本人的自有标记**，不算锁
（主播代点过一次「本人已完成」也允许本人撤回）。两种都下发 `statusLocked=false`、保存时也不忽略那格。
这条兜的是绕过 `/api/save` 的改表留下的陈旧锁（`catchUpOpenStatus` 只改状态不碰锁）与"本人改不回排队中"的现场。

## 二、认人与绑定

**认人只认 QQ 绑定，名字只用来"没有绑定时怎么认"**。`locateSelf` 的判据：绑定（QQ）就是身份——那行还在、也没被别的
QQ 有效绑着就认它；名字对不上只返回 `renamedFrom` 当**诊断数据**（记一条日志），**不判绑定作废**、**不在回执里催人改表**
（机器人手里那个名字本来就可能是错的：线上出现过"按错名字催用户把正确那格改错"的事故）。只有"那行没了 / 已有效归属
给别人"才算过期。

**名字这路并不可靠**（有些适配器给的 `card` 是 QQ 名牌，表里那格也可能写错），所以：
① `AppBase.nicknames()` 给**候选名字**，顺序 **框架 `card` → 群名单里该 QQ 的群昵称 → 框架 `nickname`**；
② `mineView` 拿这串名字逐个试（`locateSelf` 每次只吃一个），**命中行就停**——没绑定时因此能靠第二、第三个名字认回来。

**认不回来要明说，不能静默**：绑定失效、按候选名字又都找不到时，`mineView` 记一条 `missed`
（哪一榜、绑定原来指哪行、试过哪些名字、为什么没认回：`none` 没这名字 / `dup` 重名 / `claimed` 已绑给别人），
`menu()` 的**私聊档**在填写情况那行后面补一句「⚠️ 没认出你那一行：…」——否则用户只看到「未填：三榜」，
分不清"我没报名"和"机器没认出我"。另：`fillEntry` 的 `?n=` 用**表里那行**的群昵称（认出来时），不用机器人手里那个名字。

**填写情况那行是三段、顺序固定**：`未填：…；排队中：…；已完成：…`，空的段不写。
「排队中」= 有自己那行但还没完成（表里 `排队中`，或榜没开、写着 `等待开启`）；
「已完成」= 主播打完的（表里是主播名）与自己点过完成的（表里落成群昵称）。

**@ 人的"群昵称 → QQ"取两路**：实时向框架要群成员，外加最近一次**扫成功**的名单缓存（实时那份空就拿缓存兜底）；
两边都拿不到只发名字、不发 @，并记一条 info（榜名 + 行号）。缓存落盘 `<插件根>/data/roster.json`
（`{ group, at, members: [{qq, nick, avatar}] }`，常量、无配置项），机器人重启后到下次扫描之间也 @ 得动。

**群内那条链接 30 秒后自己撤掉**：普通成员发 `#排队` / `#排队 <榜>`，群里那条（图 + `点此填表：…#code=`）发出
30 秒后由机器人撤回；撤回失败只记 warn（QQ 有撤回时限，撤不掉不重试）。管理员与主人的整条回复走私聊，
即使有群内兜底也**不撤**（`replaceGroupOutput(..., { keep: true })`）。同群仍**只留最新一条**：新的一条到达时上一条
立刻撤回，它的 30 秒定时器一并取消，不会撤两次。30 秒写死在 `modules/group-link.js` 的 `AUTO_RECALL_MS`，不做配置键。

## 三、名单同步与整理

**两条自动路径**：启动后 20 秒、每天 `roster.at`（默认 05:00）。另有主人命令 **`#排队同步名单`**
（`apps/roster-sync.js`，`permission: "master"` + handler 里再判一次 `e.isMaster`）可立刻推一次，回执照实说
「同步了几人 / 改名几行 } 退群删了几行 / 为什么没做」，并且**每次都记日志**（此前 kick 那次不记，现场查不出推没推）。

**编辑器侧对账的"删行"与"改名"必须分两趟写**（先删行 + 压紧，再在搬完的表上改名）：压紧会把留下的每行内容整体重写
（拿的是本临界区开头那版表的值），同趟写改名会被旧值盖掉，而写前自检发现"期望新名、实际旧名"就**放弃整趟**
⇒ 名单同步整个失败。

**压紧扫的是"夹在活人中间"的空行，不是"这一次清掉的那几行"**：两次几乎同时的删除可能交错成"后一次先压紧、把前一次
要删的行顶上了别人"，前一次再压紧就被守卫跳过，空档留在表里（界面表现为序号跳号）。反正只有删过行才进这个函数，
扫一遍不增加开销，还能把漏掉那次一起合上。**只扫中间**：数据区末尾那片空行是"还能填的格子"（`pickRowNumber` 找第一个
空行），`dataEnd` 里有近百行，压紧它们等于整表重写。

**成员从哪个接口取，是"逐个来源试、空就换下一个"**（`model/roster.js` 的 `listMembers`）：
`getMemberMap → getMemberList → members → group.group.*`，再兜 `Bot.getGroupMemberList` / `Bot.gl.get`；每个来源都 `await`
（有些适配器做成异步），结果形状 Map / 数组 / 以 QQ 为键的对象都吃。**不许写成"方法存在就直接返回"**——某版本
`getMemberMap()` 给了空对象，于是同步永远回「取到的成员是空的」，昵称候选 / 改名 / 退群删行一起哑掉。一处都拿不到时
抛的错里带**每个来源的形状与数量**与群号，扫成功的来源进日志（`（来源 X）`）。

## 四、播报与 @

**开榜播报末尾 @ 这一榜的主播**：@ 的是**该榜主播区那几位**（表头上方 A 列，与 `#主播` 同一份名单）——口径是"该榜
所有主播"，**不按 D 列「专职」再筛**（那列是给人看的说明）。名字与群里不一样时登记在 `data/anchor-names.json`
（`{ names: { 表内名: 群内名或 QQ } }`，**手改的数据文件、不是配置项**；插件内 `<插件根>/data/` 与插件外
`<Yunzai 根>/data/` 两处任选，插件内优先；`#更新` 不会碰它）。两边都对不上的**只写名字不发 @**并记 info。开关
`notify.open_anchor`（面板 Switch），关掉就一行都不加。

**完成播报是"一块三行"，第三行 @ 下一位选的主播**（该格是「公共队列」或空着 ⇒ 整句不写）：

```
【深境螺旋】第 3 位「甲」已完成
下一位：@乙 请准备
主播：@丙
```

块与块之间空一行。第二行**不带（第 N 位）**（序号已在第一行）。主播取"下一位那行"的选择主播格，多值逐个 @，
名字不同走 `anchor-names.json`，**只 @ 不括注名字**；对不上 QQ 的只写名字。这一句没有单独开关。

**「已完成 → 排队中」补一条播报**：

```
【深境螺旋】第 3 位「甲」的完成情况由「已完成」变为「排队中」，请主播 @丙 注意
```

检测在 `modules/progress.js` 的 `detectReverts`（与 `detectCompletions` 对称：只认真的变过、**只认落到 `排队中`**——
变回 `等待开启` 是"榜还没开"；快照里原本没有的行不报），发送在 `modules/notify/send.js` 的 `notifyReverts`：
主播取**被改的那一行**自己选的主播；该格是「公共队列」或空 ⇒ 照发这句但只写「请主播注意」，不 @ 任何人。

**行位移不算"刚完成"**：`data/progress.json` 的进度快照按**行号**存，而新增主播插一行、每日整理、`#插队`、删行压紧、
整表替换都会让同一个人换行号——行号一换，同一个键上的"上一个人"和"这个人"就对不上，于是把早就完成过的人再报一次。
所以快照同时存一份**结构指纹**（`snapshotShape()`：每榜按行序的 `行号:群昵称`，**行号必须进指纹**：新增主播是在表头上方
插一行，昵称序列一个都不差，只比昵称就漏掉），`tickTasks` 先比它：**结构变了这一轮不判完成**、只记新基线
（老状态文件没这字段 ⇒ 升级后首跑也只记基线）。代价：结构变化与真完成撞同一轮时那条通知会丢——宁可少发一条，不能乱 @。

## 五、`#插队` 与每日整理

两者是同一套"换内容"的用法，都只轮转/交换**数据格内容**（群昵称 → 帮帮完成情况这七列，`MOVE_COLUMN_KEYS`）、
**A 列序号不搬**（序号 = 位置），样式随内容一起换；绑定与完成情况锁按"哪一行的人去了哪一行"重排（`remapRowsOf`）。

- **`#插队`**（白名单管理员，`apps/inserter.js` → `model/editor-commands.js` 的 `moveRow`）：把某行挪到该榜所有「排队中」
  的人最前面；位置由**编辑器**算（插件只给"哪一榜、哪一行、怎么挪"），本来就在最前面就原样回话、表一个字节不动。
- **整理有两个触发点**：每天 `roster.at` 之后进程内直调一次 `service.tidy`（与名单同步同一时刻、当天一次，**不发群**，
  所以排在 tick "没配通知群就 return" **之前**）；**立刻那一次**——谁在页面改了「帮帮完成情况」，保存成功后由 `applySave`
  的收尾 `afterSaveFollowUp` 对**那一榜**当场做一遍（不必等第二天；每天那趟是兜底）。
  规则（两个触发点共用一份实现）：**「等待开启」是挡位**（原地不动、把排队区分成段、段间不跨着挪）；段内**稳定分区**
  ——已完成（写了人：主播名或本人昵称）在前、「排队中」在后，同类保持原先后；只排**有群昵称的行**；只换内容、不插不删、
  行号与 A 列序号一个不变；**已经有序 ⇒ 一格都不写**（不重新保存、不产生历史版本）。立刻那一次**只认"完成情况真的变了"**
  （改备注不触发），并顺手做一次**昵称检测**（`nicknameCheckNow`：按名单同步改名，找不到人只提醒主人、**不自动删**）。
- **搬过行就要把搬家表回执给页面**（`rowMap`：老行号 → 新行号）：草稿按 (榜名 × 行号) 存，不搬草稿键就会"值对不上、
  永远显示未保存"，下一次自动保存还会拿这个人的值去写那行现在的人。**页面搬草稿必须"先算后写"（两阶段）**：
  `rowMap` 是一次置换（10→11、11→12 这种链到处都是），边读边写会在链 / 环里互相覆盖，留下"键在新行、值是别人"的残留
  草稿（现场表现：名字残留进别人那行的完成情况）。`remapDrafts` 先收集 `{老键, 新键, 值}`、把老键全删、再统一写回。

## 六、页面交互口径

**页面上没有「保存」按钮**：改动写草稿，停手 **1.2 秒**后自动写表（防抖合并连续改动；同一时刻只飞一个请求，飞的过程中
又改了等它回来补一轮）；**必填四项**（群昵称 / 原神游戏名 / 选择主播 / 难度及目标）没齐时**一个请求都不发**；
状态四档 `已保存` / `未保存（有改动）` / `保存中…` / `保存失败，点这里重试`（最后一档可点，点了立刻重发）；
写失败**不自动重试**；版本冲突（409）时草稿一字不动、**自动保存暂停**、也不自动重读。**主播列表那颗「保存主播列表」
保持手动**（结构性写表，在主播区插一行、下面整体下移）。自动保存那条**存底有 5 分钟节流**（`AUTOSAVE_SNAPSHOT_MS`，
否则一次会话连存 20 次就把 `versionsKeep` 个版本位吃光）。

**改主播名要先改别名表**：`config.anchor_aliases` 的**键是正名**，别名挂在它下面。`applyAnchors` 写表前逐行断言：
旧名落在键上而又要改名 ⇒ **直接拒绝**（400，提示「先把这个键改成新名」）——编辑器不替人改 YAML（手写配置，改了会被覆盖）。
取键走 `aliasCanonicalNames()`。

**保存成功之后只清"这一格现在的有效值仍等于提交值"的草稿**：提交前快照这一发的键与值，重读时 `keepDrafts = true`
（一个草稿都不动），回来只清那部分；这期间的新编辑留作草稿、新增行转成"那一行的草稿"。`/api/save` 回执带**写完之后那
一版的 `version`**，页面立刻记下——于是"保存成功但重读失败"不会引出假 409。另三条一起做：**请求 15 秒超时**、
**连败 3 次后退避**（自动发送也停，只留手动重试）、**`beforeunload` 离页守卫**（提示里报别的榜的草稿数）。

**「帮帮完成情况」的下拉候选只有三种来源**：状态词（`等待开启` / `排队中` / `本人已完成`）、主播区、手动「＋ 收录新名字」
——**表里在用的名字不再当候选**（否则每个点过完成的人都变成全体候选，改名 / 退群 / 广告名片留下的名字永远留在下拉里）。
当前值由页面并进候选（点得到、取消得掉），服务端放行"这格本来就有的值"。菜单**只点人、点完就收**：候选里不出现
`排队中` / `等待开启`（那些是机器算出来的状态词）；对还在排队的行点一位主播，页面把状态词**替换**成这位主播，
而不是拼成 `排队中,主播名`（服务端以两者互斥拒收）。

**群昵称候选是一条下拉浮层**：空着给名单最前 `NICK_BROWSE_LIMIT = 8` 个，打字给「一字不差（置顶）→ 前缀 → 包含 →
编辑距离 ≤ 2 且公共连续片段 ≥ 2 字」，取前 6，点一下填入（走草稿 + 自动保存同一条路）；浮层 15 秒无操作自动收起；
名单按需重取（60 秒节流）。**候选必须先清理再摆**：先 `trim`、丢掉"一个字母 / 数字 / 汉字都没有"的名字（纯符号 / emoji
名片）、再按折叠口径（全角括号转半角、去空白）去重，然后才喂给建议函数；名单全是垃圾时整条候选不建。
**单字查询不比编辑距离**（一个字与任意一个字距离都 ≤1），只认前缀 / 包含。浮层**只开不切换**、输入框必须带 `.nickpick`
（否则点输入框这一下冒泡到 `document` 就被当成"点了别处"）；`resize` / 滚动 / `visualViewport` 变化只**重摆**、不关。

**「＋ 新增一行」在表格下面**（移动端不用滚回顶部才能报名）；填写页底部也有一行（`#fillAddRow`，与排队表那颗绑同一个
`addRow()`）；没报名时点主按钮「我要报名」也会就地建一行（只读身份置灰、点了只提示）。

**「难度及目标」的文字口径**：剧诗用 `xx模式满星章` / `xx模式满原石`（如「月谕模式满星章」），**写进表里的值必须与那列
的下拉一字不差、不带分隔符**（2026-11-23 页面曾拼成 `月谕模式｜满原石`，服务端整串比对必然失败，线上报「不在下拉选项里」，
2026-11-26 修：`compose()` 按下拉拼、显示仍由 `goalText()` 拆；服务端 `editor/rows.js` 的 `goalLoose()` 兜底容忍 `[｜|\s]`）。
攻炼的 `7.2模式｜满星章` 是**另一套格式**（`parseAttackGoal` 专门解析），不受此限。螺旋用 `第 N 层满星`；危战文字不动
（`险恶(N4)` / `无畏(N5)` / `绝境(N6)`），只把「绝境(N6)180s」的底色换成深紫（不用深红，红色已是高难档）。
**下拉菜单的格子禁止手写**：单选列（`难度及目标`）验证强度 `errorStyle="stop"`，手打非选项值当场拦下；多值列
（`选择主播` / `帮帮完成情况`）必须 `warning`——Excel 列表验证不支持真多选，`stop` 会把「阿修Axiu,听雨」一并打回。
单选列的名单**只在保存成员行那条路上写**（`writeValidationPlan(..., { single })`）。

**历史版本给白名单成员用**：主人 / 管理口令 / 白名单管理员都能**列出、下载、回退**历史版本与归档；
**「上传覆盖云端」与「归属状态」仍限主人**。页面用两个标志分开：`perm.versions` 与 `perm.manage`——**不许合并**。

**给人看的编号一律是「序号」，不是表格行号**：三个榜表头行号不同，"表格行号"只在同一榜内部有意义。`row` 继续在数据里
流通（删行、对账、`base` 指纹、锁的键要对准表格那行），**凡显示给人的地方一律用 `seq`**（A 列 `=ROW()-k` 的缓存值；
那格空着时按"数据区第几行"算，`editor/ownership.js` 的 `seqAt` 与缺失候选同一口径）。页面写「序号 N」，真行号进 `title`。

**归属状态那一块是按列对齐的小表**：① 第一行统计（`共 N 条绑定：对得上 a、对不上账 b、争同一行 c`）；
② 一行列头（`序号 / QQ / 绑定名 / 状态 / 说明`）；③ 每榜一条分组标题（`剧诗 · 12 条（⚠ 2）`）；
④ 每条绑定一行，`grid-template-columns` 锁死列宽、`.c` 单行省略号（全文进 `title`），**每条永远只占一行**，异常行标 ⚠。
**异常行排在本组最上面**。窄屏（`≤1100px`）放不下五列，回退成"每行一句话"（统计行与分组标题保留）。退群候选仍是琥珀色卡片。

**手机端**：卡片把「序号」与「操作」并成一行（`order: 0` / `order: 1` + `margin-left: auto`，两格 `padding` 必须一致）；
`≤820px` 时 `header` 排成三列栅格（标题与「上次保存」各占满一行；管理按钮等宽三列、36px 高、13px 字；`已保存` 与实时提示
各占一行、`:empty` 隐藏）；榜标签 `auto-fit` 等宽列、榜名与人数竖排。桌面（`>1100px`）保持侧栏两栏布局。

## 七、定时任务与清榜周期

**定时任务只有一条** `notify.cron`（默认每 3 分钟），依次做：

1. **分榜清榜提醒**：@ 当前仍在排队的人，并做一次完成核查。
2. **开榜提醒**：某榜 `未开启 → 已开启` 时 @ 该榜所有排队中的人；末尾可加 `本榜主播：@…`（`notify.open_anchor`）。
3. **完成播报**、4. **回退播报**：见第四节。
5. **群成员名单同步**：`roster.at`（默认 05:00），另在启动后 20 秒跑一次。
6. **每日整理**：同一时刻，规则见第五节。
7. **绝境攻炼版更 @全体**：版更当天 10:00 之后一次，同一期只发一次。
8. **开播提醒**：订阅制，见第八节。

- 首次运行（没有 `data/progress.json`）只记基线、一件事都不做；"到点之后"当天都算数（半夜关、早上 9 点起仍补做）。
- 名单同步与每日整理**不发群**，所以关掉 `notify.enable` 不停它们；去重标记都在 `data/progress.json`，一次算好一次落盘再发，
  发送失败不重发。「月末催办」已废弃（`monthly_enable` 保留但不再产生通知）。

## 八、主播区（推荐度、专职与别名）

主播区在每张表**表头行之上**：A 列主播名（可带 `【推荐度】`）、C 列核心强项、D 列专职、G/H 列直播入口、
I 列总强项（`#主播` 合并多榜时优先用它，为空才退到各榜 C 列）。

**推荐度是五档胶囊**：`夯 / 顶级 / 人上人 / NPC / 拉完了`（颜色依次对应 N6 180s 紫 / N6 红 / N5 橙 / N4 绿 / 黑）。
档位表与排序权重只在一处：`components/render.js` 的 `REC_TIERS` / `recTierOf` / `recRank`。`#主播` 出图、`#主播 <名字>`
详情、编辑器主播区（经 `/api/data` 下发 `recTiers` 与每张卡的 `recRank` / `recTier`）用的是同一份，不另存字面量。

- **旧值按名次归档**：强烈推荐 → 夯、推荐 → 顶级、提分推荐 → 人上人、可选 → NPC、不可选 → 拉完了。归档**只用于排序与
  取最高档**，表里原文一个字不改（`queue.json`、xlsx A 列、下发的 `recommend` 都是原文），不做批量迁移。
- **显示**：旧值照原文**灰显**（图与编辑器一致），提示该换五档；在编辑器主播编辑框点一次五档胶囊即写回新值。
- **排序**：五档原值 = 档位 1..5，旧值 = 归到的档 + 0.5（同档排在五档原值之后），未填与认不出的写法 = 6（永远最后）；
  同 rank 按名字（`localeCompare('zh')`）。多榜合并与单人详情取**最高档**用同一个 rank。
- **代价**：`不可选` 以前被 `/可选/` 一并认成「可选」，现在单独归到「拉完了」，历史数据里若有它，会排到「可选」之后。

**专职** = 这位主播打哪个榜，放 D 列：① 手填；② 留空时按他出现在哪些榜的主播区推断。编辑器主播编辑框里默认填当前榜名。

**别名** `config.anchor_aliases`：键是**正名**，值是别名数组（正则整串匹配、忽略大小写；写错的正则跳过，不影响出图）。
影响 `#主播 <名字>` 查找、`#排队` 里本人那行的直播入口、编辑器「选择主播」下拉归一；**表里原文不改写**。改名时旧名若落在
键上会被拒（先改 YAML 再改表）。主播编辑框（管理员，`POST /api/anchors`，带 `version`）六个字段：主播名、推荐度、
专职、简介、直播入口平台与链接。
