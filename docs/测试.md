# 测试与套件纪律

> **为什么单独成册**：测试口径散落在提交摘要与聊天里就会走样——「为什么跳过」「为什么这里故意报错」这类问题会和代码一起忘记。这份只讲**纪律与判据**，
> 逐套清单、运行参数、测试桩与环境变量**只在 [`../test/README.md`](../test/README.md) 维护**，本页不重复。

## 一、套件形态

63 套 = 插件侧 `test/` 29 + 编辑器侧 `editor/test/` 34。每套一个 `node` 进程、自带账本、独立退出码。

- **断言器只有两个来源**（都在 `test/_helper.mjs`）：`createChecker()`（回调抛错立即中断，新套件用它）与
  `createSoftChecker()`（失败记一条 ❌ 继续跑，尾部 `finish()` 汇总并设退出码，老套件统一到这里）。**都"真的跑回调"**：
  `typeof fn === "function"` 就调用、同步 / 异步都等结果。
  > 纪律来历：2026-10 自查发现 8 个 `editor/test/` 套件各写了一份 `const check = (name, ok) => { if (ok) ✅ }`，
  > 回调永远是"真值"⇒ `check("名字", () => {...})` 只印 ✅、一条断言都没执行。判据是**变异**：把被测实现临时改坏，那一条必须变红。
- **不为死代码写断言**。断言该钉的是"行为契约"（对外可见的结果、别人依赖的语义），不是"这里有个内部函数"。
- **缺前置不算失败**：真实表不在、`XLSX_PATH` 没配、宿主没起时，套件打印跳过并 `exit 0`——`notify`、`editor-host`、
  `bootstrap` 的某些段都是这个口径。CI 与本地因此跑同一份代码、同一份账本。
- **每套 120 秒超时**（`ABYSS_TEST_TIMEOUT_MS` 可调），超时杀**整棵进程树**：编辑器套件会 spawn 子进程，只杀父进程会留孤儿占端口。

## 二、写一条测试时的硬要求

- **不依赖仓库绝对路径**：用 `new URL("./fixtures/…", import.meta.url)` 或 `path.dirname(fileURLToPath(import.meta.url))`。
- **不碰生产数据**：套件里写表一律落在 `test/.test-tmp/`（git 忽略）或系统临时目录；跑前跑后核对原表哈希。
- **端口一律 `freePort()`**：`listen(0)` 拿临时端口，绝不用 7788 / 3000 这种"大概率被占"的值。
- **「保存一行」只提交要改的字段**：行号按昵称 / QQ **现查**（`rowOfNick()` / `rowByNick()` / `myRowNow()`），
  不硬编码行号——否则样本表一变，断言就从"测业务"变成"测行号"。
- **先红后绿**：断言写完后先回退实现（`git checkout -- <实现文件>`，**不要 `git stash`**，那会把断言一起藏起来）确认变红，
  再恢复实现确认变绿。只红不绿 / 只绿不红的断言等于没写。
- **变异自查**（针对"本来就没执行"的假绿）：临时改坏被测实现，那条断言必须变红；不红就说明断言没跑到。

## 三、CI 跑两种口径

`.github/workflows/ci.yml` 两个 job，同一份代码、两种数据前提：

| job | 表从哪来 | 期望 |
|---|---|---|
| `test` | 合成样本（`ABYSS_TEST_SYNTHETIC=1`） | 62 通过 / 1 跳过（`editor-host` 要真实表） |
| `test-xlsx` | 仓库里 `resources/空模板.xlsx` 的副本，用 `XLSX_PATH` 指过去 | 同上；真实 xlsx 代码路径必须被走到 |

`requireSource()`（`test/_helper.mjs`）在缺 `XLSX_PATH` / 缺表时打印跳过而不是失败——这正是「同一份断言、两种数据前提下
应得的结果不同」的实现方式：**跳过是结论，不是掩盖**。

## 四、跑法与耗时

```bash
pnpm test                            # 全量，顺序跑，尾部汇总（约 2 分钟）
node test/run.mjs --list             # 先看清单（别猜名字）
node test/run.mjs workbook anchors   # 只跑关键词命中的
ABYSS_TEST_SYNTHETIC=1 pnpm test     # 强制合成样本
```

- **迭代时只跑受影响的套件**：每套都是新进程（≈144 ms 固定开销），全量 63 套 ≈ 2 分钟，只跑 2–3 套 ≈ 1 秒。
- `--filter=` 这种写法**会被静默忽略**——筛选用位置参数。
- 全量里最重的是 `editor/test/editor.test.mjs`（起真编辑器进程打 HTTP，十几秒）与 `test/workbook.test.mjs`（写 xlsx）；
  其余多在百毫秒级。
- 文档改动不进套件：跑 `node tools/doc-check.mjs`（路径、命令、套件数、已下线名字四类客观校验）。
