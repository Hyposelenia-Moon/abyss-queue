## 插队（`POST /api/move-row`）

群里发 `#插队` 时机器人**不写表**，只把"哪一榜、哪一行、怎么挪"发到这里，**位置由编辑器算**
（`apps/inserter.js` → `model/editor-commands.js` → `editor/actions.js` 的 `moveRow`）。

- 参数：`{ sheet, row, mode: "queue-front", nick? }`（`nick` 只进日志，不影响判定）；**不接受 `version`**——这是管理动作，
  冲突时由主人重发一次即可。
- 语义：目标行 = 数据区里**第一条**「排队中」。这一行本来就在最前面 ⇒ **什么都不做**（`{ ok: true, moved: false, reason }`），
  表 / 绑定 / 锁一个字节都不动。
- 动作：把 `[目标行, 来源行]` 这一段**整体轮转**——来源行的人 → 目标行，目标行及中间的人各后移一位；不插行、不删行、
  不改任何行号，排队区不会出现空行/缺行，序号列逐行不动、仍是 1..N。**A 列序号不搬**：序号 = 位置。
- 归属：绑定与完成情况锁按"哪一行的人去了哪一行"重排（`editor/anchors.js` 的 `remapRowsOf`）；锁上记的昵称因此**永远等于**
  那一行现在的人（不搬就是"锁留在原地、锁到别人头上"）。
- 每格都连**样式号一起换**（`ctx.refStyle`）：不这么做隔行配色会留在原地，人一挪就顶着别人的底色。只有一边有值的格子用
  `ctx.clearCell` 落成空值格，不留空串格、也不挖掉列。
- 权限：只认 `caller.role === 'admin'`；**本人与访客一律 403**——一条消息就能改全表顺序，不该由"能改自己那一行"的身份触发。
- 回归：`editor/test/write.test.mjs` 的插队段。

## 整理：每天一趟 + **改了完成情况就立刻生效**

机器人每天到 `roster.at`（默认 05:00）之后调一次 `POST /api/tidy`，把每个榜的排队顺序理一遍；它同样**不写表**，
顺序由编辑器算（`editor/actions.js` 的 `applyTidy` → `editor/table-ops.js` 的 `tidySheetsCore` + `editor/reorder.js` 的
`tidyOrder`）。**同一份整理**还有第二个触发点：**有人在页面上改了「帮帮完成情况」**（本人点「本人已完成」、管理员改行、
改名连带改到都算），保存成功后由 `applySave` 的收尾 `afterSaveFollowUp` 当场做一遍。每天那一趟是**兜底**。

- 参数：`{ sheet? }`——不给就整理所有榜（一次 `mutate`、一份历史版本、一个版本指纹）；**立刻那一次只整理被改的那一榜**。
- 口径：统一分三段——**已完成 → 等待开启 → 排队中**；组内先按难度、目标从小到大；同目标按完成类型
  本人完成 → 主播完成 → 本月临时名 → 未知完成人；最后按原始行号稳定兜底。「等待开启」不再原地不动、也不再切段。
- 只排**有群昵称的行**：空行不参与也不动（它们是"还能填的格子"）。
- 动作与归属：与插队同一套——只**换内容**（`moveCell`，样式随内容换）、不插行不删行、行号一个不变、A 列序号不动；
  绑定与锁按"哪一行的人去了哪一行"重排。
- **幂等**：已经就是这个顺序 ⇒ `moved: 0`、**一个字都不写**（不重新保存、不产生历史版本）。回执的 `moved` 数的是
  **位置变了的行数**（一次互换算 2），逐榜 `{ sheet, moved, reason? }`；立刻那一次还会带 `tidied`——**只有真挪了才有**。
- **回执要带行号搬家表 `rowMap`**：搬行 = "第 N 行换人了"，而页面草稿按 (榜名 × 行号) 存。`applySave` 把"删行压紧"与
  "立刻整理"两次搬动合成 `{ 老行号: 新行号 }`（`composeRowMap`）交给页面搬到新行号——不搬的话回执里的值对不上，
  「未保存」永远清不掉，下一次自动保存还会拿这个人的值去写那一行现在的人。
- **立刻那一次还会顺手做一次昵称检测**（`nicknameCheckNow`）：改名按名单同步，名单里找不到人只提醒主人、**不自动删**。
- **存底节流**：立刻那一次紧跟在一保存之后，而那次保存已存过底，所以它按自动保存的节流（`AUTOSAVE_SNAPSHOT_MS` = 5 分钟）
  存历史版本；每天那一趟不节流。
- 权限：`POST /api/tidy` 是**机器人身份**（插件签的 `ROSTER_QQ`）或主人；本人与访客 403。**立刻那一次不额外判权限**
  ——它是那一发已被放行的保存的收尾。
- 回归：`editor/test/write.test.mjs` 的整理段（段内分区 / 挡位不动 / 空行不动 / 行号与序号不动 / 数据不丢不重 / 归属跟搬 /
  幂等不写 / 权限 / 改完成情况立刻整理 / 名单不可信只跳过检测 / 改名同步 / 退群只报不删 / 每日兜底才删）。

## 主播列表：谁改、怎么加

表头上方那份「主播列表」（`#主播` 与「选择主播」下拉的唯一来源）只有**主人与白名单管理员**能改（`perm.role === 'admin'`，
与白名单一样**只认 QQ**，群昵称不当权限）。**本人与访客的页面上根本没有这块面板与「＋ 新增主播」**——不是置灰：
`renderAnchors()` 在非管理员时收起面板、清空行表、连按钮都不渲染；`/api/anchors` 也只认 `caller.role`（否则 403）。

- **改既有行**：`rows: [{ row, values }]`，行号必须是表里**已有**的主修行。
- **新增主播**：`added: [{ values }]`。主播区没有空行可占，所以服务端在**最后一位主播下面插一行**：公告行 / 表头行 /
  数据行连同合并格、下拉验证范围、条件格式范围、超链接、冻结窗格与序号公式一起下移一格，绑定与锁里的行号同步搬走
  （`model/xlsx.js` 的 `insertRowsAndShift` + `editor/anchors.js` 的 `shiftRowsOf`）。新行行号由**服务端**定，页面保存
  成功后重读才拿到；插入前照常存历史版本。**注意口径**：主播区（表头**之上**）与排队区（表头**之下**）是同一张表的两个区，
  行号却是一根轴——新增主播会把**表头与整个排队区一起下移（行号 +1）**，绑定与锁自动跟搬、排队区内容一个字不变；
  **两边序号各自独立**（排队区序号仍是 1..N，`=ROW()-偏移` 的常量同步 +1、值不变）。插入点必须**严格落在表头上方**
  （`insertedAt < headerRow`）：表头在第 3 行及更靠上时算出的插入点会落进排队区，这种表一律拒绝（400，表 / 绑定 / 锁 / 版本
  一个字都不动）。
- **必填与落格**：主播名不能为空（前后端都拦）；推荐度拼回 A 列原文「主播名【推荐度】」。推荐度按值着色：
  `强烈推荐` 红、`提分推荐` 与 `推荐` 同款深蓝（`#16358f`）。
- **一个 B 站直播入口**：只有一个输入框「B站直播入口（平台+链接）」；保存时自动拆成 G=`B站`、H=`链接` 两格
  （旧表里链接写在 G 或 H 都能读）。**只展示 B 站**；抖音/虎牙等其他平台写在声明里，不出现在 `#主播` / `#排队` 中。
- **绝境攻炼**：E 列点开是左右两栏——模式多选（5 个，7.0/7.1 快捷按钮）、目标单选（满原石 / 满星 / 顶分）。表里显示模式
  短名 + 目标徽章；某版本模式全选才简写为 `7.0模式` / `7.1模式` / `7.0/7.1模式`。不设难度，这列**不写表内验证**。
- **旧三榜**：难度/目标只在显示层拆成「文字 + 目标徽章」，表值、下拉值、保存值都不变；剧诗点开拆成模式/目标两栏单选
  （目标只有**满原石 / 满星章**两档，「顶分」是攻炼写法），危战/深境只在组间画线、线上不写字。
- **并发**：与成员行保存同一套——带 `version`，对不上返回 **409**，一个字都不写（要插的那行也不插），页面保留草稿、
  只提示、不自动重试也不自动重读。
- **删主播仍然要去表格里删行**：编辑器只做"改既有行 + 新增"。
- **窄屏（≤820px）看不到这块面板**：`editor.html` 的媒体查询里 `.anchors{display:none !important}`（主播表 7 列 × N 行会把
  手机页面拉得很长）⇒ 主人在手机上也看不到主播列表与「＋ 新增主播」，换宽屏就回来。这是**有意行为**。

## 页面上的草稿、自动保存、「重新读取」与「回到上一次修改状态」

**没有「保存」按钮**：改动落在内存草稿上，停手 **1.2 秒**后自动写表（连着改合并成一次请求，同一时刻只飞一个，
飞的过程中又改了等它回来补一轮）。状态在头部右上角一格：

| 状态文字 | 什么时候 |
|---|---|
| `已保存` | 没有待保存的改动 |
| `未保存（有改动）` | 有改动，等防抖到点 |
| `未保存（有改动）· 必填没补全` | 必填四项（群昵称 / 原神游戏名 / 选择主播 / 难度及目标）没齐——**一个请求都不发**，补齐后自动写 |
| `保存中…` | 请求在飞 |
| `保存失败，点这里重试` | 写失败（网络 / 口令失效 / 版本冲突）：**不自动重试**，点这行立刻重发 |

写表语义：成功只清**刚保存那一榜**的草稿、弹一句写了多少行（含 `.bak` 备份）。

**保存成功之后怎么清草稿**：`/api/save` 返回 200 之后会重读一次表，而 `await` 这一两百毫秒里用户可能又敲了字——原来
"整榜清草稿"会把新编辑一起抹掉。现在提交前快照**这一发提交的键与值**，回来只清"**这一格现在的有效值仍等于提交值**"的键；
期间又改过的照旧是草稿。回执里还带**写完之后那一版的 `version`**，所以"保存成功但重读失败"时再点重试不会撞 409
（状态字写「已保存（刷新数据失败，点「重新读取」）」）。

**回执带了 `rowMap` 就先把草稿键搬走**（`remapDrafts`）：删行压紧与"改了完成情况立刻整理"都会让"第 N 行换人"，而草稿按
(榜名 × 行号) 存。必须在"按值比对清草稿"**之前**把 `edited` / `rowClashes` / `blockedRows` / `added` / 这一发快照一起搬到
新行号——不搬的话值对不上，「未保存」永远清不掉，下一次自动保存还会拿**这个人的值**去写那一行现在的人。

**本地「新增行」的行号也可能撞上表里的行**（`settleAddedRows`，每次重读后跑一次）：新行行号是页面按"**我看到的**空行"挑的
（`pickRowNumber`），而表可能在那之后变了。撞上就把它挪到下一个空行（草稿键一起搬）：不挪的话界面上**同一行会画两次**，
点保存还会拿"我这一行"的值去写表里那一行现在的人。**刚刚提交过的那一行例外**（`load()` 的 `keepAddedKeys`）——它当然在
重读回来的表里，交给"按值比对清草稿"收尾；也正因这条豁免，退场判断必须认得"**草稿已被清掉**"= 这一行就是落表的那一版，
否则会凭空造出一条**全空的草稿**、下一次自动保存把刚加的那行清掉。还有一处收尾：**有新增行退场时要补一次重画**
（`renderGrid()`）。

**另外三处自动保存相关**：① **请求带 15 秒超时**（`AbortController`）——半开连接不会让 `saveInFlight` 永远为 true；
② **连败退避**：连续失败 3 次之后自动发送也停下，只留"点状态文字重试"；③ **离页守卫**：还有"真的没保存"的改动时注册
`beforeunload`；头部提示也把**别的榜**的草稿数说出来。

草稿只活在浏览器内存里，**没有第二份**：

- 保存时带 `/api/data` 下发的那版 `version`；服务端发现表已变就 **409**，页面只提示（常驻提示条 + 「读取最新并对比」）、
  **保留草稿**，既不自动重试也不自动重读；**409 之后自动保存暂停**，要写就点状态文字的「保存失败，点这里重试」，或先走
  「读取最新并对比」核对完再点；主播列表保存与成员行保存是**同一套**语义（`failConflict` / `keepDrafts` 共用一条路径）。
- 「保存主播列表」**保持手动**：它是结构性写表（会在主播区插一行、下面的行整体下移），不适合跟敲键自动触发。
- 「重新读取」默认**保留草稿**并列出这一版的变化（`describeChanges`）。
- **丢草稿 = 刷新页面**（页面不提供"丢草稿"按钮：那名字会让人以为它能撤销保存）。
- 「回到上一次修改状态」（主人与白名单管理员可见）= **服务端回退**：把表换回版本目录里最新那一份，走 `POST /api/restore`，
  与「历史版本」里的「回退」同一条路；回退前也先存一份当前状态 ⇒ 点错了再点一次就回来；带草稿时先提醒"回退后草稿作废"。
  **注意粒度**：自动保存那条路的存底有 **5 分钟节流**，所以连改期间"上一次修改状态"最多是 5 分钟前的状态。
- 头部「共 N 人 · 待保存 M 项」只数**真的跟表里不一样**的行（`rowChanged`），改回原样不算一项、也不发白写的请求。
- 回归：`editor/test/autosave.test.mjs`（防抖、必填闸、状态文字、失败重试、409 暂停、只读视图）。

## 数据安全

- 写入是「读 → 改 → **写后自检**（重新解析新文件核对写入值）→ 原子替换」，核对不过就放弃写入。
- **旁路状态文件（白名单 / 完成情况锁 / 群名单 / 口令登记簿 / 绑定 / 改动记录）也是原子写**：`components/json-file.js` 的
  `writeJson` 走「临时文件（与目标同目录）→ `rename`」，失败清中间产物、错误抛给调用方（原来是直接 `writeFileSync`，
  崩在中间就留下撕成两半的 JSON，读的一侧一律当"没有"）。回归：`editor/test/link-identity.test.mjs` 与 `test/roster.test.mjs`。
- 每次写表**前**把当前状态存进 `<插件根>/data/versions/`（默认留最近 20 份，第一次写表才有第一份）。**自动保存那条路有
  5 分钟节流**（`editor/versions.js` 的 `AUTOSAVE_SNAPSHOT_MS`）：每次改动都留一份的话，一次编辑会话连存 20 次就把 20 个
  版本位吃光（实测连写 25 次 ⇒ 20 份的 mtime 跨度 0 秒）。节流后连改最多 5 分钟留一份，20 份 ⇒ 至少覆盖最近 100 分钟，
  更早由每日 / 每月归档兜底。**结构性动作不节流**（上传覆盖 / 回退 / 整理 / 插队 / 名单同步 / 主播列表 / 归属重建）。
  回归：`editor/test/versions.test.mjs` 的「自动保存节流」。
- 覆盖类操作（回退 / 上传）先校验「能否解析」+「工作表清单与当前一致」，防传错文件把表搞坏；解析带**解压预算**
  （所有部件合计 ≤256 MB、条目 ≤2048）——xlsx 就是 zip，1 MB 能解出几十 GB，而编辑器与机器人同进程，撑爆一次全群掉线。
- 替换前落 `<表>.bak`；群成员名单为空时**拒绝**按它对账（防止全员被当成退群）。
- 群成员退群时删掉他那行并**压紧**，删前自动存版本。
- **按 QQ 同步昵称只在"新名片非空"时发生**：本人打开页面时若链接身份里的群名片为空（名单里没这个人、`nickOf` 也补不出），
  **一个字都不写**——不覆盖表里已有昵称、也不写空串。群名片为空只是"这次取不到"，不是本人清空了名片；当成改名回写会把
  成员填好的昵称清掉。只有拿到**非空**新名片才同步，退群删行与 stale/conflict 对账不受影响。
- **改名要顺带把「帮帮完成情况」里记着他旧昵称的整段值换成新昵称**：这一列存的是人（主播名，或「本人已完成」落成的群昵称，
  逗号分隔多值），只改昵称格会留下查无此人的名字。三条路径（本人保存改名 / 管理员改某行 / 群名单同步改名）都过同一个
  `editor/status.js` 的 `statusRenamePlan`：**逐段精确**比对（不做子串替换），主播名与 `等待开启` / `排队中` / `本人已完成`
  一律不碰；两行同名（人工改表才有）或查不到可依据的 QQ 绑定 → **宁可不动**，并在回执 / 日志里说明。
  回归：`editor/test/nickname.test.mjs`。
- **这一列的下拉候选只认三种来源**：状态词、主播区名字、手动「＋ 收录新名字」。**表里在用的名字不再当候选**
  （`mergeStatusOptions` 去掉了那段兜底）：点「本人已完成」落进来的是**群昵称**，端出来等于每个点过完成的人都变成全体候选，
  而改名 / 退群 / 广告名片留下的名字又会一路残留（`archiveOptions` 只增不减）。两条安全绳：① **当前值永远在候选里**
  （页面把这一格现值并进候选）；② **服务端放行"这一格里本来就有的值"**（`validateRows`），老数据照旧能改能存、只是不再
  扩散；保存 / 归档时这份净化后的名单会写回表里（自愈）。回归：`editor/test/editor.test.mjs`（真写一个群昵称进去、候选里
  不许出现）与 `editor/test/client-state.test.mjs`（现值仍在候选里、点一下能取消）。
- **群昵称候选是「下拉浮层」，只有一个出口**：点进输入框或打字时在**格子下方浮一层**（`.nickpick`，摆位与其它浮层共用
  `place()`），空着时给名单最前 `NICK_BROWSE_LIMIT = 8` 个，打了字给最像的几个（前缀 → 含这段 → 编辑距离 ≤2，按"越紧越短"
  排序取前 6，一字不差置顶），点一下填入并**自动收起**；走与手改**同一条路**（写草稿 → 刷"待保存 N 项" → 排自动保存）。
  常驻的胶囊条 `.nickhint` 已删（一表十几个名字、每格再撑一条，手机上整行高度翻倍）；原生 `<datalist>` 仍**不挂**
  （按前缀配、会与浮层同时出现两处，也不能按"差一两个字"匹配）。
- **候选名单先清理再摆**：先 `trim` 去空名、丢掉**纯符号 / 纯 emoji 名片**（`.` `。` `⚡`，只是占位符）、再按归一化名字**去重**，
  然后喂给 `nickSuggest`；名单里全是垃圾时整条候选不建。
- **模糊匹配只按"文字相近"判，不按字数**（`nickSuggest` + `commonRun`）：编辑距离只说明"差几个字"——「随伦」与「听雨」字数
  相同、距离 2，却一个字都不重叠，那不叫相近。所以模糊档要求两段文字有**连续 2 个字以上的公共片段**，再谈距离 ≤2；
  排序"越紧在前、同档里公共片段越长越前"。**单字查询不跑模糊匹配**（一个字与一个字的距离总是 ≤1，"随"会把名片就是 `.` 或
  另一个单字的人全捞出来），只认前缀 / 包含。
- **浮层"只开不切换"，且输入框必须带 `.nickpick`**：手机上一次点按 = `focus` → `click`，两个处理器都做开关切换就会"开了又关"
  （`showNickPicker()` 只负责开）；`document` 那层"点别处就收起"按类名放行 `.picker` / `.chips` / **`.nickpick`**，输入框不带
  这类名的话这一下 `click` 冒泡到 `document` 就被当成"点了别处"。收起只留给点别处 / `Esc` / 选完一个候选。
- **浮层跟着视口走，不再"一滚就关"**：`resize`（软键盘弹出）/ 页面滚动 / `visualViewport` 变化时只**重摆**开着的浮层；
  量视口用 `visualViewport.height` + `offsetTop`（软键盘只改它、不改 `window.innerHeight`），否则浮层"算着放得下、实际被键盘盖住"。
  回归：`editor/test/client-state.test.mjs` 两条。
- **「＋ 新增一行」在表格下面**：移动端不用滚回顶部才能报名；顶部只剩「共 N 人 · 待保存 N 项」。
  回归：`editor/test/editor.test.mjs` 的「页面源码」条（按钮必须在 `#grid` 之后、且在 `.barfoot` 那一行里）。
- **同一张表只允许一个写者**：启动时探一次 `127.0.0.1:7788`（那儿有独立编辑器就**不挂载**），挂载成功后每 **5 分钟**再复探
  ——"宿主起来之后才被拉起的旧编辑器"靠启动那一次挡不住，那种情况下两个进程会各持写队列改同一张 xlsx。复探命中只记一条
  **error** 提示人工处置（"停掉它 + 清掉拉起它的计划任务 / vbs + 重启机器人"），**不自动卸载**。判据是"那儿有 HTTP 回应"
  （200 / 403 都算）——**宽判据是有意的**：宁可少挂一次、让人看一眼日志，也不放过残留写者；探针不带口令。

**响应头（公网面加固）**：所有响应——含 301 / 403 / 410 / 500 这些提前返回的——都由 `editor/http/server.js` 开头统一带上
三个头 + 一份 CSP（`editor/http/respond.js` 的 `SECURITY_HEADERS` / `CSP_PLAIN` / `cspForPage`）：

| 头 | 值 | 堵什么 |
|---|---|---|
| `X-Frame-Options` | `DENY` | 被任何站点 iframe 套住 → 诱导已登录的主人改数据（点击劫持） |
| `Referrer-Policy` | `no-referrer` | 口令在地址栏 / `?k=` 里，别顺着外链 Referer 漏出去 |
| `X-Content-Type-Options` | `nosniff` | 提示页是 HTML、接口是 JSON，别让浏览器猜类型 |
| `Content-Security-Policy` | 首页：`default-src 'self'` + `script-src 'self' 'nonce-<每次响应现生成>'`；其余页面：`default-src 'none'` | 塞进来的脚本执行不起来（**最后兜底**） |

页面模板里两段内联 `<script>` 都写着 `nonce="__NONCE__"`，由首页路由按**每次响应**现生成的随机串替换；`style-src` 保留
`'unsafe-inline'`（页面本来就是内联样式）。**页面里不许再出现内联 `on*=` 属性**——CSP 会挡掉（现有代码全部用 JS 赋处理器）。

**凭证走请求头、不进 URL**：页面自己发的 `/api/*` 一律用 `x-abyss-token` / `x-abyss-identity` / `x-abyss-sign` / `x-abyss-admin`
带头（`editor.html` 的 `authHeaders`），所以这些请求的 URL 里没有凭证、nginx access log 也记不到。服务端取法是 **`paramOf`：
请求头优先、query 兜底**（`x-abyss-window` / `x-abyss-window-sign` 同理），老地址 / 老页面照旧能用。**仍带 query 凭证**的
只剩导航类：首页那一跳、`font/cn.woff`、下载链接——要彻底干净就在 nginx 对 `/queue/` 的 query 做脱敏或关掉这段 access log。

**写操作留痕（审计）**：所有非 GET 请求在响应结束时记一行 `[abyss-editor] qq=… action=/api/xxx status=… <细节>`
（`editor/audit.js`），细节由各写接口补（`sheet` / `rows` / `written` / `version` / `members` / `add` 等）——目的是
"表被改坏了能回溯是谁干的"。出口**由宿主注入**：宿主模式走框架 logger，独立跑走 `console` 并同时写 `data/editor.log`；
这一行**只写显式字段，绝不带 `?k=`**；**失败也记**（`status=403/400`）。

接口响应（`json()`）统一带 `cache-control: no-store`：里面是按身份裁剪过的行数据，不许被浏览器或中间代理缓存。以后新增
**口令校验之前**就能到达的路由（现在三条：301 / favicon / 头像代理 `GET /api/avatar?qq=`——`<img src>` 带不了 `x-abyss-*`
请求头，只能放在闸前；QQ 只认 5~12 位数字，上游按主机白名单固定拼、不接任意 URL）时，要一并想清楚这几个头与 CSP。

**页面上的其他加固**：

- **群昵称进 `innerHTML` 前先转义**（`esc()`）：群名片是用户随时能改的文本。单引号也转（`&#39;`）——现在拼的都是双引号属性，
  但页面里只要有一处把转义值放进单引号属性或内联脚本，少这一个字符就能跳出上下文（CodeQL `incomplete-escaping`）。
  其余 HTML 面（`pillEl` / `describeChanges` / `note` / 白名单面板 / 版本列表）本来就走 `textContent`。
- **页脚自由 HTML 先净化**（`editor/config.js` 的 `sanitizeFooter()`）：`<script>` / `<iframe>` / `<object>` / `<link>` / `<meta>` /
  `<base>` / `<form>` 整段、所有 `on*=` 事件属性、`javascript:` / `vbscript:` / `data:` 的 `href|src`（含 `xlink:href`）一律剥掉，
  `<style>` 与普通标签留着。**实现**：先按不动点剪危险标签，再把每个标签拆成属性重建；属性值先按浏览器口径还原（实体
  `&#x61;` / `&colon;`、大小写、空白）再判协议——一遍正则删属性是 CodeQL 点名的「不完整净化」，别改回去。**代价**：页脚里
  跑不了脚本。CSP 是第一道防线，这是第二道。
- **业务日志里的用户可控文本先压成一行**（`editor/audit.js` 的 `oneLine()`）：群昵称 / 表名 / 手填名字都可能带 `\n`，不折叠就能
  在日志里伪造一行。
- **提示条带 `role="status" aria-live="polite"`**，输入框带 `aria-label`、长度上限 `maxlength`、`data-row`/`data-field`（重画后
  找回焦点）。

## 旧写入端在「保存后立刻整理」之后不可信

改完成情况会**立刻整理**（已完成 → 等待开启 → 排队中，组内难度/目标/完成类型），行号会变。**带 `base` 行指纹的页面**不受影响：
每行下发 sha1 指纹，目标行换人 ⇒ 409/422 **行级冲突**，不会写到别人那一行上；页面自己还会用返回的 `rowMap` 把草稿迁到新行号。

但**不带 `base` 的写入端**（旧标签页、脚本重放整行、机器人进程内提交的整行保存）在搬行之后**不可信**：它按旧行号写下去，
落到的是**别人的行**。目前只有 `nickname` 格有"同榜唯一"校验兜着（会以「昵称与表格第 N 行重复」被 400 拒掉），而**空昵称的
新建行、只改备注/主播/完成情况的重放没有这层保护**，会静默写错行——事后可从改动记录与历史版本追回。

口径：**整理与保存都假定写入端带 `base`**；要正式支持旧端，就在服务端补一条"整行提交而该行号已换主人 ⇒ 拒"的判据。
