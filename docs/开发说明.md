边界口径：本仓库**不设 `lib/`**（框架级通用库位，插件不新建，见 `docs/架构.md`）。能被编辑器（同进程的第二个入口）
直接 import 的纯逻辑按归属落在 `model/`、`modules/`、`components/`；吃 bot 全局（`Bot` / `segment` / `logger`）
或会读文件的同样按归属放。带 ★ 的文件加 `model/table.js`、`model/store.js` 是编辑器 `shared()` 实际加载的共用面，
改它们要一起跑编辑器套件。

`modules/` 的边界：**"先…再…"的流程编排**放这里（可 import model / components，也可有副作用）；**判断与状态**
留在纯函数里，**发送与取数**这类可复用动作留在 `components/`/`model/`。定时通知就是三层分工：
`modules/notify.js`（该不该发）→ `modules/notify/send.js`（发什么、发到哪）→ `components/notify-send.js`（怎么发）。

编辑器就在本仓库的 `editor/` 里，按绝对路径复用本插件的 `model/`、`modules/`、`components/`（表格读写只有一份实现，避免两套逻辑漂移）。入口薄、按职责分模块：

## 二、实现要点

- `model/xlsx.js`：极简 xlsx 容器。不整表解析重排，而是**外科手术式替换目标 `<c>` 节点**，写入用 `inlineStr`，
  完全不动 `sharedStrings.xml`；未改动的工作表逐字节保持原样。**读入口带解压预算**：所有被读到的部件合计解出的
  字节 ≤ 256 MB、条目 ≤ 2048，边解边数（不信 zip 头声明的大小），超了立刻中断并抛错——上传 / 回退都从
  `openWorkbook()` 这一条路进。
- `model/table.js`：每次操作都重新读盘，写入走「读-改-校验-原子替换」；替换前用新缓冲重新解析并核对写入结果，
  核对不过就放弃写入；所有写操作进程内串行。
- `components/config.js`：首次启动从 `config.yaml.example` 生成运行时配置；缺 `editor.public_url` 时回复明确提示
  而不是静默失败（它只用于拼链接，插件不发请求）。
- `model/roster.js`：取群成员（群名片优先）并推给编辑器（进程内 service），供「群昵称候选」与按 QQ 对账用。
  扫成功的名单留一份缓存落盘 `data/roster.json`，给 @ 人兜底。**身份昵称为空时不回写昵称**：群名单里没有这个人
  时链接身份里的 `n` 空着（`editor/roster.js` 的 `nickOf` 也给空串），按 QQ 同步昵称必须整个跳过——空名片是
  "这次没拿到名片"，不是本人清空了名片，拿它回写会把成员填好的群昵称清成空（`modules/queue.js` 的 `locateSelf`
  因此只在名片非空时返回 `renamedFrom`）。
- 解析/建模/签名与 `modules/`、`components/` 下的纯函数（不 import Yunzai、不碰文件系统）可以脱离机器人做回归。
- `apps/` 下的类由 `index.js` 聚合导出为 `module.apps`——框架 loader 的取法：插件根一旦存在 `index.js`，loader 就只导入它、不扫 `apps/`。

## 三、配置键归属（接锅巴 / 写模板前先读这节）

这是一个 bot 进程：插件（`index.js` → `apps/`）与编辑器（`editor/editor.mjs`）同进程——编辑器由
`modules/editor-host.js` 在加载期挂到 bot 自己的 HTTP server 上（前缀 `/queue`）。两层都读配置，但**配置面不能混**：

| 归属 | 键 | 默认值来源 | 谁消费 |
|------|----|-----------|--------|
| **插件** | `editor.public_url` / `token` / `sign_key` / `admin_token` | `components/config.js` 的 `DEFAULT_CONFIG` | 插件（`public_url` 只拼链接）+ 宿主注入编辑器 |
| **插件** | `notify.*`（`enable` / `groups` / `cron` / `monthly_at` / `monthly_enable`） | 同上 | 插件 |
| **插件** | `roster.group` / `roster.at` | 同上 | 插件 |
| **插件** | `default_sheet` / `list_limit` / `render_image` / `render_scale` / `render_max` / `anchor_aliases` / `snapshot_backup.enable` | 同上 | 插件 |
| **编辑器** | `footer.html` | `editor/config.js` 的 `DEFAULTS.footerHtml`（插件配置里有值就用它；自由 HTML，编辑器在后面追加规范署名行） | **编辑器** |
| **编辑器**（启动参数，**不进配置文件**） | `port` / `bind` / `mount` / `rosterQq` / `versionsKeep` / `archiveDays` / `archivesKeep` | `editor/config.js` 的 `DEFAULTS` | 编辑器 |

**四条规矩**：

1. **只有一个键跨层**：`footer.html` —— 写在插件配置文件里（维护者只维护一份 `config.yaml`），由编辑器读；
   其余键都只归一边。
2. **编辑器没有自己的启动参数**：它挂在 **bot 自己的 HTTP server** 上，状态文档固定 `<插件根>/data/queue.json`
   （同目录 `queue.xlsx` 是导出镜像），所以 `port` / `bind` / `mount` / `--file` 这些**在正式部署里不存在**——
   只剩"独立调试模式"（`node editor/editor.mjs …`）下有意义，因此不进 `config.yaml`、也不上锅巴。
3. **密钥与配置是一份，由宿主注入**：`editor.token` / `sign_key` / `admin_token` 既是插件配置项又是编辑器凭证——
   方向是**插件把配置注入编辑器**：`config/config.yaml ──(bot 读)──> modules/editor-host.js ──(注入)──> 编辑器`。
   注入优先、argv / 环境变量兜底。编辑器不再读命令行、也不读 `editor-path.txt`：同一件事只有一个来源。
4. **配置里没有路径键**（见 §四）：数据落点是常量，不是配置项。

### 3.1 三段式配置（锅巴怎么落盘）

```
defSet/config.yaml          ← 模板：值写成 ${变量}，注释完整
        │  锅巴保存时：读它 → 替换 ${变量} → 写下面那份
        ▼
config/config.yaml          ← 运行时（git-ignored；不存在时从 .example 复制）
config/config.yaml.example  ← 参考默认值（入 git，给人照着改；不参与运行时）
```

三份**结构必须一致，而且是同一份模板的产物**：`config.yaml.example` 与 `config.yaml` 都由
「`defSet/config.yaml` 模板 + `DEFAULT_CONFIG` 走一遍 `renderDefSet()`」生成——**改了模板就重新生成参考文件，别手改**。
`test/guoba.test.mjs` 的骨架闸逐行比「注释 + 键」，并对"面板字段 ↔ `CONFIG_FIELDS`"做漂移守卫。

- **变量名规则**：配置路径把点换成下划线（`editor.public_url` → `${editor_public_url}`），由 `fieldToVar()` 实现，**不手写映射表**。
- **值的序列化**：字符串一律 `JSON.stringify`；数组与对象写成**单行 YAML**（多行块会被锅巴归一成一行，三份骨架就对不上）。
- **注释保留**：靠"渲染模板"而不是 `YAML.stringify` 整写。
- **跨层键**：`footer.html` 默认值两边各一份且必须逐字相同（`CROSS_LAYER_FIELDS` 登记）；编辑器读它之后自己追加
  规范署名行 `Created By {框架名} {宿主版本} & {插件名} {插件版本}`（框架名按 bot 根 `package.json` 的 `name` 判），
  所以配置里那份只管版权 / 备案，**不写版本号**。

### 3.1.1 面板的读与写：读文件、读写同源、写完热重载

- **读文件，不读内存**：`getConfigData()` 走 `readCurrentConfigWithStatus()`。运行期的 `config` 是模块加载那一刻的快照
  ——启动补齐写进去的口令、维护者手改、面板上次保存，它都看不见。面板必须读文件，否则会把"看不见的值（空串）"
  在下次保存时写回，抹掉刚生成的密钥。`renderDefSet()` 的"没提交的键"也按文件当前值兜底。
- **读写同源**：两边都用 `resolveConfigPath()`（`ABYSS_QUEUE_CONFIG` 优先，否则 `config/config.yaml`）。
- **写完同步内存**：`setConfigData()` 落盘后调 `reloadConfig()`——`config` 是多个模块共用的**同一个对象**，就地改写即全局生效。

**热重载**：`index.js` 加载期挂 `watchConfig()`，文件一变就 `reloadConfig()` 并打一行「配置已热重载」。
**用 `fs.watchFile` 轮询，不用 OS watcher**（chokidar / `fs.watch` 在这台机器上会崩在原生层：盯文件时文件被删抛
未捕获的 `EPERM: watch`，盯目录时退出撞 libuv 断言；轮询最多晚一个间隔生效，但"文件被删 / 原子替换 / 外部覆盖"都不崩）。
**哪些键改了要重启**（`RESTART_ONLY_FIELDS`）：① `notify.cron`——cron 是插件实例化时交给框架的；
② `editor.token` / `sign_key` / `admin_token` / `footer.html`——编辑器在插件加载时把它们取走。提醒**只提这次真改了的**键。

**读不出来 / 写得回去**（事故换来的）：`config.yaml` 语法坏掉时 `readUserConfig()` 只能返回空，照写就是拿全空模板
把配置整份覆盖掉，面板还报"保存成功"。现在读路径返回带状态的结果，三处按它走：

1. **`getConfigData()` 不抛错**：抛错会让锅巴前端只剩一个"确认"弹窗、**面板彻底打不开**——而面板正是主人唯一能改回来的地方。
   它照常返回参考默认值并给一个 `_panel_warning` 告警横幅（`component` 只能是锅巴注册过的名字，且必须排在某个
   `SOFT_GROUP_BEGIN` 之后；两条都由 `test/guoba.test.mjs` 钉住）。
2. **错误文案不带配置文件内容**：`yaml` 库会把出错那行原文塞进异常消息，而那行常常就是 `token:` / `sign_key:`。
   `explainParseError()` 只留"哪份文件 + 解析器给的原因（到第一个换行为止）"。
3. **`setConfigData()` 写盘前先验**：渲染出的文本先 `YAML.parse`，再逐个比对"提交的值"与"解析回来的值"；对不上就
   `Result.error` 且**一个字节都不写**。坏配置仍允许被保存覆盖（面板是唯一救回它的路），但其余键按参考默认值重写，回执里点明。

`ensureConfig()` 同理：只在"文件根本不存在"时复制参考文件，不拿参考文件盖掉空白 / 坏掉的 `config.yaml`。

### 3.2 锅巴面板管哪些键

面板字段 = `CONFIG_FIELDS`（`components/config.js`）里那 24 个**插件键**，按四个大 label 分组（`guoba/connection.js` /
`display.js` / `footer.js` / `advanced.js`，`guoba/index.js` 只做拼装）。插件信息与图标在 `guoba/index.js` 的 `pluginInfo`。

**凭证由启动补齐生成（缺才生成一次），面板只显示 / 手改**：`editor.token` / `editor.sign_key` 的"生成"来源只有一个
——`index.js` 在 `ensureConfig()` 之后调的 `components/bootstrap.js`。面板**不替主人生成**（它不知道编辑器正拿着哪个口令，
换一个就把编辑器踢出局）。因此**"还没配置"（凭证都是空串）是正常状态**，只有"文件读不出来"才挂告警横幅。

**加一个新配置键要动的地方**（顺序即依赖）：① `DEFAULT_CONFIG` 加默认值（跨层键也要加）；② `CONFIG_FIELDS` 加一行
（点分路径）；③ `defSet/config.yaml` 加占位符（**只改模板**），再重新生成两份 `config.yaml*`；④ 需要上面板时在
`guoba/*.js` 加字段并**在 `PANEL_FIELDS` 加同一路径**（忘了这步面板上是空的；已被 `test/guoba.test.mjs` 钉住）。

## 四、数据落点：不许离开插件目录

插件侧的写盘位置**都是常量**，配置里没有路径键：绑定 → `data/bindings.json`、进度快照 → `data/progress.json`、
编辑器白名单 → `data/abyss-editor-admins.json`、私聊链接状态 → `data/manager-link.json`、群成员名单缓存 →
`data/roster.json`、直播状态缓存 → `data/anchor-live.json`、开播订阅 → `data/live-alerts.json`、重启标记 →
`data/restart.flag`、周期账本 → `data/cycle-ledger.json`。这样"数据只能待在 `<插件根>/data`"不是靠校验挡回来的，
而是**根本没有能填的地方**（`components/config.js` 的 `atData()` 直接拼死）。字体**不在这里**——随源码入库
（`resources/common/font/`），不写盘、不下载。

编辑器那侧更硬：表解析到插件外直接**拒绝启动**（见 `editor/README.md`）。

只有回归套件能把数据放进系统临时目录，走**环境变量**而不是配置项：`ABYSS_QUEUE_TEST_PATHS=1` /
`ABYSS_EDITOR_TEST_PATHS=1` 打开开关，再用 `ABYSS_QUEUE_*` / `ABYSS_EDITOR_*` 指定落点（完整表见 `test/README.md`）；
生产不设任何这类变量，`confineDataPath` 会挡住出圈的值并记 error。

## 五、实现口径（改这里之前先读）

- **插件不写表**：写操作全在编辑器；绑定只记在 `data/bindings.json`。
- **三个密钥互不相同**：`token`（口令）／`sign_key`（身份签名）／`admin_token`（管理备用入口）。缺了由启动补齐生成。
- **出图与文案同一条消息**：渲染时传 `cfg.retType = "base64"`，再自己 `reply([图, "\n", 文案])`；框架的 `e.reply`
  把发送失败吞成返回值 `{ error }`，兜底判断必须看返回值。
- **唯一一条定时任务**（`notify.cron` → `tick()`）：五件事（进度轮询 / 开榜提醒 / 月末催办 / 名单同步 / **每日整理**）
  在 `modules/notify.js` 的纯函数里算好，先一次落盘再发消息；「状态翻转才提醒」的首轮只记基线。**名单同步与每日整理
  都不发给群**，所以排在"没配群就返回"那道闸**之前**，共用 `roster.at`，当天标记在**做成之后**才写。每日整理的排序
  口径与幂等见 `editor/README.md`——**同一份整理还有第二个触发点**：改「帮帮完成情况」时编辑器在保存收尾里对那一榜
  当场做一遍（`afterSaveFollowUp`），每天那一趟退居**兜底**。**管理员的私聊链接不在这一条里**：只在本人发 `#排队` 时
  给一次，tick 不主动重发。
- **`#排队` 的投递方式按身份分**（`apps/queue.js` 的 `dmTarget` / `afterSend`）：发送者是主人或白名单管理员 ⇒ 整条回复
  **私聊**发、群里一个字都不发，链接是带当期时间窗的长地址；普通群友照旧群内发短码。私聊失败只在群里报一句原因，
  **绝不把管理链接退回群里**。
- **「上一位完成 → 下一位」只写群昵称文字，不 @ 人**（`modules/notify/send.js`）：第二行固定 `下一位：乙 请准备`，
  不查绑定、不查群名单；第三行「主播：@…」按主播名映射 @ 主播。
- **群昵称候选只有一条出口**（`editor/editor.html` 的 `nickList` / `nickSuggest` / `paintNickPicker`）：空着给名单最前
  `NICK_BROWSE_LIMIT = 8` 个，打字给「一字不差（置顶）→ 前缀 → 包含 → 编辑距离 ≤ 2」，取前 6，点一下填入（走草稿 +
  自动保存同一条路）；浮层 15 秒无操作自动收起。名单按需重取（`refreshNickList()`，60 秒节流），群里改了名片也能选到。
- **「帮帮完成情况」存的是人，昵称改了要跟着改**（`editor/status.js` 的 `statusRenamePlan`）：三条改名路径（本人保存 /
  管理员改行 / 群名单同步）都过它，逐段精确换（不子串替换，不碰主播名与状态词）；榜里两行同名或这一行没有可依据的
  绑定 → 宁可不动并说明。
- **「帮帮完成情况」的下拉候选只认三种来源**（`editor/cycle-ledger.js` 的 `mergeStatusOptions`）：状态词
  （`等待开启` / `排队中` / `本人已完成`）、主播区、手动「＋ 收录新名字」。**表里在用的名字不再当候选**——否则每个点过
  完成的人都变成全体候选，改名 / 退群 / 广告名片留下的名字还会永远残留在下拉里。当前值由页面并进候选，服务端放行
  "这一格里本来就有的值"，保存 / 归档时把净化后的名单写回表里（自愈）。
- **xlsx 一切靠内容识别**：表头行、列映射、数据区末日行、主播区都从内容推断，不写死行号列号。
- **列对齐契约**：文本列左、状态/数字列居中、表头跟着内容走（`test/layout.test.mjs` 钉住）。

## 六、更新冲突的由来（行尾策略）

`.gitattributes` 固定 `* text=auto eol=lf`。Windows 上 git 默认 `core.autocrlf=true`，会把工作区文件签出为 CRLF，
代码却是 LF——两者不一致时 git 把「行尾不同」判成本地改动，于是 `#更新` 的快进被拒绝。固定 `eol=lf` 后不再因此变脏。
若克隆时已经按 CRLF 签出过，执行一次 `git add --renormalize .`；同时把两个仓库的 `core.autocrlf` 都设为 `false`。

`.gitignore` 覆盖：`config/config.yaml`、`data/`、`node_modules/`、`pnpm-lock.yaml`、`.DS_Store`、`Thumbs.db`、
`.vscode/`、`.idea/`、`.claude/`、`CLAUDE.md`、`.dsh/`、`test/.test-tmp/`，以及兜底的 `*.bak`、`*.tmp`、`*.log`。

## 七、部署一致性自查

两个目录是同一仓库的两份**独立克隆**（不是同一目录，也不做成软链接——框架要求插件真实位于 `<bot根>/plugins/` 下）：

- **源码仓库**：改代码、跑测试、提交、推送
- **部署目录** `<bot根>/plugins/abyss-queue`：只由更新指令拉取（框架的 `#更新 abyss-queue`——**写目录名，缩写 `abyss` 不生效**），**不接受任何手工拷贝**

排查"`#更新` 报本地冲突"时跑 `node test/check-deploy.mjs ["<部署目录>"]`：输出两边 HEAD、工作区改动、未跟踪文件、
两棵树的内容差异（按行尾归一）与 `core.autocrlf` 状态，发现问题时列出文件并给出处理命令、退出码非 0。

## 九、其它开发备忘

- 宿主根口径：JS 用 `components/config.js` 的 `pluginRoot` 推导，**不要用 `process.cwd()`**。
- 字体口径：正文与标题统一用 `HYWH-65W`（汉仪文黑，原神标准字体），**随源码入库**在 `resources/common/font/`
  （各带 `.woff` 与 `.ttf` 两份）。渲染模板以 `file://` 引用它，**不下载、不缓存、没有配置项**。
  另有装饰字 `NZBZ`（印品南征北战NZBZ体，取自 miao-plugin，同样入库）：字形带倾斜感，**只给页头这类大字**——
  `components/font.js` 的 `FONTS.display` → `fontUrls().fontDisplay` → 模板里的 `GenshinDisplay`，当前只用在
  单榜图与帮助图的 `.title`（36px、字距 1.5px；同尺寸下它比 HYWH 显小，所以比原字号放大两号）。
  正文、表格、小标签一律不用：14px 左右会发细像斜体，20px 的本人卡标题试过也挤。
