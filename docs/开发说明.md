边界口径：本仓库**不设 `lib/`**（`lib/` 是框架级通用库位，插件自身不新建，见 `AGENTS.md` §3.1）。**能被第二个入口（云端编辑器）直接 import** 的纯逻辑按归属落在 `model/`、`modules/`、`components/` 里；吃 bot 全局（`Bot` / `segment` / `logger`）或会读文件的同样按归属放 `components/`、`model/`。带 ★ 的文件加 `model/table.js`、`model/store.js` 是编辑器 `shared()` 实际加载的共用面，改它们要一起跑编辑器套件。

`modules/` 的边界：**"先…再…"的流程编排**放这里（可以 import model / components，也可以有副作用）；**判断与状态**留在 `modules/` 的纯函数里，**发送与取数**这类可复用动作留在 `components/`/`model/`。定时通知就是这个口径的三层分工：`modules/notify.js`（该不该发）→ `modules/notify/send.js`（发什么、发到哪）→ `components/notify-send.js`（怎么发）。

编辑器就在本仓库的 `editor/` 里，它按绝对路径复用本插件的 `model/`、`modules/`、`components/`
（表格读写只有一份实现，避免两套逻辑漂移）。入口薄、按职责分模块：

```
editor/
├── editor.mjs       入口：装配 → 表/绑定实例 → HTTP 路由与业务（归属 / 校验 / 保存 / 归档）
├── config.js        启动配置：所有路径与开关的唯一口径 + fail-closed 拒绝启动
├── cli.js           argv 解析原语（flag / boolFlag）与日志重定向
├── plugin-root.js   插件根定位 + shared()（从插件目录加载共用模块）
├── util.js          JSON 读写与日期小工具（多模块共用）
├── acl.js           白名单（只认 QQ）+ 完成情况锁（连昵称与表指纹一起记）
├── ownership.js     归属状态：绑定/锁与表的对账、审计、按 QQ 重建
├── roster.js        群成员名单：昵称候选 + 按 QQ 取当前名片
├── versions.js      历史版本与归档：命名口径（含下载校验正则）、滚动保留、每日/换月归档
├── audit.js         写操作的请求级审计：一行一条（qq / action / status + 路由补的细节），出口由宿主注入
├── http/respond.js  HTTP 基本动作：回 JSON、读请求体、取口令、FEATURES
├── http/auth.js     鉴权：口令、身份签名、主人与白名单（createAuth）
├── http/pages.js    三个提示页 + 页脚（createPages）
├── editor.html      前端（单文件、无构建；内联脚本与样式）
└── test/            本目录的回归套件（23 个，黑盒：spawn 编辑器 + 打 HTTP）
```

编辑器的模块同样是「只依赖注入进来的 `deps`、不读全局」：`acl.js` 的群昵称回查由调用方给，
`roster.js` 的绑定库也是注入的，`http/auth.js` 的名单读取与签名校验、`http/pages.js` 的页脚 HTML
同样由调用方注入——这样它们能脱离 HTTP 单独调用。

## 二、实现要点

- `model/xlsx.js`：极简 xlsx 容器。不整表解析重排，而是**外科手术式替换目标 `<c>` 节点**，写入用 `inlineStr` 从而完全不动 `sharedStrings.xml`；未改动的工作表逐字节保持原样。**读入口带解压预算**：整份表所有被读到的部件合计解出的字节 ≤ 256 MB、条目 ≤ 2048，边解边数（不信 zip 头里声明的大小），超了立刻中断解压、抛错拒收，而不是先把内容解进内存——上传 / 回退 / 云端拉取都从 `openWorkbook()` 这一条路进。
- `model/table.js`：每次操作都重新读盘（可能刚被其它工具改过），写入走「读-改-校验-原子替换」；替换前会用新缓冲重新解析并核对写入结果，核对不过就放弃写入；所有写操作进程内串行，多人同时保存不会互相覆盖。
- `components/config.js`：首次启动自动从 `config.yaml.example` 生成运行时配置；缺 `remote.url` 时回复明确提示而不是静默失败。
- `model/roster.js`：取群成员（群名片优先）并推给云端编辑器，供「群昵称候选」与按 QQ 对账用。
  **身份昵称为空时不回写昵称**：云端群名单里没有这个人时，短链展开补不出名片（`editor/roster.js` 的 `nickOf` 给空串），
  按 QQ 同步昵称这一步必须整个跳过——空名片是"这次没拿到名片"，不是本人把名片清空了，
  拿它回写会把成员填好的群昵称清成空（`modules/queue.js` 的 `locateSelf` 因此**只在名片非空时**返回 `renamedFrom`）。
- `model/` 的解析/建模/签名与 `modules/`、`components/` 下对应的纯函数（不 import Yunzai、不碰文件系统）可以脱离机器人做回归测试。
- `apps/` 下的类由 `index.js` 聚合导出为 `module.apps`——这是框架 loader 的取法：插件根一旦存在 `index.js`，loader 就只导入它、不扫 `apps/`（`lib/plugins/loader.js:58-62`、`:130`）。

## 三、配置键归属（接锅巴 / 写模板前先读这节）

这个仓库有**两个进程**：bot 里的插件（`index.js` → `apps/`）与独立的编辑器进程（`editor/editor.mjs`）。
两层都读配置，但**配置面不能混**——混了就会出现"某个键写在这里、其实只有另一边认"的情况。
归属如下：

| 归属 | 键 | 默认值来源 | 谁消费 |
|------|----|-----------|--------|
| **插件** | `remote.url` / `token` / `sign_key` / `short_link` / `link_markdown` / `ttl_ms` / `timeout_ms` / `autostart` | `components/config.js` 的 `DEFAULT_CONFIG` | 插件 |
| **插件** | `notify.*`（`enable` / `groups` / `cron` / `monthly_at` / `monthly_enable`） | 同上 | 插件 |
| **插件** | `roster.group` / `roster.at` | 同上 | 插件 |
| **插件** | `default_sheet` / `list_limit` / `render_image` / `render_scale` / `render_max` / `anchor_aliases` / `snapshot_backup.enable` | 同上 | 插件 |
| **编辑器** | `footer.html` | `editor/config.js` 的 `DEFAULTS.footerHtml`（插件配置里有值就用它；这段只是**自由 HTML**，编辑器会在它后面追加规范署名行） | **编辑器** |
| **编辑器**（启动参数，**不进配置文件**） | `port` / `bind` / `mount` / `rosterQq` / `versionsKeep` / `archiveDays` / `archivesKeep` | `editor/config.js` 的 `DEFAULTS` | 编辑器 |

**四条规矩**：

1. **只有一个键跨层**：`footer.html` —— 写在插件配置文件里（这样维护者只维护一份 `config.yaml`），
   由编辑器读。其余键都只归一边。
2. **编辑器没有自己的启动参数了**：编辑器由 `modules/editor-host.js` 挂在 **bot 自己的 HTTP server** 上
   （前缀 `/queue`），表固定 `<插件根>/data/queue.xlsx`，所以 `port` / `bind` / `mount` / `--file`
   这些**在正式部署里根本不存在**——它们只剩"独立调试模式"（`node editor/editor.mjs …`）下有意义，
   因此**不进 `config.yaml`、也不上锅巴**。

   保留策略三键（`versionsKeep` / `archiveDays` / `archivesKeep`）现在只从 **`ABYSS_EDITOR_*` 环境变量 →
   `DEFAULTS`** 取。它们**可以**进配置（同进程，宿主拿得到），但那与"编辑器随框架启停"是两件事：
   **同进程不等于改完立即生效**——编辑器是在**插件加载时**把配置取走的（凭证由宿主注入、页脚与开关进 `cfg`），
   改了要重启机器人。所以"能不能进配置"的门槛不是"能不能热改"，而是"重启一次能不能接受"。

3. **密钥与配置是一份，由宿主注入**：`remote.token` / `sign_key` / `admin_token` 既是插件的配置项、
   又是编辑器用的凭证——同一份，方向是**插件把配置注入编辑器**：

   ```
   config/config.yaml ──(bot 读)──> modules/editor-host.js ──(注入 --token/--sign-key/--admin-token)──> 编辑器（同进程）
   ```

   注入优先、argv / 环境变量兜底（`editor/injected.js`）。所以**编辑器不再读命令行、也不再读
   `editor-path.txt`**：同一件事只有一个来源，这类"两边对不上"的事故从结构上消失。

4. **配置里没有路径键**（见下节）：数据落点是常量，不是配置项。

> **未决**：`versionsKeep` / `archiveDays` / `archivesKeep` 是**保留策略**（不是网络拓扑），
> 进配置完全合理（同进程、宿主拿得到；代价是改了要重启机器人，与凭证 / `footer.html` 一并进
> `RESTART_ONLY_FIELDS`）——只是与"编辑器随框架启停"不是一件事，单独做。

### 3.1 三段式配置（锅巴怎么落盘）

```
defSet/config.yaml          ← 模板：值写成 ${变量}，注释完整
        │  锅巴保存时：读它 → 替换 ${变量} → 写下面那份
        ▼
config/config.yaml          ← 运行时（git-ignored；不存在时从 .example 复制）
config/config.yaml.example  ← 参考默认值（入 git，给人照着改；不参与运行时）
```

三份**结构必须一致，而且是同一份模板的产物**：`config/config.yaml.example` 与 `config/config.yaml`
都由「`defSet/config.yaml` 模板 + `DEFAULT_CONFIG` 走一遍 `renderDefSet()`」生成——**改了模板就重新生成参考文件，别手改它**。
`test/guoba.test.mjs` 的骨架闸逐行比「注释 + 键」（行内对齐空格与示例值带不带引号不算差异），
并对"面板字段 ↔ `CONFIG_FIELDS`"做漂移守卫（漏一个键、拼错一个变量都会红）。
推论：**模板里每个占位符都必须有默认值来源**（含跨层键 `footer.html`——它的默认值与
`editor/config.js` 的 `DEFAULTS.footerHtml` 逐字相同）。

- **变量名规则**：配置路径把点换成下划线（`remote.url` → `${remote_url}`），
  由 `components/config.js` 的 `fieldToVar()` 实现——**不手写映射表**，否则会跟 schema 漂移。
- **值的序列化**：字符串一律 `JSON.stringify`（含 `#` / `:` / 引号 / 换行的值也不会写坏 YAML），
  数组与对象写成**单行 YAML**（`{名: ["别名"]}` / `[1, 2]`）——多行块写法会被锅巴保存归一成一行，
  三份文件的行数与骨架就对不上了。实现是 `yamlValue()`。
- **注释保留**：靠"渲染模板"而不是 `YAML.stringify` 整写；模板里那些解释性注释就是用户在
  `config/config.yaml` 里看到的那份。
- **跨层键**：`footer.html` 写在本配置文件里但由编辑器读，默认值**两边各有一份且必须逐字相同**
  （`components/config.js` 的 `DEFAULT_CONFIG.footer.html` 与 `editor/config.js` 的 `DEFAULTS.footerHtml`）：
  插件侧要它来把三份配置填成同一份，编辑器并排部署时读不到插件配置就用自己的。
  这个"哪个键跨层"的登记在 `CROSS_LAYER_FIELDS`。
  编辑器读它之后会**自己追加**规范署名行 `Created By Yunzai-Bot {宿主版本} & {插件名} {插件版本}`
  （§3.5；版本与插件名按编辑器定位到的插件根推导，见 `editor/plugin-root.js` 的 `attributionLine`），
  所以配置里那份只管版权 / 备案这类自由排版，**不写版本号**。

### 3.1.1 面板的读与写：读文件、读写同源、写完热重载

这三条是"面板读不到 / 保存像没生效"那类事故的三道闸，改 `guoba/index.js` 或
`components/config.js` 的读写入口前先读：

- **读文件，不读内存**：`getConfigData()` 走 `readCurrentConfigWithStatus()`。
  运行期的 `config` 是**模块加载那一刻的快照**——`#排队初始化` 写进去的口令与签名密钥、
  维护者手工编辑、面板上一次保存，它都看不见。面板必须读文件，否则就会把"看不见的值（空串）"
  在下次保存时写回文件，把刚生成的密钥抹掉。`renderDefSet()` 的"没提交的键"也按文件当前值兜底。
- **读写同源**：两边都用 `components/config.js` 的 `resolveConfigPath()`（`ABYSS_QUEUE_CONFIG`
  优先，否则 `config/config.yaml`）。一处硬编码、一处解析，套件里就会出现"面板把值写进仓库配置、
  插件却从临时配置读"。
- **写完同步内存**：`setConfigData()` 落盘后调 `reloadConfig()`——`config` 是 15 个模块共用的
  **同一个对象**，就地改写它即全局生效（因此面板保存与手工改文件都不用重启机器人）。

**热重载**：`index.js` 加载期挂 `watchConfig()`，文件一变就 `reloadConfig()` 并打一行
「配置已热重载」。**用 `fs.watchFile` 轮询，不用 OS watcher**（chokidar / `fs.watch` 在这台机器上
会崩在原生层：盯文件时文件被删会抛未捕获的 `EPERM: watch`，盯目录时退出会撞 libuv 断言；
轮询最多晚一个间隔生效，但"文件被删 / 被原子替换 / 被外部覆盖"都不崩、也不吊住离线套件）。
**哪些键改了要重启**（`RESTART_ONLY_FIELDS`，锅巴保存回执与热重载日志都按它提醒）：
① `notify.cron`——那条 cron 是插件实例化时交给框架的（`apps/queue.js` 的 `task[].cron`），运行期改不了；
② `remote.token` / `remote.sign_key` / `remote.admin_token` / `footer.html`——**编辑器在插件加载时把它们取走**
（宿主 `modules/editor-host.js` 注入凭证、`editor/config.js` 读页脚），插件侧热重载了、编辑器侧没有，
不重启就是"插件用新口令、编辑器还认旧口令"（填表链接直接 403）。提醒**只提这次真的改了的**键——
面板提交的是整张表单，按"在不在表单里"判会把每次保存都标成要重启。

**读不出来 / 写得回去**（这条是事故换来的）：`config.yaml` 语法坏掉时，`readUserConfig()` 只能返回空，
于是 `renderDefSet()` 对"表单没提交的键"的兜底全变成默认值——照写就是拿一份全空的模板把主人的配置
**整份覆盖掉**，而面板还会报"保存成功"。现在读路径返回**带状态**的结果
（`readCurrentConfigWithStatus()` 的 `error`），三处都按它走：

1. **`getConfigData()` 不抛错**：抛错会让锅巴前端只剩一个"确认"弹窗，**面板彻底打不开**——
   而面板正是主人唯一能把坏配置改回来的地方。它照常返回参考默认值，并额外给一个
   `_panel_warning` 告警横幅，写明读不了哪份文件、显示的是参考默认值。**这个横幅受两条锅巴约束**：
   `component` 只能是锅巴**注册过**的名字（它没有纯展示组件，写错只会渲染成一句"未知的组件"，
   现在的实现是只读的 `InputTextArea`），且这一项**必须排在某个 `SOFT_GROUP_BEGIN` 之后**
   （锅巴前端先造一个"默认"页签，把第一个分组之前的字段全塞进去）。两条都由 `test/guoba.test.mjs` 钉住。
2. **错误文案不带配置文件内容**：`yaml` 库会把出错那行的原文塞进异常消息，而那行常常就是
   `token:` / `sign_key:`——原文进了日志或面板弹窗，等于把口令打出来。`explainParseError()`
   只留"哪份文件 + 解析器给的原因（到第一个换行为止）"。
3. **`setConfigData()` 写盘前先验**：渲染出的文本先 `YAML.parse` 一遍，再逐个比对"提交的值"与
   "解析回来的值"；解析不了、或对不上，就 `Result.error` 且**一个字节都不写**。这一条守的是"写坏"
   （例如值里混进引号，渲染出 `token: """` 这种下次读不出来的样子）。
   **坏配置仍然允许被保存覆盖**——面板是唯一能救回它的路——但要按参考默认值重写其余键，
   所以回执里点明"其余键已按参考默认值重写"。

`ensureConfig()` 同理：只在"文件根本不存在"时复制参考文件，不拿参考文件盖掉空白/坏掉的 `config.yaml`。

### 3.2 锅巴面板管哪些键

面板字段 = `CONFIG_FIELDS`（`components/config.js`）里那 24 个**插件键**，按四个大 label 分组
（`guoba/connection.js` / `display.js` / `footer.js` / `advanced.js`，`guoba/index.js` 只做拼装）。
**编辑器没有自己的启动参数**（表固定、端口用 bot 的，理由见第 2 条规矩）；插件信息与图标在 `guoba/index.js` 的
`pluginInfo`（图标走 `iconPath` 绝对路径，锅巴用 `res.sendFile` 直接吐图，前端 URL 是
`/api/plugin/s/abyss-queue/icon`）。

**凭证由 `#排队初始化` 生成，面板只显示 / 手改**：`remote.token` / `remote.sign_key` / `remote.admin_token`
的"生成"来源只有一个——`#排队初始化`。面板**不替
主人生成**：面板不知道编辑器正拿着哪个口令，换一个就把编辑器踢出局；这三个键由
`modules/editor-host.js` 注入编辑器。因此**"还没配置"（凭证键都是空串）是正常状态**：
面板照常打开、照常保存，只有"文件读不出来"才挂告警横幅（见 §3.1.1）；这两条路的界线由 `test/guoba.test.mjs` 钉住。

**加一个新配置键要动的地方**（顺序即依赖）：
1. `components/config.js` 的 `DEFAULT_CONFIG` 加默认值（跨层键也要加——模板里每个占位符都要有来源）；
2. `CONFIG_FIELDS` 加一行（用点分路径）；
3. `defSet/config.yaml` 加一行占位符（**只改模板**），再用「模板 + 默认值」重新生成
   `config/config.yaml.example` 与 `config/config.yaml`；
4. 需要上面板时在 `guoba/*.js` 加字段，**并在 `guoba/index.js` 的 `PANEL_FIELDS` 加同一路径**——
   忘了这步 `getConfigData` 就不会返回它、面板上是空的（这条已被 `test/guoba.test.mjs` 钉住）。

## 四、数据落点：不许离开插件目录

插件侧的写盘位置**都是常量**，配置里没有路径键：绑定 → `data/bindings.json`、进度快照 →
`data/progress.json`、快照备份 → `data/backup`、重启标记 → `data/restart.flag`。这样"数据只能待在
`<插件根>/data`"不是靠校验挡回来的，而是**根本没有能填的地方**：`components/config.js` 直接
拼出前三个路径（`atData()`），重启标记在 `components/boot.js` 里同样拼死，都不是从配置读一个再判断要不要回落。
字体**不在这里**——它随源码入库（`resources/common/font/`），不写盘、不下载。

编辑器那侧更硬：表（`--file` / `ABYSS_EDITOR_FILE`）解析到插件外直接**拒绝启动**
（见 `editor/README.md`）。

只有回归套件能把数据放进系统临时目录，走**环境变量**而不是配置项：
`ABYSS_QUEUE_TEST_PATHS=1` / `ABYSS_EDITOR_TEST_PATHS=1` 打开开关，再用
`ABYSS_QUEUE_STORE_FILE` / `_STATE_FILE` / `_BACKUP_DIR` / `_RESTART_FLAG` / `_XLSX_PATH`（插件侧）与
`ABYSS_EDITOR_ADMINS_FILE` / `_LOCKS_FILE` / `_ROSTER_FILE` / `_VERSIONS_DIR`（编辑器侧）指定落点；
生产不设任何这类变量，`confineDataPath` 会挡住出圈的值并记 error。
`_RESTART_FLAG` 是**最后补上的**这一处：重启标记由 `components/boot.js` 的退出钩子在子进程退出时写，
而 `boot()` 由 `index.js` 装配——凡是 import 了入口的套件都会碰到它；兜底值在 `test/_helper.mjs`
里设（不 import `test/env.mjs` 的套件也覆盖得到），`env.mjs` 再改指本套件的临时目录。

回归测试可用环境变量 `ABYSS_QUEUE_CONFIG` 指定另一份配置，避免动到真实配置。

## 五、实现口径（改这里之前先读）

- **插件不写表**：写操作全在编辑器；绑定只记在 `data/bindings.json`。
- **三个密钥互不相同**：`token`（口令）／`sign_key`（身份签名）／`admin_token`（管理备用入口）。
- **出图与文案同一条消息**：渲染时传 `cfg.retType = "base64"`，再自己 `reply([图, "\n", 文案])`；框架的 `e.reply` 把发送失败吞成返回值 `{ error }`，兜底判断必须看返回值。
- **唯一一条定时任务**（`notify.cron` → `tick()`）：四件事都在 `modules/notify.js` 的纯函数里算好，先一次落盘再发消息；「状态翻转才提醒」的首轮只记基线。
- **xlsx 一切靠内容识别**：表头行、列映射、数据区末日行、主播区都从内容推断，不写死行号列号。
- **列对齐契约**：文本列左、状态/数字列居中、表头跟着内容走（`test/layout.test.mjs` 钉住）。

## 六、更新冲突的由来（行尾策略）

`.gitattributes` 固定 `* text=auto eol=lf`。Windows 上 git 默认 `core.autocrlf=true`，会把工作区文件签出为 CRLF，而代码与配置通常是 LF——两者不一致时 git 会把「行尾不同」判定为本地改动，于是 `#更新` 的快进被拒绝。固定 `eol=lf` 后，git 期望的工作区行尾与工具产出一致，部署目录不会再因此变脏。

> 若克隆时已经按 CRLF 签出过，执行一次 `git add --renormalize .` 即可让索引与工作区按新策略对齐。
>
> **同时要把两个仓库的 `core.autocrlf` 都设为 `false`**：`.gitattributes` 已经固定了 `eol=lf`，再叠加 `autocrlf=true` 会出现"写 LF、期望 CRLF"的对立，制造幻影本地改动。本机两个仓库均已设置；换机克隆后各执行一次：
>
> ```bash
> git -C "<源码仓库>" config core.autocrlf false
> git -C "<bot根>/plugins/abyss-queue" config core.autocrlf false
> git -C "<源码仓库>" add --renormalize .
> ```

`.gitignore` 覆盖的内容：`config/config.yaml`、`data/`、`node_modules/`、`pnpm-lock.yaml`、`.DS_Store`、`Thumbs.db`、`.vscode/`、`.idea/`、`.claude/`、`CLAUDE.md`、`.dsh/`、`test/.test-tmp/`，以及兜底的 `*.bak`、`*.tmp`、`*.log`（这三类正常都落在 `data/` 里）。`.dsh/` 下只放上游自带的 `AGENTS.md`——它已被根目录 `AGENTS.md` 取代，不入库。

## 七、部署一致性自查

两个目录是同一仓库的两份**独立克隆**（不是同一个目录，也不应做成软链接——框架要求插件真实位于 `<bot根>/plugins/` 下）：

- **源码仓库**：改代码、跑测试、提交、推送
- **部署目录** `<bot根>/plugins/abyss-queue`：只由更新指令拉取（`#排队更新`，或框架的 `#更新 abyss-queue`——**写目录名，缩写 `abyss` 不生效**），**不接受任何手工拷贝**

排查"`#更新` 报本地冲突"时跑：

```bash
node test/check-deploy.mjs                 # 默认查本机部署目录
node test/check-deploy.mjs "<部署目录>"     # 或指定路径
```

它会输出两边 HEAD、工作区改动、未跟踪文件、两棵树的内容差异（按行尾归一，避免假差异）与 `core.autocrlf` 状态；发现会挡住 `#更新` 的问题时列出具体文件并给出处理命令，退出码非 0。

## 九、其它开发备忘

- `test/locate-self.test.mjs` 里的宿主根口径：JS 用 `components/config.js` 的 `pluginRoot` 推导，**不要用 `process.cwd()`**。
