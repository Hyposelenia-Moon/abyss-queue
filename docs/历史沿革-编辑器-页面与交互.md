# 历史沿革 · 编辑器 · 页面与交互

**覆盖**：版式与移动端、页脚、页面标题、草稿与自动保存、实时刷新与行级冲突、历史版本与改动记录、群昵称候选浮层。

规则见 [`历史沿革.md`](历史沿革.md)：只追加、不改写历史行；本册只收编辑器这一子题的变更。

| 变更 | 说明 |
|------|------|
| 编辑器页脚改为配置提供 | 新增 `footer.html`（自由 HTML，原样插入页面），由 `GET /api/meta` 提供给首页，三个提示页共用；不拆字段、不转义（只由维护者维护，不接用户输入） |
| 编辑器标签页图标 | 新增 `GET /favicon.ico` 路由，**排在 `authorized()` 之前**——浏览器请求 favicon 时不会带 `?k=`（页面口令在 localStorage 里、不是 cookie），放在口令校验之后会让正式部署拿到 403、图标根本不显示。编辑器按自己算出的插件根读，**不需要新增启动参数**；favicon 用 256×256 那版（标签页 16/32/48、任务栏与 apple-touch-icon 可达 180，64 会插值发虚），锅巴面板仍用 64 那版；`editor.html` 用绝对路径 `/favicon.ico` 引用。`editor/test/editor.test.mjs` 补 5 条断言（其中"不带口令也能取到"是关键那条——**带上口令测就测不出这个坑**） |
| 编辑器页脚注入规范署名行 + `hasFont` 私有化 | **页脚（编辑器这第二个入口的署名）**：页脚内容仍由配置 `footer.html` 提供（自由 HTML，不拆字段、不校验、留空 = 整块不渲染），但 `editor/config.js` 现在会在它**后面自动追加**一行 `Created By Yunzai-Bot {yunzaiVersion} & {PluginName} {pluginVersion}`——§3.5 要求 HTML 输出统一带这行署名，而编辑器此前只有维护者自定内容。新增 `editor/plugin-root.js` 的 `attributionLine(pluginDir)`：插件版本读**编辑器自己定位到的插件根**下的 `package.json`，宿主版本按「插件根的上一级必须叫 `plugins/`」推导（与 `components/pluginVersion.js` 同一口径），插件名取插件 `components/constants.js` 的 `PLUGIN_NAME`（与 `versionFooter` 同源）；三者推导不到一律给「未知」，不抛错、不用 `process.cwd()`。编辑器可能按并排布局部署，这一路**没有静态 import 插件的 `components/`**（仍走 `makeShared` 动态加载）。**为什么这样切**：署名行是规范、不由配置提供，所以配置里那份自由 HTML 照旧可自由编辑，**版本号不进任何默认 footer 文本**（`DEFAULTS.footerHtml` / `defSet` / `config.yaml.example` 的默认值一字未动）。文档同步：`editor/README.md`、`docs/开发说明.md`、`guoba/footer.js`。**字体**：`components/font.js` 的 `hasFont` 改为**不导出**（§3.7：不为内部实现细节留接口）；`test/guoba.test.mjs` 第 6 组随之改成按**公开接口**断言，`fontUrl(key)` 文件在时给 `file://` 且文件真的存在、**缺失时给空串**（模板 `@font-face` 整条失效、回落系统字体，即 §3.1 的"可读降级"）。**是换测法不是放宽**：缺失那一支由"只改内存里的 `FONTS`、`finally` 还原、不动磁盘上的字体文件"走到；删掉/挪走一个入库字体文件，这两条断言都会红 |
| 挂载形态下页脚与图标两处修复 + 尾斜杠规范化 | 实机截图暴露两个只有"挂在 `/queue` 下"才会出现的 bug，都在 `editor/` 里修掉：① **页脚缺失**——`editor.html` 原来有独立的第三段脚本，自己 `new URLSearchParams(location.search)` 取 `k`；而主脚本开局就把 `?k=` 收进 localStorage 并用 `history.replaceState` 把地址栏清干净了，那次请求带的是**空口令** → `/api/meta` 回 403 → 脚本 `if (!res.ok) return` 静默返回，页脚**从来没画出来过**。现在页脚并进主脚本末尾、与其它请求共用同一个 `withToken("api/meta")`，第三段脚本删除（一处实现）。② **网页图标缺失**——`editor.html` 的 `<link rel="icon">` 原来写的是**站根绝对路径** `/favicon.ico`；编辑器只接管 `/queue` 与它下面的路径，所以浏览器请求站根那条会给框架 404。现在模板写 `__MOUNT__/favicon.ico`，首页路由按**这次请求实际带的前缀**替换（剥前缀的代理下是空串，渲染成 `/favicon.ico`）。③ **尾斜杠规范化**：`<前缀>` → 301 `<前缀>/`——首页里的请求全是相对路径（`api/*`、`font/*`），地址栏 `…/queue` 会让它们解析到站根、一起 404；这条顺带把 `font/cn.woff` 那类相对路径也钉稳。**回归**：`editor/test/editor.test.mjs` 补 5 条（挂载形态下图标指向 `/queue/favicon.ico`、`/queue/favicon.ico` 不带口令 200、`/queue` → 301、页脚必须走 `withToken` 且读地址栏的写法只许出现一次、无前缀形态仍照旧） |
| 页脚三处修正（字面 `\n` / 字体字号 / 链接下划线） | 实机页脚暴露三个问题：① **`\n` 被原样画出来**——模板注释教"多行内容由 `\n` 转义"，但在锅巴面板里打 `\n` 走不到那条路（面板值经 `yamlValue()` = `JSON.stringify`，反斜杠被再转义一层，YAML 解析回来仍是"反斜杠 + n"两个字符），实机配置里就是 `</div>\\n<div>`。现在 `editor/config.js` 的 `withFooterLine` **容忍字面 `\n` / `\r`**（当换行，老配置不用改就正常），并把口径改成"**多行就直接换行**；别手打 `\n`"（模板注释、参考文件、锅巴 `footer.js` 引导三处同步）。② **字号/字体与正文不一致**：`.site-footer` 原来 12px、且没写 `font-family`；现在 `font-family: inherit; font-size: 14px;`（正文 17px、次要文字 13~14px），颜色加深到 `#5c6b96`。③ **链接带下划线**：那是浏览器默认样式，现在 `.site-footer a { text-decoration: none }`，hover 用颜色变深表示可点。顺带把同一段里过期的口径改掉：模板里"改完要重启**编辑器进程**（本机由启动器拉起）"→"改完要重启机器人"，"重启标记…启动器据此判断重启还是停服"→"维护者自己的启动脚本可据此判断"。**回归**：`editor/test/editor.test.mjs` 补 2 条（夹具把字面 `\n` 写进页脚，断言 `/api/meta` 回的是真换行且不含字面 `\n`；页脚样式必须字号 ≥14px、字体 inherit、链接 `text-decoration: none`） |
| 页脚间距：挪进 main + 上边距收到 10px | 桌面端"最后一个组件 → 页脚"原来 ≈82px 空档：`.hintbar` 自己的下内边距 14px + `main` 的 40px 底衬 + 页脚 `margin-top` 28px。`main` 那 40px 是**页尾留白**，页脚原本是 `</main>` 的兄弟，于是它被夹在"最后一个组件"与页脚之间。现在页脚挪到 **main 里面**（最后一个组件之后）、`margin-top: 28px → 10px` → ≈24px，`main` 的底衬回到页脚**下方**（它本来就是这个用途）；页脚为空时 `:empty` 仍然整块隐藏，行为不变。`editor/test/editor.test.mjs` 的页脚组补一条：页脚必须出现在 `</main>` 之前、上边距 ≤ 12px（免得以后又飘走） |
| 「帮帮完成情况」下拉：当前值打不上勾 + 底行「＋ 收录新名字」被裁 | 维护者三张截图报的三条，**逐条在临时实例（空闲端口、只读维护者那份表）里复现过：两条是真缺陷、一条不成立**。① **真缺陷**：`paintPicker()` 的勾选用原样 `now.includes(v)`，而底色 `pillColor` 用的是 `pillNorm`（全角括号当半角、去空格）——候选表里写成「险恶（N4）」而表里是「险恶(N4)」时，胶囊上了色、下拉里却没有一项打勾；而且候选表与本格旧值只是拼接，**同一个值会列两项**（实测 `["险恶（N4）","险恶(N4)"]`）。现在候选按 `pillNorm` 去重、**以这一格里的写法为准**，勾选用同一套归一化。② **真缺陷（同症状的另一条路）**：`statusWithSelfDone` 落成的是这一行的群昵称，而"昵称已是候选就收起字面「本人已完成」"那条判据（`list.includes(rowNick)`）**不看当前值**——表是腾讯文档那边人工维护的，能直接选到字面那四个字，此时下拉里没有任何一项等于当前值（看着像没存上、想改也点不到它自己）。该判据现在多一条"要收掉的正好是当前值就别收"。③ **不成立、也不该那么修**：`pillColor` 判"本人"只认这一行自己的群昵称，这一版表**一行空昵称都没有**（`/api/data` 查过），而 `statusWithSelfDone` 又是"昵称空就原样保留「本人已完成」"，所以"空昵称 + 状态里是人名"只可能是表被外部清过格；拿状态值当本人名兜底等于把"对不上名单的人名给黄底"那条规则弄瞎（临时成员、写错的名字全变橙），**不动**。④ **真缺陷**（headless 浏览器按真实 CSS 量过）：底行原本是 `.picker` 的最后一个子节点、跟候选共用一个 220px 的滚动区，10 个候选 + 底行自然高 449px 时底行落到浮层可见区域之外（量到 top 650、浮层只到 464）——**主人根本点不到「收录」**；另外 `placePicker()` 向下开写的 `max(96, min(cap, below))` 那个 96 的下限，会在单元格贴着视口下沿时把 fixed 浮层顶出屏幕。现在候选搬进独立的 `.picker .opts`（只有它滚）、底行常驻浮层底部，`placePicker()` 按"哪一侧真正放得下"选边并夹进视口（最少 48px）。**回归**：`editor/test/client-state.test.mjs` 12 → 15 项（新增三条：候选写法只差空格/全角括号时当前值照样打勾且同一值只列一项、昵称已是候选而这一格还是字面「本人已完成」时它不能被收掉、浮层的几何——限高落在视口里且底行在候选滚动层之外；假 DOM 补了"最小排版"：`scrollHeight` / `clientHeight` / 按 style 复算 `getBoundingClientRect`，视口 1200×600），`test/layout.test.mjs` 那条加了两条结构约束（`.picker` 不再自己滚 + `.picker .opts` 有自己的滚动区 + JS 里真造得出 `.opts`），三个假 DOM 帮手（`page-vm.mjs` / `save-conflict.test.mjs` / `client-state.test.mjs`）改成从 `.opts` 那一层取候选。**逐条验证过能失败**（最小变异）：候选不加归一去重 → 第一条红；`opts` 判据不看当前值 → 第二条红；底行搬回 `.picker` 那层 → 几何那条红；`.picker` 回到自己滚 / `.opts` 不单独滚 / 不造 `.opts` → 版式契约红；每次改完立刻还原并核对哈希。**维护者真实表**（只读 `/api/data`，未写表）复核：32 个可编辑完成情况格、当前值 35 个 token **缺勾 0**、归一化重复 0 处，候选少的 5 处全是既有口径（行内昵称已是状态值 ⇒ 收起字面「本人已完成」）。`node --check` 通过（`editor.html` 两段内联脚本抽出来也 check 过）；`node test/run.mjs` → **51 套（50 通过 + 1 按设计跳过）** |
