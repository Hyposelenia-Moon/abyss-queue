## 归属接口（`/api/ownership`，主人专用）

表里**没有 QQ 列**，稳定身份只存在编辑器侧：绑定文件（`data/abyss-editor-bindings.json`）里的 `QQ → 行号`，外加
"这份绑定是对着哪一版表写的"（表指纹）+ 完成情况锁。行号只在**同一版表**里才有意义，所以外部（Excel / WPS / 别的进程）
改过表之后归属随时可能"对不上账"。这两个接口就是把这层状态摊开。

### `GET /api/ownership`

```jsonc
{
  "ok": true,
  "version": "…当前表指纹…",
  "bindings": { "table": "…绑定记的那一版…", "stale": false, "count": 7 },
  "locks": { "table": "…", "stale": false, "count": 2,
             "rows": [{ "sheet": "幽境危战", "row": 11, "seq": 1, "nickname": "乙", "by": "主播", "at": 1, "current": "乙", "stale": false }] },
  "roster": { "group": "…", "updatedAt": 0, "count": 42 },
  "sheets": [
    { "name": "幽境危战", "bound": 7,
      "entries": [{ "qq": "30001", "row": 11, "seq": 1, "nickname": "别人", "current": "甲", "rowExists": true,
                    "stale": true, "conflict": false, "conflictWith": [] }] }
  ],
  "missing": { "supported": true, "reason": "",
               "rows": [{ "sheet": "幽境危战", "row": 15, "seq": 5, "nickname": "查无此人", "gameName": "…", "status": "排队中" }] }
}
```

`entries` 里每一项就是一条绑定，四个字段回答"这条还信不信得过"：

- `nickname` 是绑定里**记的**群昵称，`current` 是表里那一行**现在**的群昵称；
- `stale`：`!rowExists || nickname !== current`——那一行没了，或已经换了人；
- `conflict` / `conflictWith`：同一行被**两个以上** QQ 都"有效"认领（绑定记的昵称与表里一致）。正常写入流程造不出
  这种状态（`validateRows` 拒重名、`dropBindsAt` 清旧绑定），只有手工改过的绑定文件 / 老数据才会；
- 表里已经没有的榜（绑定还在）也会列出来，标 `missingSheet: true`。

**`row` 与 `seq` 是两个数，别混用**：`row` 是**表格行号**（删行 / 对账用它对准那一行），`seq` 是 A 列那个**序号**
（`=ROW()-k` 的缓存值 1..N；那格空着时按"数据区第几行"算）。三个榜的表头行号不一样，同一个位置的 `row` 各不相同
（现场同一个人显示成「剧诗 第 9 行」「危战 第 15 行」），所以**给人看的数字一律用 `seq`**（页面写「序号 N」，真行号只进
悬浮提示）。`missing` 那份同理（`editor/roster-sync.js` 的 `missingCandidates`）。

### `POST /api/ownership` `{ "action": "rebuild" }`

按**当前表**重算一遍（`rebuildOwnership`，与自动对账同一套规则）：绑定记的那一行还在、昵称也没变 → 保留；按群昵称在表里
**唯一**命中 → 跟过去（顺手纠正行号）；重名看不出是哪一位 / 表里没这个人 / 两个 QQ 争同一行 → **一律作废**，绝不按旧行号
认人。响应就是"做了什么"：

```jsonc
{ "ok": true, "version": "…", "kept": 2, "moved": 1, "dropped": 5,
  "unconfirmed": 3, "missing": 2, "locks": { "kept": 1, "dropped": 1 } }
```

- `kept` / `moved`：保留几条、其中几条纠正了行号；
- `dropped`：作废几条，拆成 `unconfirmed`（重名 / 争同一行，**只能人工核对**）与 `missing`（已不在表里）；
- 重建**只写绑定与锁，不动表格**，所以不存历史版本；走同一条写队列，页面上的做法是"查看 / 一键重建（二次确认）"，
  重建**不碰**用户没保存的草稿。

权限与 `/api/admins` 同一口径：**主人**（或管理口令这个备用入口）；白名单管理员与本人链接一律 403——前者不该看到全表
归属，后者本来就只该看到自己那一行（`editor/test/ownership.test.mjs` 盯着）。

### 为什么不给表加"稳定成员 ID"列

加了 ID 列，"这一行是谁"就写成表里的数据，审计与跨版本对账都能退化成一次列比对。代价是：

- 表是**人工维护、还要给人看**的（会被人直接在 Excel / WPS 里打开编辑）。多一列 ID 等于让每个人多维护一样东西，
  漏填一行就是"这个人没有身份"，而漏填是必然发生的；
- ID 得由程序发、程序写进用户正在编辑的那一行，等于把"报名"拆成两步（填表 + 领号），群友拿到的还是同一份表，出错面更大；
- 稳定身份本来就在编辑器侧（QQ 是签名过的、不会变），表里的昵称只是**展示**。真正需要的不是 ID 列，而是"这层状态可审计、
  可重建"。

所以这条路代价明确：表保持原样，编辑器侧的绑定承担稳定身份，用表指纹 + `stale` / `conflict` 把风险显式暴露出来，并给主人
一个一键重建的入口。要认下来的代价：① 别人手工把 A 的名字写进 B 那一行，原理上无法与"A 自己改了群名片"区分——这类改动靠
**群名单对账**（`POST /api/roster`）+ 审计 + 人工核对兜底；② 绑定文件丢了 / 换部署目录，归属就得重建一次（重建规则是安全的：
宁可让人重新认一次，也不会把别人的行认成自己的）。

## 改动记录（留痕）

**谁在什么时候改了哪一行的哪个字段**，落在 `<插件根>/data/abyss-editor-changes.json`，滚动保留最近
`ABYSS_EDITOR_CHANGES_KEEP` 条（默认 2000）；页面右上角「改动记录」面板看它。

为什么要有它：历史版本回答"怎么退回去"但**没有作者**；审计日志答得出"谁调了哪个接口"但**没有字段级差异**；归属锁只有
"完成情况"一格、而且记的是昵称。权限放开之后真正兜底的是"看得见 + 退得回"，所以这一份是唯一能回答"这一格是谁改的"的地方
（实现与口径见 `editor/changes.js`）。

| `kind` | 什么时候写 | 关键字段 |
|---|---|---|
| `edit` | 保存成功（`/api/save`）、群名单同步改名（`/api/roster`） | `sheet` `row` `changes: { 字段: [原值, 新值] }` `via` `snapshot` |
| `reject` | 保存被拒（越权 / 校验不过 / 409 冲突）——**"谁在试"和"谁改成了"一样重要** | `rows: [试图改的行号]` `reason` |
| `remove` | 群名单对账发现**退群 / 被移出**，那一行被删并压紧 | `qq` / `nick` 记的是**被删那一行的人**，`reason` |
| `order` | `/api/move-row` 插队 | `from` `to` `moved` |

几条口径（都有套件钉着，见 `editor/test/changes.test.mjs`）：

- **只认实际差异**：自动保存提交的是**整行**，所以"提交了几行"≠"改了几行"——服务端按逐字段比对算，没碰的字段一个都不记；
- **记的是写完之后的终值**：服务端会改造提交值（「本人已完成」落成群昵称、主播锁回退），记终值才对得上表；
- **改名连带单独标 `via: "改名连带"`**：本人改名会带着改**别人那些行**的完成情况，那是系统替他改的，不能记成"他动了别人的行"
  （群名单同步写的记 `via: "群名单同步"`，`qq` / `nick` 记那一行的人）；
- **可见范围按身份分**（`GET /api/changes`）：管理员看全部；本人看**自己发的 + 改到我自己那些行的**——"别人改了我的行"必须让
  本人看得见；访客 403；
- **不影响写表**：记录在"表写成功之后、仍在同一个临界区里"落盘（`afterCommit`），写记录失败只记一行日志。

面板里每条若带着 `snapshot`（**写这一笔之前**存下的历史版本），右边就有「回到这一笔之前」，走与历史版本同一个
`POST /api/restore`。自动保存那条路的存底有 5 分钟节流，所以 `snapshot` 常常是空串（= 这一刻没有单独存底，面板不猜是哪一份）。

## 实时刷新与行级冲突（多人同时填表）

两个机制配套出现，缺一个都会坏事：**只做实时刷新** ⇒ 谁改了表别人就 409（整表指纹连坐）；**只做行级冲突** ⇒ 页面看不到
别人的改动、冲突发现得太晚。

### 实时刷新（别人的改动自动进来）

- **探测**：`GET /api/version?fast=1` 每 **5 秒**一次，**只回表指纹**（几百字节）。三个不探的时机：页面不在前台
  （`document.hidden`，切回来立刻补探一次）、有保存在飞、这一轮还没排下一轮。连续失败按 **5s → 10s → 30s** 退避，
  **失败不弹任何提示**（它是后台动作，每 5 秒打扰一次比不刷新更烦）。
- **拉取与合并**：指纹真变了才 `GET /api/data`，然后**按行**合并（`mergeRemote`）：

  | 情况 | 怎么办 |
  |---|---|
  | 我没碰过的行 | 直接换成远端的（这就是"看到别人的改动"） |
  | 我改过、远端没改 | 什么都不做 |
  | **两边都改过** | 本地值一个字不动，那一行记进 `rowClashes`、行左边加一条竖线，右上角给「用表里的 / 保留我的」 |
  | 远端没有了（退群删行） | 我改过 ⇒ 同上（远端那半是 null）；没改过 ⇒ 跟着表走 |
  | 正聚焦的那一行 | 整行跳过（可能刚点进去还没敲字，这一刻换值会让人盯着没见过的数字继续打字） |

- **提示不与保存状态混在一起**：`#permTip` 说"别人的改动进没进来"，`#saveState` 说"我的改动存没存"。前者几秒后自己消失，
  有冲突时改成常驻的两个按钮。合并之后 `tableVersion` 跟着换新（不换的话下一轮又会"发现"同一个新版本、每 5 秒白拉一次）。
- **不动的东西**：主播列表（`anchorRows`）不合并不覆盖——那是管理员的**手动保存**区，正在改的时候被换掉更糟；下拉候选 /
  主播名 / 默认值这些不覆盖用户输入的元信息照常更新。

### 行级冲突（我改的那几行有没有被人动过）

`/api/data` 给每行下发 `fp`（**行指纹**：那 7 列的值按列序拼起来取 sha1 前 16 位，**口径只有服务端一处**，页面当不透明凭据）。
页面保存时带 `base = {行号 → fp}`：

- **带了 `base`** ⇒ 服务端按**行**判：只比"这一轮真正提交的那些行"的指纹，对不上就 409 并回 `rows: [...]`——别人改了别的行
  **不再连坐**。新行没有指纹，`base` 里给空串 = "我读到的是空行"：表里若已被别人填上，判冲突（老口径下这种覆盖是**静默发生**的）。
- **没带 `base`**（机器人 / 旧页面 / 套件）⇒ 照旧整表指纹连坐。**混跑时两边都不用改**：新页面 + 旧服务端走老口径，
  旧页面 + 新服务端也走老口径。页面另有一道保险：表里若有行**没有** `fp`（服务端比页面旧），整份请求退回只带 `version`
  的老口径，绝不自己造空基线。
- 两种 409 **分开处理**：`rows` 给了行号 ⇒ **只把那几行挂起**（`blockedRows`），其余草稿照旧自动保存；没有 `rows` ⇒ 整表冲突，
  照旧暂停自动保存。
- 解冲突：**用表里的** = 基准换成远端那一版 + 丢掉这一行的草稿（远端删了这一行就把行也去掉）；**保留我的** = **基准也换成远端
  那一版**，再把我的有效值整行写成草稿——用户看到的值一个字不变，但下次保存的基线已经是对方那一版（不会再撞车）。

回归：`editor/test/live-refresh.test.mjs`（服务端与页面两段）。

## 权限

**先看"名单可不可信"**（`editor/roster.js` 的 `trusted()`：收到过、非空、且 48 小时内），这是本群守卫的地基：

| 谁 | 看 | 改 |
|---|---|---|
| 主人 / 白名单管理员 / 管理口令（`role=admin`） | 整表 + 主播列表 + 白名单 + 历史版本 | 不限 |
| **本群成员**（名单可信 + QQ 在名单里） | **整张表**（口径 A：能看到才能改） | 整张排队区：**自己的行不限**；**别人的行**一次 ≤3 位、10 分钟 ≤10 位，且不碰红线 |
| 有身份但**名单里没有他**（名单可信） | 只有自己那些行 | **只读**（转发到群外 / 退群了） |
| 有身份、**名单不可信**（空 / 超 48 小时） | 只有自己那些行 | 只有自己那一行 + 空行（**老口径**；不放权也不拒人） |
| 没有身份签名（`guest`） | 整表只读 | 无 |

- **三条红线**（本群成员改**别人的行**时，不计数、直接拒 + **每次都私聊告警主人**）：清空别人的行（等于把人踢出队列）、
  改别人那一行的群昵称（群昵称是"这一行是谁"的依据）。第三条「改被主播锁定的完成情况」**不整单拒**：照旧"忽略那一格、
  其余照写 + 回执说明"——既保住主播的填写，又不让人白填一整行。
- **主播锁只在"写成某位完成人"时才建**：主播把这一格改成主播名（或落成群昵称的 `本人已完成`）⇒ 建锁，本人那一格只读；
  改成 `排队中` / `等待开启` / 清空 ⇒ **删掉旧锁**、本人可以继续改——"改回排队中"本来就是还给本人填的动作。
- **普通人只能填两档**：自己那一行只能写成 `排队中` 或 `本人已完成`（落成该行群昵称）；其余值（主播名 / `等待开启` /
  任意文本）**只忽略那一格并回报**（`ignored` 里带原因，不整单拒），同一发的备注 / 游戏名等照旧写。页面把本人那一行的
  完成情况下拉也收窄到这两档。本群成员改**别人的行**仍按旧口径（额度 + 主播锁 + 红线）。
- **锁只在"这一格当前确实记着某位完成人、且不是本人自有标记"时才生效**（`lockIsLive` + `lockWorthy`）：值是 `排队中` /
  `等待开启` / 空 ⇒ 算**过期**；值是**字面「本人已完成」或本行自己的群昵称** ⇒ 那是**本人的自有标记**、同样不算锁
  （主播代点过一次「本人已完成」也允许本人自己撤回）。两种都下发 `statusLocked=false`、保存时也不忽略那一格（页面与执行
  同一个判断，不会"看着能改、存下去被拦"）。兜的是：① 绕过 `/api/save` 的改表（手工改 / 第三方工具）留下的陈旧锁——
  开榜自动翻只改状态不碰锁，所以 `catchUpOpenStatus` 翻完会把被翻那几行的锁一并删掉；② 主播代点过「本人已完成」之后，
  本人那一格变成只读胶囊、连"改回排队中"都做不到。
- **额度**（`editor/quota.js`）：一次保存 ≤3 位、10 分钟滑动窗口 ≤10 位，超了只拒**这一次**并告警；**被拒的尝试不占额度**
  （否则一次手滑会把后面整个窗口锁死）。它是「每次保存」的额度，不是「每人每天」的额度——真正拦"慢慢改"的是窗口累计那一档。
- **群外人想写表不算红线**（只记审计与日志，不私聊）：那多半是有人点了转发链试了一下，每次都私聊只会把人烦到关掉告警。
- **告警通道**（`editor/alert.js` + `editor/injected.js` 的 `injectOwnerAlert`）：编辑器发不出消息（它可能独立跑），只回答
  "该告警了 / 告给谁 / 说什么"，发送由宿主做（`modules/editor-host.js` 的 `sendOwnerAlert`，私聊每一位主人）。硬红线每次都发；
  其他越界同一个 QQ **5 分钟合并一条**（带上"第几次触发"）；独立模式下退化成**记一行日志**。告警发不出去**不影响保存判定**。
- **名单过期的提醒**：有人打开页面时顺手看一眼，超 48 小时就私聊主人一次（最多 24 小时一条）。"一次都没推过"**不吵**
  （启动后 20 秒会推一次，每次重启都报就是噪音）。
- **`#排队` 前补推名单**（`apps/queue.js` 的 `ensureRosterKnows`）：名单每天才推一次，**刚进群的人当天不在名单里** ⇒ 拿到的
  链接会被判成群外人（只读）。所以发链接之前先看"他在不在**已有名单**里"，不在就**当场重扫一次群成员并推给编辑器**再发
  （顺序不能反）。只在"不在名单里"时才做（扫全群是重活），失败只记日志、绝不挡住这次 `#排队`。

### 另外几条（与上表配套）

- **页面标题跟着角色走**：主人 / 白名单管理员（含管理口令，三者算出来的角色都是 `admin`）看到 **「排队表 · 管理」**，
  本人与只读访客是 **「排队表 · 填写」**（标签页标题一起改）。2026-11-26 起两者连**页面集合**都分开了：管理身份只有管理那七页、
  没有填写页；本人与只读访客只有填写页（PC 与手机一致），详见 [`编辑器-页面.md`](编辑器-页面.md) 的「两套页面」。
  判据只有 `perm.role` 一个（`editor.html` 的 `renderPerm()`）。
- 独立跑并开 `--owner-only` 时：以上之外的人一律 403（只有 `/api/version`、`/api/meta`、`/healthz` 仍凭口令放行）。
- 「权限管理」面板（右上角，`perm.showAdmins` = 主人或管理口令）**三样都要列**：**主人**（服务器 `owner` 名单 / 启动参数，
  带「主人」标记）、**白名单管理员**（`/api/admins` 的 `admins`）、以及文件里**解析不出 QQ 的条目**（群昵称等，标「不是权限」
  并给"该改成哪个 QQ"，可点「×」删）。主人名单与白名单是**两份独立名单**：主人不重复写进 `admins` 也照样是主人，所以面板
  不能只画其中一份（漏画哪一种，当事人都会以为"配了却没生效"）。回归见 `editor/test/ownership.test.mjs` 末组。
- **白名单只加 QQ 号，不收群昵称**：输入框 placeholder 与面板提示都只提 QQ（以前写着「QQ 号或群昵称」，等于教人填昵称）；
  真填了昵称，`POST /api/admins` 会 400 拒掉，并且**当场去群名单里查一次**——查得到就直说「「某某」在群名单里的 QQ 是
  123456789，要加就填这个号」，查不到只说规则。文件里已存在的昵称条目**不生效但会显示**（见上条），可删或改成 QQ。
