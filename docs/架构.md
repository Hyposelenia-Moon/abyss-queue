# 架构

> 目录分层、数据与读写链路、入口加载、插件 class API、命名。

## 目录结构

| 目录 | 职责 |
|------|------|
| `apps/` | 功能入口，每个文件导出一个 extends `plugin` 的 class（7 个：queue / anchors / help / inserter / leaver / live / roster-sync） |
| `model/` | 数据层：外部 API 调用、HTTP 客户端、签名、文件与数据读写 |
| `modules/` | 业务层：调度、状态、缓存、流程编排（import `model/`） |
| `components/` | 可复用工具：配置读取、渲染、日志、常量、格式化、启动补齐 |
| `editor/` | 网页编辑器（挂在 bot 自己的 `http.Server` 上，唯一写表入口），含 `editor/http/` 与前端 `editor.html` |
| `guoba/` | 锅巴配置面板（schema 分文件，`guoba/index.js` 只做拼装） |
| `config/` | 运行时配置（git-ignored）+ `.example` 参考（入 git） |
| `defSet/` | 配置模板，含 `${变量}` 占位符 |
| `resources/` | HTML 模板、字体、图标等静态资源（入 git） |
| `tools/` | 独立小工具：`migrate.mjs`、`migrate-anchor-name.mjs`、`verify.mjs`、`doc-check.mjs` |
| `docs/` | 文档（每册一个主题；历史沿革单独成册） |
| `test/` | 回归套件（入 git，清单见 [`../test/README.md`](../test/README.md)） |

- 判定文件该放 `model/` 还是 `modules/`：**import 了 `../model/` 的，必须放 `modules/` 或 `apps/`**；自己发 HTTP 且不做别的事的，
  放 `model/`。
- 本仓库不设 `lib/` / `tool/` / `example/`：框架级通用库不归插件管；需要的外部工具都写成 `tools/` 下的 ESM 脚本；
  原 `lib/` 里那些纯逻辑文件已按层归入 `model/`、`components/`、`modules/`（映射见 `docs/历史沿革-工程与套件.md`）。
- **静态资源随源码分发**：字体、图标、模板都入库，放在 `resources/` 下（字体用 `resources/common/font/`，与 Axiu-Plugin /
  Atlas-Plugin 同位置）。**不做"首次使用时联网下载 + 本地缓存"**——那会引入网络失败分支、缓存目录与镜像配置，都不是这个插件
  该管的事。需要某个静态资源时直接放进仓库并读本地文件；文件缺失要给出可读的降级（例如回落到系统字体）而**不是**再去下载。

## 数据与读写链路

```
编辑器（挂在 bot 的 http.Server 上，前缀 /queue，唯一写入口）
   │ 写 data/queue.json（原子替换；写前抢 data/queue.lock）
   │ 每次提交后重建 data/queue.xlsx（导出镜像）
   ▼
插件（只读）── model/local.js 的 JsonTable 读 json → 投影成 models → 渲染 → 推送
```

- **唯一事实源是 `data/queue.json`**。插件每次读都重新打开，没有快照 / TTL / 缓存副本，写过的下一次读立刻看到；JSON 走
  同目录临时文件 + `rename` 原子替换，读不到半份。
- **`data/queue.xlsx` 是导出镜像**，每次提交后重建。外部用 Excel 改它，只在镜像 mtime 比 json 新时被导回（按表头认列）——
  兼容入口，不是推荐工作流。
- **只有一个写者**：正式部署就是挂在 bot 上的那一个编辑器；`127.0.0.1:7788` 上的独立调试实例还在服务时，宿主拒绝挂载
  （见 [`编辑器.md`](编辑器.md) 与 `modules/editor-host.js`）。
- **`data/queue.lock` 是兜底跨进程锁**：只圈住「读文档 → 写文档 → 写镜像」这一段；常规读不拿锁，只有读路径需要把镜像导回时
  才进锁（`model/json-table.js` 的 `NEED_IMPORT` 重试）。锁里的 `{pid, host, at}` 三样都用来判残留：**同主机只看 pid**
  （进程还活着就不算残留，哪怕它已经写了很久——按时间硬抢会让「写得慢」变成两个写者同时写），**跨主机（网络盘）才按时间判**。
- **插件不直接写表**：名单同步 / 每日整理 / 插队 / 退队 / 完成情况 / 周期清榜都经 `editor/service.js` 的
  `registerEditorService()` / `getEditorService()` 直调编辑器进程内的同一份 `JsonTable`（同一套锁、版本与审计）。编辑器没挂载时
  `getEditorService()` 为 `null`，动作直接报错，不做 HTTP 兜底。
- 历史版本与归档：写前存 `data/versions/`（滚动 20 份；5 分钟内连续小改最多一份），每日 / 每月归档在 `data/archives/`
  （7 天 / 12 个月）。结构细节见 [`queue.schema.md`](queue.schema.md)。

## 入口加载

- 目录下存在 `index.js` → **单入口模式**，Yunzai 只加载该文件；无 `index.js` → 目录遍历模式，逐个 `.js` 注册。两种模式都合法，
  但**不得在未与维护者确认的情况下切换**（见 `AGENTS.md` 的约定）。
- 单入口模式下，`index.js` 依次做：`ensureConfig()`（配置缺失时从参考文件复制）→ `bootstrap()`（启动补齐，见
  `components/bootstrap.js`）→ `boot()`（退出钩子与重启标记）→ `await startEditorHost()`（挂编辑器，**失败不抛**）→
  `watchConfig()`（配置热重载）→ 动态发现并按文件名导出 apps：
  - 先 `readdir` 过滤出 `.js`，import 数组与命名遍历**同源**，避免索引错位；
  - 用 `Promise.allSettled` 并行 import；
  - 用 `isPluginClass()`（判断 `prototype` 属性不可写）挑出插件 class，**不得用 `Object.keys(mod)[0]`**——ESM 命名空间对象的
    key 按名字排序，多导出一个常量就会顶掉 class，且 loader 会静默跳过无效导出，导致整条规则不注册；
  - 每个 apps 文件**只能导出一个 class**，其余导出（常量 / 工具函数）随意；
  - 逐条打印 `[abyss-queue] 载入: xxx`，漏注册时能一眼看出。
- 单入口插件**没有热重载**：loader 只为目录遍历模式注册文件 watcher，任何 `.js` / 模板改动都必须完整重启 Yunzai。

## 插件 class API

```js
export default class SomeFeature extends plugin {
  constructor() {
    super({
      name: '中文功能名',        // 必填，中文
      dsc: '功能描述',           // 必填，中文
      event: 'message',         // 默认 message
      priority: 5000,           // 数字越小越先执行
      rule: [{
        reg: /^#命令/,
        fnc: 'methodName',      // 指向 this.methodName，接收 e
        permission: 'all',       // master | owner | admin | all
        log: true,              // false 时不打印执行日志
      }],
      task: [{ name: '任务名', cron: '0 30 5 * * *', fnc: 'taskMethod', log: false }],
      handler: {},
      namespace: 'abyssQueue',
    })
  }
}
```

- 类名 PascalCase，与文件名对应；`name` / `dsc` 一律简体中文。
- 方法返回 `true` 表示命令已处理（阻止低优先级插件继续匹配）。
- 拦截类命令（需要抢在其他插件之前处理的）必须把 `priority` 调到足够小，并在报告中说明理由。
- 插件注册失败、规则不生效这类问题，先查 `rule` 是否真的注册上了，再查业务逻辑。

## 命名

| 元素 | 规范 | 示例 |
|------|------|------|
| 插件目录 | kebab-case，带 `-plugin` 后缀 | `LinkFlow-Plugin` |
| 功能文件名 | camelCase | `cmdExport.js` |
| 导出的 class | PascalCase，与文件名对应 | `class cmdExport` |
| 子目录 | kebab-case | `linkparse/` |
| 配置键 | 点分隔小写驼峰 | `gallery.autoUpdate` |

本仓库目录名 `abyss-queue` 不含 `-plugin` 后缀，属既有偏差；**是否改名由两位维护者共同决定**，不得自行执行。
