# abyss-queue（三路深渊排队）

在 QQ 群里查深渊排队：机器人读**本机**的状态文档 `data/queue.json`（唯一事实源），渲染成图发出去。
同目录的 `data/queue.xlsx` 是它的**导出镜像**（给 Excel 看、下载、历史版本用），不是第二个事实源。

四张榜：**幻想真境剧诗 / 幽境危战 / 深境螺旋 / 绝境攻炼**。榜名可以自己改，插件按表内内容识别，不写死。

填表与改表都在**编辑器**里做，它是唯一的写入口。编辑器就在本仓库 `editor/`，由插件挂到**机器人自己的
HTTP server** 上（前缀 `/queue`），与机器人同进程、同启停——不是另一台服务器，也没有单独的进程要维护。
**插件自己一个字都不写表**：它只读 `queue.json`，要写就经 `editor/service.js` 直调编辑器进程内的同一份实现。

## 能做什么（命令速览）

| 命令 | 谁 | 干什么 |
| --- | --- | --- |
| `#排队` | 所有人 | 四榜人数总览 + 本人排队信息（一张图），后面接填写情况与填报入口 |
| `#排队 <榜>` · `#<榜>排队` · `#<榜>列表` | 所有人 | 某一榜的队列；榜名可写全名、简称或序号 |
| `#主播` · `#主播 <榜>` · `#主播 <名字>` | 所有人 | 主播列表（合并 / 单榜 / 单人详情，含开播状态） |
| `#退队 <榜>` · `#退队 全部` | 所有人 | 退出**自己**的排队（一次一个榜），退完自动整理该榜 |
| `#插队 [<群昵称>] [<榜>]` | 主人 / 白名单管理员 | 把某人挪到「排队中」最前面；不带参数挪自己 |
| `#开播提醒` · `#开播提醒 开/关 [主播]` | 所有人 | 查看 / 设置**自己**的开播提醒（旧写法 `#排队开播提醒` 兼容） |
| `#排队直播状态` | 所有人 | 强制刷新一次直播状态（调试用，忽略缓存） |
| `#排队帮助` · `#排队菜单` · `#深渊帮助` | 所有人 | 帮助页（图片，失败回退同源文本） |
| `#排队初始化` | 主人 | 生成口令与签名密钥、写白名单、探活，三步一次做完 |
| `#排队同步名单` | 主人 | 立刻扫一次群成员名单并推给编辑器 |
| `#更新排队` | 主人 | 框架 `#更新` 的简写：拉本插件最新代码并重启 |

共 **10 条**注册规则（上表前两行是同一条规则的两种写法）。聊天端只负责**查询**；
`#插队` / `#退队` 也只是把「哪一榜、哪一行、怎么挪」交给编辑器。

## 安装与部署

在 Yunzai 根目录执行：

```bash
git clone --depth=1 https://github.com/Hyposelenia-Moon/abyss-queue.git ./plugins/abyss-queue/
pnpm install --filter=abyss-queue
```

配置只需填好编辑器那四项（`config/config.yaml` 的 `editor` 段）：

| 键 | 作用 |
| --- | --- |
| `editor.public_url` | 群友能打开的编辑器地址，**只用于拼链接**，插件不向它发请求 |
| `editor.token` | 访问口令（插件与编辑器共用这一份，会出现在每个人的链接里） |
| `editor.sign_key` | 身份签名密钥（**不要与口令相同**；留空或相同，编辑器拒绝启动） |
| `editor.admin_token` | 管理口令（可选；页面上 `?a=<这段>` 即主人身份，用来维护白名单） |

然后：

1. **放一份起始表**：把插件自带的 `resources/空模板.xlsx` 复制成 `data/queue.xlsx`。
   编辑器第一次启动时按它生成 `data/queue.json`；此后 json 是事实源，xlsx 变成导出镜像。
   **起始表与 json 都没有时编辑器不会挂载**（fail-closed：记一行 error 日志，机器人照常跑），
   日志里会直接告诉你该复制哪两个路径。
2. **重启 Yunzai**——凭证是插件加载时交给编辑器的，改完不重启会出现「插件用新口令、编辑器还认旧口令」，
   填表链接直接 403。
3. 在群里发 `#排队初始化`（**仅主人**）：口令与签名密钥、编辑器白名单、探活一次做完。
   **遇错即停**，已有产物只校验不覆盖，与当前配置不一致时宁可停下来让你决定。

数据目录不用管：固定 `<插件根>/data`，不可配置，也不允许离开插件目录（表、版本、归档、白名单、
绑定、进度都在里面；`data/` 已被 git 忽略，所以更新只动代码不动数据）。

编辑器挂在**机器人自己的端口**上（`server.port`，默认 2536），不是独立编辑器的 7788。
nginx 与安全口径见 [`editor/DEPLOY.md`](editor/DEPLOY.md)。

> **填表内容对全群可见**：编辑器口令在每个人的填表链接里，所以**拿到链接的人都能读到整张表**
> （群昵称、游戏名、选择与备注都在内）。本群成员还能改别人的行（受额度与三条红线限制），
> 所以别把隐私写进备注。

## 命令详解

### `#排队`

**只发一条消息**：一张图 + 图后的两段文字。

- **图**：四榜人数总览 + 发送者本人的排队信息（按 QQ 定位，表里没有就不显示这一块），底部印常用指令。
- **第一段：填写情况**，最多两段，按 `未完成：<榜名…>；已完成：<榜名…>` 组织（空的段不写）：
  - 「未完成」= 有自己那一行、且状态明确是 `排队中`；
  - 「已完成」= 主播打完的（表里是主播名）或本人点过完成的（表里落成群昵称）；
  - `等待开启` 与空状态两边都不列；**没有自己那一行的榜也不列**。
- **第二段：填报入口**。群聊发的是**固定入口页 + 6 位数字口令**：
  `点此填表：<editor.public_url>/#code=<6位数字>`。页面打开时自动用口令换回完整链接；
  口令 **5 分钟**有效，过期或不对就提示回群重发 `#排队`。
  完整长链接（`?k=&u=&s=&w=&ws=#v=`）**只走私聊**，因为 QQ 会风控群里的长外链。
  - `k` 访问口令，`u`/`s` 身份与签名，`w`/`ws` 是 **5 分钟时间窗**（只有当期与上一期可用），
    `v` 是**链接标记**：每发一次 `#排队` 就换一个，编辑器只认该 QQ **最新**那一条可写，其余只读——
    所以本人重发一次 `#排队` 就等于把转发出去的那条作废。
  - 地址、口令、签名密钥缺任一项就写「暂无链接」。

**主人与白名单管理员那一份走私聊**：发送者是主人或管理员时，整条回复私聊发给他本人，群里一个字都不发
（链接一旦落在群里，谁先点谁认领）。私聊那份再叠一层 5 分钟时间窗，且**只在本人发 `#排队` 时给一次**，
机器人不会主动重发；私聊发不出去只在群里回一句原因，**不会把管理链接退回群里**。

发送者不在已有群名单里时，机器人会**当场重扫一次群成员并推给编辑器，再发链接**（顺序不能反）——
编辑器的写权限按「名单可信 + 你在名单里」判，而名单每天才推一次，刚进群的人当天会被判成群外人只读。
只在「不在名单里」时才做，失败只记日志，绝不挡住这次 `#排队`。

### 按 QQ 定位「我的排队信息」

发送者的 QQ 是**权威身份**，群昵称只用来第一次认人：

1. **有绑定** → 按绑定认这一行（改了群名片也认这个人）
2. **没有绑定** → 按群昵称在表里找；找到就记下 QQ → 行 的绑定
3. 绑定指向的行已被清掉或已属于别人 → 绑定作废，回第 2 步
4. 仍然找不到 → **只发菜单**，不多发一条「没有你的记录」

名片与表里昵称不一致时插件只记日志、不改表（改表由编辑器做）；匹配**只看群昵称**，游戏名不参与。

### `#排队 <榜>` / `#<榜>排队` / `#<榜>列表`

```
#排队                → 总览（不带榜名）
#排队 危战           → 单榜
#幽境危战排队        → 同上
#螺旋列表            → 同上
#排队 2              → 按序号
```

榜名支持全名、`SHEET_ALIASES` 里的简称（剧诗 / 幻想 / 真境剧诗、危战 / 幽境、深渊 / 螺旋 / 深境、
攻炼 / 枪战 / 绝境）、以及序号（1 起）。
**不再支持 `#排队 全部`** —— 要看整体请到编辑器或表格。

单榜图里带着本人那一行（`list_limit` 控制显示行数，`0` = 全部）。

### `#主播`

- `#主播`：四榜合并成一张表，同一主播只出现一次，带「专职」列
- `#主播 <榜>`：只列该榜的主播
- `#主播 <名字>`：文本详情 —— 专职、各榜强项、开播状态与直播间链接

### `#退队`

- `#退队 <榜>`：退出自己在某一榜的排队（一次一个榜）
- `#退队 全部`：退出所有榜

**只处理调用者自己**，管理员也不能替别人退队。已完成的行不允许退队
（会回「已完成（原第 N 位），不予退队」）。退队由编辑器清行并立刻整理该榜。

### `#插队`

**主人 / 白名单管理员专用**（权限在 handler 里按 QQ 现查，与白名单共用同一份）：

- `#插队`：把自己在排队的每一个榜都挪到「排队中」最前面
- `#插队 <群昵称>`：点名挪别人那一行
- `#插队 <榜>`：只处理那一个榜

本来就在最前面时什么也不做，回一句「已经在最前面」。执行交给编辑器的 `model/move-row.js`。

### `#开播提醒` / `#排队直播状态`

- `#开播提醒`：查看自己的订阅状态（先看一眼，避免误开误关）
- `#开播提醒 开` / `#开播提醒 关`：全部主播开 / 关
- `#开播提醒 开 <主播>`：只关注这一位（可多次指定）

开播提醒是**可选功能**：只有订阅过、当前还在排队、且选的就是这位主播的人才会被 @；
**一个订阅的都没有时整条不发**，绝不 @ 全体。

`#排队直播状态` 是**强制刷新**（忽略缓存 TTL），它发现的开关播事件留在 pending 里，由下一轮 tick 发出。

### `#排队初始化` / `#排队同步名单` / `#更新排队`

| 命令 | 说明 |
| --- | --- |
| `#排队初始化` | 三步一次做完：生成口令与签名密钥 → 写白名单（owner QQ）→ 编辑器探活。**遇错即停、不覆盖既有产物** |
| `#排队同步名单` | 立刻跑一次群成员名单同步（平时只有两条自动路径：机器人启动后 20 秒、每天到 `roster.at`），回执照实说结果 |
| `#更新排队` | 框架 `#更新` 的**简写**，行为等同 `#更新 abyss-queue`：拉本插件最新代码并重启 |

三条都是**主人专用**。

## 数据与读写链路

```
编辑器（bot 同进程，挂 /queue，唯一写入口）
      │  写 data/queue.json（+ data/queue.lock 跨进程写锁）
      │  每次提交后重写 data/queue.xlsx（导出镜像）
      ▼
插件（机器人）── model/local.js 把 json 投影成 models → 渲染 → 推送
```

- **没有快照、没有 TTL、没有备份副本**：插件每次读表都重新打开 `queue.json`，表被改过下一次读取立刻看到。
- 读失败（json 与镜像都不存在）直接报错，指令层回「表格文件不存在」，不存在「拿上一次成功的快照顶着」的分支。
- 如果有人用 Excel 直接改镜像，编辑器下一次读表会发现镜像更新、按表头认列导回 json。
- 插件与编辑器之间**没有 HTTP**：写操作（名单同步 / 每日整理 / 插队 / 退队 / 完成情况 / 周期清榜）经
  `editor/service.js` 的注册表直调编辑器进程内的同一份 `JsonTable`（同一套锁、版本与审计）。
  编辑器没挂载时 `getEditorService()` 为 `null`，插件直接报错，不做 HTTP 兜底。
- `editor.public_url` 只用来拼链接，**插件侧没有任何出站请求**。

**历史版本与归档**（都在 `data/` 下）：

| 目录 | 什么时候写 | 留多久 |
| --- | --- | --- |
| `versions/queue-YYYYMMDD-HHMMSS.xlsx` | 每次**写表前**存底；页面连续小改 5 分钟内最多留一份 | 最近 `versionsKeep` 份（默认 20） |
| `archives/queue-YYYY-MM-DD.xlsx` | 当天第一次写表时留一份起始状态 | `archiveDays` 天（默认 7） |
| `archives/queue-YYYY-MM.xlsx` | 换月时留前月最后一次修改 | `archivesKeep` 个月（默认 12） |

## 编辑器

挂在机器人 HTTP server 的 `/queue`，与机器人同进程。宿主在 `http.Server` 这一层接管 `/queue` 及其子路径，
**不经框架的 express 中间件**（框架先装了四个 body parser 且无路径过滤，编辑器自己读原始请求体，
挂在中间件之后会收不到 body 事件、请求永久挂起）。`/queue` 不过框架的 `server.auth`，
鉴权就是编辑器自己的 `?k=` 与身份签名。

### 页面

侧栏三组，共七个页面（另有填写页，只靠深链进入）：

| 分组 | 页面 | 内容 |
| --- | --- | --- |
| 数据 | **排队表** | 四榜页签、主播区、排队表、已完成栏；改行的主战场 |
| 数据 | **概览** | 三张统计卡、四榜进度、**主播完成率**（可切换榜）、最近改动 |
| 数据 | **清榜安排** | 四榜的当前阶段 / 上次清榜 / 下次清榜 / 还剩多久 |
| 版本与审计 | **历史版本** | 版本列表（下载 / 回退）、每日与每月归档 |
| 版本与审计 | **改动记录** | 谁在什么时候改了哪一行的哪个字段（按天分组、逐字段对照） |
| 权限与归属 | **权限管理** | 白名单（只认 QQ）、角色、来源 |
| 权限与归属 | **归属状态** | QQ → 行 的对账：QQ 号 / 群昵称 / 对象 / 行 / 状态 |

填写页（`#fill`）是给群友用的窄版：只有「排队中」与「已完成」两块，没有侧栏。

### 权限四档

只按**稳定 QQ** 判，群昵称不能当身份（白名单、主人名单是两份 QQ 清单）：

| 角色 | 能做什么 |
| --- | --- |
| 主人（`owner`，或页面带 `?a=<管理口令>`） | 全部：白名单与归属重建 / 清空无主行、周期清榜、呼叫成员、主播列表、历史版本与回退、改动记录 |
| 白名单管理员（QQ 在 `abyss-editor-admins.json`） | 改所有人的行（不限行数）、主播列表、历史版本与回退、呼叫成员、改动记录看全部；**不能**清榜，也没有「权限管理 / 归属状态」两页 |
| 群成员（有身份签名、且在本群名单里） | 改整张排队区（自己的行不限；别人的行受额度与三条红线）、呼叫主播、收录临时成员名、改动记录（只看自己发的与改到自己行上的） |
| 不在名单里 / 链接已过期 / 只有口令 | 只读 |

**群成员不是「只能改自己那一行」**：名单可信且他在名单里时（`roam`），整张排队区都能改，
只是改别人的行有额度（一次 ≤3 行、10 分钟 ≤10 行）和三条红线（清空别人的行、改别人那一行的群昵称、主播锁）。
名单不可信（空 / 超过 48 小时）时退回老口径：只能碰本来就是自己那一行、或新增且昵称是自己的行。
主页面的「权限管理」「归属状态」两页只给主人（`perm.manage`）；主播列表的**编辑**按钮只给管理员；
「收录临时成员名」本群成员都能用。清榜接口（`/api/cycle*`）只认机器人自己或主人。

### 写表与自动保存

- 输入即改，**1.2 秒防抖**后自动保存。每次保存带 `version`（页面读到的那一版表指纹），对不上回 **409**，
  一个字都不写。
- 每一行还带 `fp`（行指纹），保存时作为 `base` 带回 ⇒ 判**行级冲突**：别人改了你这一行，你的保存会被拒，
  而不是把别人的改动盖掉。
- 保存回执可能多三样（只在真的发生时出现）：`compacted`（删行后把下面提上来）、
  `tidied` / `nickSync`（改了完成情况就立刻整理 + 昵称检测）、`rowMap`（老行号 → 新行号，页面据此搬草稿）。
- 页面上的「回退」/「前进」不弹确认框，取的是**最新一份历史版本**；请求中按钮置灰并显示「处理中…」，
  完成后同按钮 3 秒内重复点击被忽略。

## 主播

主播区在表头行**之上**：A 列主播名（可带 `【推荐度】`）、C 列核心强项、D 列专职、
G/H 列直播入口、I 列总强项（`#主播` 合并多榜时优先用它，为空才退到各榜 C 列）。

### 推荐度

编辑器里是**五档胶囊**：`夯 / 顶级 / 人上人 / NPC / 拉完了`（颜色依次对应 N6 180s / N6 / N5 / N4 / 黑）。
旧值（强烈推荐 / 推荐 / 提分推荐 / 可选 / 不可选）照原样灰显，改一次就换成五档。

> 注意：**机器人出图仍按旧口径排序**（强烈推荐 → 推荐 → 提分推荐 → 可选 → 其它），
> 编辑器页已按五档排序。两者暂时不一致。

### 专职

「专职」= 这位主播打哪个榜，放在 **D 列**（C 与 G/H 之间那块合并区的空位，不与其他列抢格）：

1. **表里手填**：D 列写他专职的榜
2. **自动推断**：D 列留空时，按他出现在哪些榜的主播区显示

编辑器的主播编辑框里，专职**默认填当前榜名**，不用手敲。

### 直播入口

编辑器里是**两个字段**：平台、链接。渲染时只显示 B 站，抖音/虎牙等其它平台请写在声明里，不进图。

| G 列（平台） | H 列（链接） | 显示 |
| --- | --- | --- |
| `B站` | `https://live.bilibili.com/1960956034` | `B站 https://live.bilibili.com/1960956034` |
| `B站 https://live.bilibili.com/1960956034` | *(空)* | 同上（旧表里链接写在 G 也能读） |
| `B站/抖音（付费）` | *(空)* | `B站`（其它平台过滤掉） |
| `B站` | `https://live.douyin.com/123` | `B站`（非 B 站链接不显示） |

### 主播编辑框（管理员）

主播卡上的「编辑」打开居中模态，六个字段：主播名、推荐度（五档胶囊）、专职、简介、
直播入口（平台）、直播入口（链接）。保存走 `POST /api/anchors`，带 `version`；
名字撞上别名表正名键会被拒（见下节）。

### 别名（表里/群里的其它写法）

```yaml
anchor_aliases:
  阿修Axiu: ["阿修"]          # #主播 阿修 也能查到
  摸头妹: ["璃月第一深情"]     # 表里写「璃月第一深情」的行算作摸头妹
```

- 别名按**正则整串匹配**（忽略大小写），写错的正则会跳过、不影响出图
- 影响 `#主播 <名字>` 的查找、`#排队` 里本人那一行的直播入口、编辑器「选择主播」的下拉归一
- 表里的原文不会因为别名被改写
- **正名是这里的键**：在编辑器里把主播改成另一个名字时，如果旧名正是 `anchor_aliases` 的键，保存会被拒，
  提示你先把配置里那个键改成新名——否则别名会全部指空。**改名请先改配置、再改表**。

### 直播状态与开播提醒

- 只认 **B 站** 的 `live.bilibili.com/<房间号>` 与 `space.bilibili.com/<UID>`；其它平台不查、也不展示
- 开关 `anchor_live.enable`（默认开）：关掉**完全不发请求**；打开后机器人每次重启强制刷新一次、
  每天第一次 tick 再强制刷新一次，其余 tick 按缓存增量刷新；`#主播` / `#排队` 只读缓存，不在命令里等外网
- 只显示 **直播中 / 未开播**；查不到或超过 10 分钟没刷新成功就**不显示**（不把「不知道」写成「未开播」）
- 开播提醒（`anchor_live.push`）：只 @ 订阅过、当前在排队、且选的正是这位主播的人；无人订阅整条不发

```
【幻想真境剧诗】主播「阿修Axiu」已开播，请 @甲 @乙 注意
https://live.bilibili.com/1960956034
```

## 业务口径

### 完成情况（「帮帮完成情况」列）

| 值 | 含义 |
| --- | --- |
| `等待开启` | 这个榜还没开，既不算排队也不算完成 |
| `排队中` | 还在等 |
| 其它任何值 | 已经处理过了 |

「其它值」存的是**人**：主播名，或点「本人已完成」时落成的**该行群昵称**（一格可写多个，逗号分隔）。
群友改群昵称时，编辑器只把他名下那些行里**整段等于旧昵称**的值换成新昵称——逐段比对，
别人的名字、主播名、状态词一个字都不碰。三条路走同一套：本人保存改名、管理员改某一行、每天推来的群名单改名。
分不清是哪一位时（两行同名、查不到 QQ 绑定）**宁可不动**，只在保存回执 / 日志里说明。

**编辑器里的完成情况下拉只给「人」**：本人已完成 + 本榜主播 + 本周期临时成员（紫玻璃，可现场 `＋收录`）。
`排队中` 与 `等待开启` 是自动流转的，不再作为选项出现；已完成的行可以点「改回排队中」。
候选**不再**收录表里在用的其它残留名字，否则点过完成的人名会越积越多。

### 定时任务只有一条

`notify.cron`（默认每 3 分钟一次）里依次做这些事（都发到 `notify.groups`）：

1. **分榜清榜提醒** —— 见下节周期表；提醒里 @ 的是**当前仍在排队的人**，并附带一次完成核查结果
2. **开榜提醒** —— 某榜从「未开启」翻到「已开启」时，把该榜所有排队中的人 @ 一遍，
   末尾可加一行 `本榜主播：@…`（`notify.open_anchor` 控制）
3. **完成播报** —— 一块三行，块间空行：

   ```
   【深境螺旋】第 3 位「甲」已完成
   下一位：乙
   主播：@丙
   ```

   下一位**只写群昵称文字、不 @、也不写「请准备」**；第三行取自**下一位那一行**的「选择主播」，
   是「都可以」或空着就不写。
4. **回退播报** —— 完成了又变回排队中：

   ```
   【深境螺旋】第 3 位「甲」的完成情况由「已完成」变为「排队中」，请主播 @丙 注意
   ```

5. **群成员名单同步** —— 每天到 `roster.at`（默认 05:00）推一次（机器人启动后 20 秒还有一次）
6. **每日整理** —— 同一时刻按统一规则整理四个榜（规则见下）
7. **绝境攻炼版更 @全体** —— 版更当天 10:00 之后一次，同一期只发一次
8. **开播提醒** —— 见上文

**首次运行（没有状态文件）只记基线，一件事都不做**——避免刚部署就把全榜 @ 一遍。
「到点之后」的语义是**一整天都算数**：机器人半夜关着、早上 9 点才起，当天的名单同步与每日整理仍会补做。
名单同步与每日整理**不发群**，所以关掉通知不会连带停掉它们。

所有去重标记都在**同一个状态文件** `data/progress.json` 里，一次算好、一次落盘、再发消息——
发送失败不重复发，重启、重复 tick 同样不会重复。

> 「月末催办」已废弃：改由分榜清榜提醒替代。

### 清榜周期（四榜各不相同）

| 榜 | 周期 | 提醒 | 清榜动作 |
| --- | --- | --- | --- |
| 幻想真境剧诗 | 每月一轮 | 上月最后一天 12:00 | 每月 1 日 04:00 清空全部成员行 |
| 深境螺旋 | 每月一轮 | 本月 15 日 12:00 | 16 日 04:00 清排队 / 已完成，并翻「等待开启」行 |
| 幽境危战 | 42 天一轮 | 清榜前一日 12:00 | 第 34 天 04:00 清排队 / 已完成；第 42 天 10:00 下一轮开启 |
| 绝境攻炼 | 长期开放 | 版更前一日 12:00 | 版更日 10:00 **只清已完成**，排队中与等待开启保留 |

清榜前**先把该榜单独导出为 xlsx 存进 `data/archives`**（带一份 `.meta.json` 记源版本 sha256），
归档成功才允许编辑器删行——**宁可晚清，不能丢数据**。
失败会**私聊主人**并且不写 done 标记，下一轮重试。
通知关掉（`notify.enable: false`）时提醒不发，但清榜照做。

### 每日整理（重排规则）

只排有群昵称的行，空行当固定格子不参与也不移动：

- **分组**：已完成 → 等待开启 → 排队中（空状态归最后一组）
- **组内**：难度 → 目标 → 完成类型（本人完成 → 主播完成 → 本月临时名 → 未知）→ 原始行号稳定兜底
- 绝境攻炼另算：排队状态 → 模式数量从少到多 → 目标从低到高

**只换内容、不插行不删行**，序号与行号一个都不变；本来就是这个顺序就一个字都不写（不存版本）。
改了「帮帮完成情况」或攻炼的目标时，编辑器会**当场**对那一榜整理一次，每天那趟退居兜底。

## 绝境攻炼

第四张榜，列与其它三榜一致，E 列「模式及目标」存一个组合值 `模式1、模式2｜目标`，
例如 `焰羽追绞、囚笼冰城｜满星章`。点开是左右两栏：模式多选、目标单选。

- 当前八个模式：7.0 `线列破袭 / 至寒风暴 / 狭域死战`、7.1 `焰羽追绞 / 囚笼冰城`、
  7.2 `交错锤砧 / 重兵固港 / 灾厄旧城`；7.3 暂用 `7.3模式` 占位
- 某个版本的模式**全部选中**时用版本简写（`7.0模式` / `7.2/7.3模式`），否则逐个列名字
- 目标三选一：**满原石（绿）/ 满星章（红）/ 顶分（深紫）**，不设难度
- 完成情况是复合值：多个模式各有一段（如 `7.0完成、7.1排队中`），编辑器按空白拆成多个胶囊渲染
- 版更：**2026-11-04 10:00** 第 1 期，之后每 **42 天**一期；版更当天 10:00 在 `notify.groups` 发

  ```
  @全体成员
  【绝境攻炼】新模式已开启，如需帮帮可前往排队。
  ```

  同一期只发一次，重启不重复；首跑/停机跨天不补发

## 配置

配置文件 `config/config.yaml`（首启时若不存在，会自动从 `config/config.yaml.example` 复制）。
**完整键位与注释以 [`config/config.yaml.example`](config/config.yaml.example) 为准**，这里只列常用项：

```yaml
editor:
  public_url: ""          # 群友能打开的编辑器地址（只用于拼链接）
  token: ""               # 访问口令（出现在每个人的链接里）
  sign_key: ""            # 身份签名密钥（留空或与口令相同 → 编辑器拒绝启动）
  admin_token: ""         # 管理口令（可选，?a=<这段> 即主人身份）

roster:
  group: ""               # 拉群成员名单的群号；留空 = 关闭（编辑器里就没有群昵称候选）
  at: "05:00"             # 名单同步与每日整理的时刻

notify:
  enable: true            # 总开关：false = @ 通知全关（名单同步与整理不受影响）
  groups: []              # 通知发到哪些群
  cron: "*/3 * * * *"     # 唯一那条定时任务的周期（改动要重启）
  open_anchor: true       # 开榜提醒末尾的「本榜主播：@…」

anchor_live:
  enable: true            # 查 B 站直播状态（公开接口，不需要账号）
  push: true              # 开播提醒（只 @ 订阅过的人）

default_sheet: "幽境危战"  # 总览图的默认榜（只进模板数据，当前模板未引用）
list_limit: 20            # 单榜图显示行数，0 = 全部
render_image: true        # 是否出图（渲染后端不可用时自动回退文本）
render_scale: 6           # 出图分辨率倍数
```

- **改完不用重启**：插件盯着 `config/config.yaml` 热重载。**唯一例外 `notify.cron`**。
  （`editor` 段的凭证是插件加载时交给编辑器的，那一组改完仍需重启机器人。）
- **也可以用锅巴改**：装着 Guoba-Plugin 时，后台「插件配置」里按「连接与通知 / 展示与别名 / 编辑器页脚 / 高级」
  四组列全部配置项，保存时按模板渲染回 `config/config.yaml`（注释保留）。
- **新增配置键只写进 `config/config.yaml.example`**；老部署不会自动获得新键，需要手工补。
- **数据落点固定 `<插件根>/data`，不可配置**：
  `queue.json`（事实源）/ `queue.xlsx`（镜像）/ `queue.lock`（跨进程写锁）、`versions/`、`archives/`、
  `bindings.json`（QQ → 行 绑定）、`progress.json`（通知去重基线）、`cycle.json`（清榜进度）、
  `anchor-live.json` / `live-alerts.json`（直播状态与订阅）、`anchor-names.json`（表里名 → 群里名）、
  `roster.json` / `manager-link.json` / `restart.flag`，以及编辑器那套
  `abyss-editor-*.json`（白名单、锁、群名单、绑定、认领、改动记录、额度、链接、清榜幂等账本）
  与 `abyss-editor-cycle-intents/`。

## 更新约定

| 指令 | 行为 |
| --- | --- |
| `#更新排队` | 本插件提供的**简写**，等同框架的 `#更新 abyss-queue`：拉最新代码并重启 |
| `#更新 abyss-queue` | 框架的更新（**要写全 `abyss-queue`**） |
| `#强制更新 abyss-queue` | 框架的强制更新：`git reset --hard` 对齐远端，**会丢弃被跟踪文件的本地改动** |
| `#全部更新` | 框架的整机更新（本体 + 全部插件，含 `pnpm install`） |

> ⚠️ `#更新 abyss`（缩写）**不生效**：框架那条规则会命中，但解析不出 `plugins/abyss`，直接放行——
> 命令被吃掉、没有任何回复，看起来像「机器人没理你」。

两条硬约定：

1. **配置与数据只以模板形式入库**：仓库跟踪 `config/config.yaml.example`，运行时 `config/config.yaml`
   由它在首启时复制生成；数据都在 `data/`。两者都已被 `.gitignore` 忽略，所以更新（含强制对齐）
   **不会碰你的配置与数据**。
2. **部署目录只由更新指令改动**：不要手工复制/编辑去同步代码——那会让部署目录产生未提交改动，
   一旦与远端提交重叠，快进会被 git 拒绝（「有本地改动，无法快进」）。
   正确做法：改动先在源仓库落地并推送，再发 `#更新排队` 拉取。

## 表格要求

- 四张工作表（榜）名称可自定义，插件按表内内容识别，不写死行号与表名
- 每个工作表要有一行表头，**A 列写着「序号」**；表头行之上是主播区
- 数据列按表头关键字识别：群昵称 / 原神游戏名 / 选择主播 / 难度 / 帮帮完成情况 / 备注
- 主播、难度、完成情况列的下拉验证会被当作合法选项读出来
- 序号列（A 列）的公式不会被改动；清行只删数据列的单元格，不删整行
- 表必须是 `.xlsx`（只认这一种）

## 已知限制

- **宿主命令冷却会吞消息**：TRSS-Yunzai 的 `config/config/group.yaml` 有 `singleCD`（默认 2000ms，同群同一人）
  与 `groupCD`（默认 500ms，同群）。冷却期内消息在规则匹配前就被丢弃，插件收不到。
- 表格里没有 QQ 号列，「你是谁」靠群昵称 + QQ 绑定：绑定过之后按 QQ 认人。
- 表格正被 Excel/WPS 打开时可能写入失败（`EPERM/EBUSY`），编辑器会提示「请关闭后重试」，不会写坏原文件。
- **机器人出图的主播排序仍按旧推荐度口径**（编辑器已改五档，见「推荐度」）。
- 清榜 / 翻状态 / 插队 / 退队都要求**编辑器已挂载**；起始表与 json 都缺时编辑器不挂载，这些动作会直接报错。

### 与其它插件的命令冲突

规则分发先命中先执行（`priority` 升序）。本插件的榜单命令**一律要求带 `排队` / `列表` 后缀或 `#排队` 前缀**，
与下列规则天然错开：

| 会被抢的命令 | 占用方 | 对方 priority |
| --- | --- | --- |
| `#幽境危战` / `#幻想真境剧诗` / `#深境螺旋` / `#深渊` / `#危战` / `#剧诗` | `Axiu-Plugin`「终局挑战」 | `1` |
| `#排队` | 框架示例 `plugins/example/排队.js`（各版本可能自带） | `500` |
