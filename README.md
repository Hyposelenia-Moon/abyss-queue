# abyss-queue（三路深渊排队）

在 QQ 群里查排队情况：从**云端编辑器**拉一份排表快照（不改表结构、不丢条件格式/下拉/公式/超链接），渲染成图发出去。

本文档里的「**云端**」指**部署在云服务器上的在线编辑器**（本仓库 `editor/` 那份代码），不是任何第三方在线文档。
填表与改表都在云端编辑器里做，它是**唯一的写入口**；**插件自己一个字都不写表**。
编辑器就在本仓库里（`editor/`），随插件一起部署。

## 安装与部署

在 Yunzai 根目录执行：

```bash
git clone --depth=1 https://github.com/Hyposelenia-Moon/abyss-queue.git ./plugins/abyss-queue/
pnpm install --filter=abyss-queue
```

配置只要连上云端编辑器就够（`remote.` 四项）：

- `remote.url`：云端编辑器地址
- `remote.token`：访问口令（插件与编辑器共用这一份）
- `remote.sign_key`：身份签名密钥（**不要与口令相同**）
- `remote.admin_token`：管理口令（可选，编辑器页面上 `?a=<这段>` 即主人身份，用来维护白名单）

填完重启 Yunzai，然后在群里发 `#排队初始化`（**仅主人**）：口令与签名密钥、编辑器白名单、探活
一次做完。**遇错即停**，已有产物只校验不覆盖，与当前配置不一致时宁可停下来让你决定。
数据目录不用管（固定 `<插件根>/data`），但**表要自己放一份**：把插件自带的
`resources/空模板.xlsx` 复制成 `data/queue.xlsx`。**没有这张表编辑器不会挂载**（fail-closed：记一行 error 日志，
机器人照常跑），日志里会直接告诉你该复制哪两个路径。

**编辑器随机器人一起跑**（挂在机器人自己的 HTTP server 上，前缀 `/queue`），所以没有单独的进程要维护：
配置里的口令 / 签名密钥 / 管理口令就是它用的那一份。**但凭证是在插件加载时交给编辑器的**——
改完要**重启一次机器人**，否则会出现「插件用新口令、编辑器还认旧口令」，填表链接直接报 403。

编辑器部署（nginx 指向）见 [`editor/DEPLOY.md`](editor/DEPLOY.md)。

> **填表内容对全群可见**：编辑器口令会出现在每个人的填表链接里，所以**拿到链接的人都能拉到整张表**
> （群昵称、游戏名、选择与备注都在内），只是改不动别人的行。别把隐私信息写进备注。

## 命令

| 命令 | 说明 |
| --- | --- |
| `#排队` | 我的排队信息 + 三榜人数总览（一张图），后面接填写情况与**填报短链**；主人 / 白名单管理员改为**私聊发**（见下） |
| `#排队 <榜> [全部]` | 查看某个榜的队列；榜名可写全名、简称（`危战` / `剧诗` / `深渊` / `幽境` / `幻想` / `螺旋`）或序号，加 `全部` 看全量 |
| `#主播` | 主播列表：三个榜合并成一张表（同一主播只出现一次），含「专职」列 |
| `#主播 <榜>` | 只列该榜的主播 |
| `#主播 <名字>` | 文本输出这位主播的详情：专职、各榜强项、直播入口 |
| `#插队` · `#插队 <群昵称>` · `#插队 <榜>` | **主人 / 白名单管理员专用**：把已排队的某个人往前挪一位（越过他前面最近的那一位「排队中」）。不带参数挪**自己**在排队的每一个榜；带群昵称就点名挪**别人**那一行（管理能力）；带榜名只处理那一个榜。前面没有「排队中」的人时什么也不做，回一句"已经在最前面" |
| `#排队初始化` | **主人专用**：口令与签名密钥 / 编辑器白名单 / 编辑器探活，三步一次做完 |
| `#排队同步名单` | **主人专用**：立刻扫一次群成员名单并推给编辑器（`roster.group` 那个群），回执照实说"同步了几人 / 改名几行 / 退群删了几行"或"为什么没做"。名单平时只有两条自动路径：机器人启动后 20 秒、以及每天到 `roster.at` |
| `#排队更新` · `#排队强制更新` | **主人专用**：拉最新代码并重启（强制更新先 `reset --hard`） |

命令只有 **5 条**（`#排队` / `#主播` / 管理员专用的 `#插队` / 主人专用的 `#排队初始化` 与 `#排队同步名单`），聊天端只负责**查询**（`#插队` 也只是把"哪一榜、哪一行、怎么挪"交给编辑器，插件自己不写表）。

### `#排队` 发出来的东西

**只发一条消息**：一张图 + 图后面接的两段文字。

- 图里是「三榜人数总览」与「发送者本人的排队信息」（按群昵称/QQ 定位，表里没有就不显示这一块），常用指令印在图底部
- 第一段写填写情况，按 `未填：<榜名…>；已完成：<榜名…>` 组织：还没排的榜进「未填」，已经打完的（表里是主播名）和自己点过完成的（表里落成了群昵称）都进「已完成」，还在排队的两边都不提；三个榜都填过就只给入口——已填的内容也能回去改
- 第二段是填报入口的**短链**：`点此填表：<remote.url>/s/<16 字符码>?t=<签发分钟>&ts=<签名>&n=<群昵称>&v=<链接标记>`（整条约 90~110 字符）。码里只有加密后的 QQ + MAC（看不出 QQ、也不用编辑器存映射），有效期按 30 天窗口算、认当期与上一期 → **约 30~60 天**。点开短链 → 编辑器验码 → 302 到带身份签名的完整地址。后面那四段是机器人签的：`?t&ts=` 是**签发时刻**（签名只留 96 位 / 16 个字符——整段 HMAC 要 43 个字符，群里那条链接会因此折得更长）——一条链接归第一台打开它的设备（防转发），而**更新且够新**的链接可以接管，所以万一你的链接先被别人点开、你只能只读，**重新发一次 `#排队`、点最新那条**就能拿回填写权限；`?n=` 是**你当时的群昵称**，给编辑器兜底用（它的群名单是每天推一次的旁路数据，名单里还没你的时候，靠这个才认得出"你自己那一行"）；`?v=` 是**这条链接的标记**（每次发都换一个，记在 `data/abyss-editor-links.json`）——编辑器只认**最新**那一条可写，其余的只读 ⇒ **本人重发一次 `#排队` 就等于把转发出去的那条作废**（老链接没有 `v` 时一律只读）。四段共用同一段签名，改一个字整段作废；旧链接（没有这些段、或签名还是整段 43 个字符的）照旧**打得开、但只读**（要写就重发一次 `#排队`）

短链要「地址 + 口令 + 签名密钥」齐备才签得出，缺任一项就写「暂无链接」；编辑器没有 `/s/` 路由时把 `remote.short_link` 设成 `false`，用完整长链接（**长链接一律带 5 分钟时间窗**，所以退出短链之后链接只有当期与上一期可用，过期就重新发一次 `#排队`）。
`remote.link_markdown: true` 时改成「点此填表」四个字本身带链接的 markdown 段。

**`#排队` 之前会顺手补一次群成员名单**（`apps/queue.js` 的 `ensureRosterKnows`）：编辑器的写权限按"**名单可信 + 你在名单里**"判（本群守卫，见 `editor/README.md` 的「权限」），而名单每天才推一次——**刚进群的人当天不在名单里，拿到的链接会被判成"群外人"只读**。所以发送者不在已有名单里时，机器人**当场重扫一次群成员并推给编辑器，再发链接**（顺序不能反）。只在"不在名单里"（新人 / 名单过期 / 从没推过）时才做，扫全群是重活；失败只记日志，绝不挡住这次 `#排队`。

**主人与白名单管理员那一份走私聊**（这一步是防"链接被转发出去"）：发送者是主人（框架 master，或 `#排队初始化` 写的 `data/abyss-editor-admins.json` 里的 `owner`）或白名单管理员时，整条回复**私聊发给他本人**，群里一个字都不发。私聊那份用的是**带 5 分钟时间窗的长地址**——短码是"点开的那一刻现签窗口"，等于永不过期，不能用在管理链接上。这条私聊链接**只在本人发 `#排队` 时给一次**，**5 分钟窗口过期即失效**（靠编辑器的时间窗，不需要额外机制），要新的就再发一次 `#排队`——机器人**不会主动重发**。私聊发不出去（没加机器人好友）时只在群里回一句原因，**不会把管理链接退回群里**。普通群友的行为一个字都没变。

### 「我的排队信息」怎么定位（按 QQ）

发送者的 QQ 是**权威身份**，群昵称只是用来第一次认人：

1. **有绑定** → 直接按绑定认这一行：即使他改了群名片，也认这个人
2. **没有绑定** → 按群昵称在表里找；找到就记下 QQ→行 的绑定，以后都按 QQ 认
3. 绑定指向的行已被清掉（退队）或已经属于别的 QQ → 绑定作废，回到第 2 步
4. 仍然找不到 → **只发菜单**，不会多发一条「没有你的记录」

**名片与表里昵称不一致时，插件只记日志、不会去改表**（改表由云端编辑器做：本人打开编辑器时按群名片同步，机器人每天的群成员名单核对也会兜一遍）；图里显示的始终是表里的昵称。匹配**只看群昵称**，游戏名不参与判断。

### 主播别名（表里/群里的其它写法）

同一位主播在表里、群里常有多种写法。配置里登记「正名 → 别名」，读的时候统一归到正名：

```yaml
anchor_aliases:
  阿修Axiu: ["阿修"]          # #主播 阿修 也能查到
  摸头妹: ["璃月第一深情"]     # 表里写「璃月第一深情」的行算作摸头妹，直播入口照样带出来
```

- 别名按**正则整串匹配**（忽略大小写），所以 `纸笑.*` 这种写法也可以；写错的正则会跳过、不影响出图
- 影响范围：`#主播 <名字>` 的查找、`#排队` 里本人那一行的直播入口；编辑器侧的下拉同样会归一
- 表里的原文不会因为别名被改写

### 数据链路：纯云端（插件只读）

```
云端编辑器（云服务器，唯一写入口） ── 服务器上那份 xlsx
      │  GET <remote.url>/api/snapshot?k=<remote.token>
      ▼
插件（机器人）── 解析成 models → 渲染 → 推送
      └── 每次成功拉取都往本地写一份备份（data/backup，只留最新一份）
```

- 插件**按 TTL 拉快照**（默认 30 秒内复用内存里那份），**对比差异、有差异才换**
- **网络抖动不当失败**：拉取出错时继续用上一次成功的快照（记一条 warn）；从来没成功过才报错，命令里会直接说「云端表不可达（地址）」
- **本地备份**（`snapshot_backup`）：每次成功拉取都写 `data/backup/queue-日期.xlsx`，只留最新一份；备份失败只记日志，绝不影响读表
- 裸链接与请求格式：`GET <remote.url>/api/snapshot?k=<token>` 返回 xlsx 原始字节；口令错是 403，编辑器没挂上或路径不对会拿到 404 / 站点首页（这时日志会提示"拿到的可能不是 xlsx"）

### 菜单里的榜单状态

`#排队` 的「**排队中人数**」列 = 这一榜**还没打完的人**（完成情况写着「排队中」、或者空着；已完成的——主播名 / 本人昵称——和「等待开启」都不算）。**单榜图（`#排队 <榜>`）那一行「共 N 人排队中」是同一个口径**，两张图不会给出不一样的数；单榜图下面列的行仍是**这一榜的全部行**（含已完成的，各自带状态徽章），所以那个数字可以小于表格行数。**规则也一样**：某个榜**一个都没在排队**时，总览那一格与单榜图那一行都改显示整榜状态（典型是深境螺旋还没开、每行都写着「等待开启」）——那种时候「0 人」什么也说明不了，"还没开榜"才是要传达的信息。这样不必打开表格就知道某个榜是"还没开始"而不是"有人排队"。

### 完成情况与四个自动通知

「帮帮完成情况」这一列的值分三类，通知逻辑都建立在这个约定上：

| 值 | 含义 |
| --- | --- |
| `等待开启` | 这个榜还没开，既不算排队也不算完成 |
| `排队中` | 还在等（还没轮到他） |
| 其它任何值 | 这一位已经处理过了 |

「其它值」存的是**人**：主播名，或点「本人已完成」时落成的**该行群昵称**（一格可以写多个，用逗号分隔）。
所以哪位群友改了群昵称，编辑器会把他名下那些行里**整段等于旧昵称**的值换成新昵称——逐段比对，
别人的名字（哪怕就是旧昵称加了个后缀）、主播名、`等待开启` / `排队中` 这类状态词一个字都不碰。
三条路都走同一套：**成员自己保存改名、管理员改某一行、每天推来的群成员名单改名**。
分不清是哪一位的时候（例如人工改表改出两行同名，或这一行查不到可依据的 QQ 绑定）**宁可不动**，
只在保存回执 / 日志里说明，绝不猜。

这一列的下拉候选**只认三种来源**：状态词（`等待开启` / `排队中` / `本人已完成`）、主播区的名字、
以及页面底部「＋ 收录新名字」手动收录的临时成员。表里在用的其它名字（点「本人已完成」落下的群昵称、
改名 / 退群 / 广告名片留下的残留）**不再进候选**——不然每个点过完成的人的名字都会变成全体候选、越积越多；
这一格的当前值页面照旧会列出来，所以看得到、也取消得掉。

**定时任务只有一条**（`notify.cron`，默认每 3 分钟），下面四件事都由它按时间依次做，发到 `notify.groups`：

1. **上一位完成 → @ 下一位**：某一行从「未完成」变成「已完成」时，发一条
   `【榜名】第 N 位「某某」已完成 → 下一位 某某（第 M 位）请准备`，**末尾再 @ 下一位**：
   先按这一行的绑定（QQ → 行）反查他的 QQ，其次按昵称查群成员名单；两边都拿不到就只发名字、**不 @**
2. **榜开启提醒**：某个榜从「未开启」翻到「已开启」时，把该榜**所有排队中的人** @ 一遍；首次部署只记基线、不在群里 @ 人
3. **月末催办**：每月最后一天、到 `notify.monthly_at`（默认 12:00）之后，把三个榜里**还在排队的人** @ 一遍，当天只发一次
4. **群成员名单同步**：每天到 `roster.at`（默认 05:00）之后推一次群成员名单给云端编辑器（当天只发一次；机器人启动后 20 秒还有一次）
5. **每日整理表格**：同一个时刻（也是 `roster.at`）顺手把每个榜的排队顺序整理一遍——**同一段里已完成的人前移、还在排队的人后移**；
   「等待开启」那一行是**挡位**，原地不动、也把顺序分成段，段与段之间不跨着挪；同类之间保持原有先后（谁先排的不会被搅乱）。
   只换内容、不插行不删行，序号与行号一个都不变；**本来就是这个顺序就一个字都不写**（不重新保存、不产生历史版本），所以天天跑也不会留垃圾版本

五件事的去重状态全在**同一个状态文件** `data/progress.json`（落点固定，不可配置）里，**一次算好、一次落盘、再发消息**——发送失败也不重复发，重启、重复 tick 同样不会重复。
「到点之后」的语义是**一整天都算数**：机器人半夜关着、早上 9 点才起来时，当天的名单同步、每日整理与月末催办仍会补做一次。
第 4、5 两件**不发给群**，所以关掉通知（`notify.enable = false`）不会连带停掉它们。

#### 群号（写在配置里，可自己改）

**这些 @ 通知和「群昵称候选」都靠群号，不配就不会跑**（插件加载时会写日志提示），改完重启机器人生效：

@ 人靠"群昵称 → QQ"的映射，取两路：**实时**向框架要这个群的成员名单，**外加最近一次扫成功的那份缓存**
（启动后 20 秒那次 + 每天 `roster.at` 那次都会刷新它）。所以机器人刚重启、或某一下取成员失败时，
通知**不会**退化成"只有名字没有 @"；真的一处都对不上（改了群名片、名单还没同步到表里）时只在日志里说一句，
绝不瞎 @、更不 @ 全体。

| 配置键 | 作用 | 怎么写 |
| --- | --- | --- |
| `notify.groups` | 上面 1~3 条通知发到哪些群 | 群号列表，可多个：`groups: [123456789, 987654321]`；留空 = 这些通知都不发 |
| `notify.enable` | 三条 @ 通知的总开关 | `false` = 全部关掉（`groups` 一并失效，也不提示"没配群号"）；**不影响**群名单同步 |
| `roster.group` | 从哪个群拉成员名单 → 编辑器的「群昵称候选」+ 按 QQ 对账（改名同步、退群删行）；**也决定每日整理跑不跑** | 只能填一个群号：`group: "123456789"`；留空 = 关闭群名单（编辑器里就没有候选，每日整理也不做） |
| `roster.at` | 名单同步**与每日整理**的时刻（本地时间 "HH:MM"，默认 05:00） | 到点之后一整天都算数；两者共用这一个时刻，不单独配 |

两者**可以是不同的群**（例如名单从主群拉、通知发到通知群）。

```yaml
notify:
  enable: true               # false = 三条 @ 通知全关
  groups: [123456789]        # ← 发 @ 通知的群（可多个）
  cron: "*/3 * * * *"        # ← 唯一那条定时任务的周期
  monthly_at: "12:00"        # ← 月末催办的时刻
roster:
  group: "123456789"         # ← 拉群成员名单的群（只能一个）
  at: "05:00"                # ← 每天推名单的时刻
```

### 主播的「专职」列

`#主播` 的合并表里，「专职」表示这位主播打哪个榜。它有两级来源：

1. **表里手填**：各榜主播区的 **D 列**（"核心强项" C 列与"直播入口" G/H 列之间那个空格）写上他专职的榜。想区分同一位主播在不同榜的定位时填这里。
2. **自动推断**：D 列留空时，按这位主播出现在哪些榜的主播区来显示——他出现在哪个榜就说明他接哪个榜。

两种都留空的情况下不显示 `—`，不会影响表格。

### 主播的「直播入口」列

主播区的入口占 **G、H 两列**，拆分规则是「**一个格子 = 一个入口位**」：

| G 列 | H 列 | 渲染结果 |
| --- | --- | --- |
| `B站` | *(空)* | `B站` |
| `B站` | `抖音（付费）` | `B站` / `抖音（付费）`（两行） |
| `B站/抖音（付费）` | *(空)* | `B站/抖音（付费）`（**一行**：`/` 是普通字符，不拆项） |
| `群语音通话（屏幕共享）` | `腾讯会议370-976-3227` | 两行 |
| `B站、抖音` | *(空)* | `B站` / `抖音`（两行） |
| `B站` | `https://live.bilibili.com/1960956034` | `B站https://live.bilibili.com/1960956034`（一行） |

- **斜杠 `/` 不是分隔符**（它是普通字符，链接里的斜杠也照旧不拆）：想写在同一行就用 `B站/抖音`
- 想拆成多行：把平台写在**两个格子**里（G、H），或同一格内用 `、` `,` `，` 并列
- 整格是一个链接时，贴到前面最近一个**还没有链接**的入口上（就是上面的「平台+链接」写法）；没有可贴的入口才单独成行
- 入口按**一项一行**渲染，所以 G/H 都填了内容时**不会挤在同一行**
- `#主播` 与 `#主播 <名字>` 里入口**不按深渊分组**，是跨榜去重后的平台列表（同一位主播在三个榜填了同一个入口也只显示一行）

### 编辑器（就在本仓库 `editor/`，部署在云服务器上）

填表与改表都在**云端编辑器**里做，它是**唯一的写入口**：

- 白名单管理员能改所有人的行；带身份签名的人只能改自己那一行；没签名只能只读浏览
- 群昵称有**候选**（机器人每天推一次群成员名单），选中即照抄群名片，手写也行；
  输入时还会在框下面按**相近度**给几个最像的名字（前缀 / 含这段 / 差一两个字都能命中，点一下填入）——
  只记得半个名字时不用去翻群成员列表
- 名人改了群名片 → 打开编辑器时按新名片同步表里的群昵称；退群/被移出 → 每天核对时删掉那一行并**压紧**（不留空洞）
- **历史版本 + 回退**：每次写表前自动存一份（留最近 20 份；**页面上的连续小改 5 分钟最多留一份**——自动保存是 1.5 秒防抖的，不节流的话一次编辑会话就把 20 份占满），**主人与白名单管理员**可在页面上列出、下载、回退（回退前也会先存一份，回退错了还能再退回来）；「上传覆盖云端」与「归属状态」仍是主人专属
- 服务器上的那份表就是数据本体；**本机那份只是备份/工作副本**（`#排队` 的链接永远指向云端）
- 编辑器细节（字段、权限模型、签名密钥、部署与 nginx 挂载）见 [`editor/README.md`](editor/README.md) 与 [`editor/DEPLOY.md`](editor/DEPLOY.md)

## 配置

配置文件 `config/config.yaml`（首次加载时若不存在，会自动从 `config/config.yaml.example` 复制一份）。
**完整键位与注释以 [`config/config.yaml.example`](config/config.yaml.example) 为准**，这里只列必填与常用项：

> **也可以用锅巴改**：装着 [Guoba-Plugin](https://github.com/guoba-yunai/guoba-plugin) 时，
> 后台「插件配置」里就有本插件，按「连接与通知 / 展示与别名 / 编辑器页脚 / 高级」四组列全部配置项，
> 带说明与取值范围；保存时按模板渲染回 `config/config.yaml`（注释完整保留）。
> 改完**重启机器人**生效；**编辑器页脚**那项也随机器人一起生效（编辑器就在机器人进程里）。
>
> 注意：编辑器不再有自己的启动参数——它挂在机器人自己的 HTTP server 上（前缀 `/queue`），
> 表固定 `data/queue.xlsx`，口令 / 签名密钥 / 管理口令都取自下面这份配置。

```yaml
# 数据来源：云端编辑器（必填；本机联调可写 http://127.0.0.1:7788）
remote:
  url: "https://example.com/queue"   # 云端编辑器地址
  token: ""                              # 访问口令（插件与编辑器共用这一份）
  sign_key: ""                           # 身份签名密钥（不配就退回用 token 签：拿到链接的人能伪造身份）
  admin_token: ""                        # 管理口令（可选；页面上 ?a=<这段> 即主人身份）
  short_link: true                       # 群里发短链；编辑器还没更新（无 /s/ 路由）时改 false
  link_markdown: false                   # true = 入口做成「点此填表」可点文字（多数群不认 markdown）

roster:
  group: ""                              # 拉群成员名单的群号（**要在群里填**），留空 = 关闭

notify:
  enable: true                           # false = 三条 @ 通知全关（名单同步不受影响）
  groups: []                             # 通知群号（可多个）
default_sheet: 幽境危战                   # `#排队 全部` 不带榜名时使用
list_limit: 20                           # 名单显示行数，0 = 全部
render_image: true                       # 是否出图（渲染后端不可用时自动回退文本）
render_scale: 2                          # 出图分辨率倍数
snapshot_backup:
  enable: true                           # 云端快照的本地备份（落在 data/backup），false = 关掉
```

其余键（`ttl_ms` / `timeout_ms` / `autostart` / `snapshot_backup` / `notify.cron` 等）见 `config/config.yaml.example`。

- **新增配置键**：只写进 `config/config.yaml.example`，运行时 `config.yaml` 由它复制生成；老部署不会自动获得新键，需要手工补
- **数据落点固定在 `<插件根>/data`，不可配置**（表格副本、绑定、进度、日志都在它里面），因此更新只动代码、不动数据；写盘口径见 [`docs/开发说明.md`](docs/开发说明.md)

## 更新与「部署目录不被改动」的约定

### 用插件自己的指令（推荐）

| 指令 | 行为 |
| --- | --- |
| `#排队更新` | 在插件目录里 `git pull`，拉到新代码就**自动重启**机器人（编辑器随机器人一起重启） |
| `#排队强制更新` | 先 `git reset --hard origin/main` 对齐远端再 pull。**会丢弃被跟踪文件的本地改动**，只在快进被拒时用 |

两条都是**主人专用**。它们是插件自己注册的，落在自己的指令空间（`#排队**更新**`），不与框架的 `#更新` 竞争——框架那条排在最前（`priority: -Infinity`），任何以 `#更新` 开头的消息都会被它先吃掉。

### 用框架的指令

**框架的 `#更新` 只能按目录名**（`getPlugin()` 只按 `plugins/<名字>/.git` 找，没有别名表）：

| 指令 | 行为 |
| --- | --- |
| `#更新 abyss-queue` | 框架拉取本插件最新代码（**注意写全 `abyss-queue`**） |
| `#强制更新 abyss-queue` | 框架的强制更新：`git reset --hard <上游>` 对齐远端 |
| `#全部更新` | 框架的整机更新（本体 + 全部插件，含 `pnpm install`） |

> ⚠️ `#更新 abyss`（缩写）**不生效**：框架那条规则会命中，但 `getPlugin()` 解析不出 `plugins/abyss`，直接 `return false` —— 命令被吃掉、没有任何回复，看起来像"机器人没理你"。

1. **配置与数据只以模板形式入库**：仓库跟踪 `config/config.yaml.example`，运行时 `config/config.yaml` 由它在首启时复制生成；绑定数据在 `data/`。两者都在 `.gitignore` 内，因此**更新（含强制对齐）不会碰用户的配置与数据**。
2. **部署目录只由更新指令改动**：不要用手工复制/编辑去同步代码——那会让部署目录产生未提交改动，一旦与远端提交重叠，快进就会被 git 拒绝（表现为「有本地改动，无法快进」）。正确的做法是：改动先在本仓库落地并推送，再发 `#排队更新` 拉取。**开发期也不要"先拷过去试"**：验证新功能在源仓库跑离线套件（`pnpm test`），需要真机验证就先推送再更新。

## 表格要求

- 三个工作表（榜）名称可自定义，插件按表内内容识别，不写死行号/表名。
- 每个工作表需有一行表头，**A 列写着「序号」**；表头行之上是主播区（A 列主播名、C 列强项、G/H 列直播入口）。
- 数据列按表头关键字识别：群昵称 / 原神游戏名 / 选择主播 / 难度 / 账号强度 / 帮帮完成情况 / 备注。
- 主播、难度、强度列的下拉验证（数据验证）会被当作合法选项读出来。
- 序号列（A 列）的公式不会被改动；清行只删 B–H 的单元格，不删整行。

## 已知限制

- **宿主的命令冷却会吞消息**：TRSS-Yunzai 的 `config/config/group.yaml` 里有 `singleCD`（默认 2000ms，同群同一人）与 `groupCD`（默认 500ms，同群）。用户连续快发独立指令时，冷却期内的消息在规则匹配前就被丢弃，插件收不到。实测发消息间隔 >2s 时 16/16 全部得到回复。
- 表格里没有 QQ 号列，「你是谁」靠群昵称 + QQ 绑定判定：绑定过之后按 QQ 认人；昵称被改动时由云端编辑器按群名片/群名单同步。
- 表格正被 Excel/WPS 打开时可能写入失败（`EPERM/EBUSY`），编辑器会明确提示「请关闭后重试」，不会写坏原文件。
- 表必须是 `.xlsx`（编辑器只认这一种）。

### 与其它插件的命令冲突

框架的规则分发**先命中先执行**，顺序是 `priority` 升序（相同则按插件加载顺序）。与本插件相关的撞车点只有「裸榜名」，因此本插件的榜单命令**一律要求带 `排队` / `列表` 后缀**，与下列规则天然错开：

| 会被抢的命令 | 占用方 | 对方 priority |
| --- | --- | --- |
| `#幽境危战` / `#幻想真境剧诗` / `#深境螺旋` / `#深渊` / `#危战` / `#剧诗` | `Axiu-Plugin`「终局挑战」（`plugins/Axiu-Plugin`） | `1` |
| `#排队` | 框架示例 `plugins/example/排队.js`（「三路深渊排队」示例，各版本可能自带） | `500` |

因此 `#排队` / `#排队 危战` 这些写法在任何组合下都不会被抢（后缀式 `#危战排队` / `#螺旋列表` 同样命中本插件的规则）。`#排队`（本插件的菜单入口）在本机由本插件响应——`plugins/example/排队.js` 不在；若某次框架升级把它带回来，`#排队` 会先被示例插件（`priority: 500`）吃掉，届时把入口命令换掉即可。
